# ubuntu-cc-03 终端故障与后续发行

## 已确认现场

用户回传：Build 16 镜像中的 `node-pty/lib/terminal.js` 与 Build 14 同版本依赖仅一个字节不同，`setEncoding` 出现异常字符，导致语法错误。隔离容器复现，Build 16 发布文件清单与 CLI 摘要正常；Build 14 的 node-pty 可加载。崩溃三次后 supervisor 的持久计数达到上限，后续启动拒绝执行。

用户在 03 定点恢复该文件、核对内容一致并备份 journal 后重置 attempts，健康检查恢复。本机数据未回退。开发机独立核对 VPS 回环 28789 与公网 8445 的健康检查通过。备份位置 `/var/tmp/cc03-pty-recovery.tIBEMQ`。容器内恢复不修复底层镜像，删除重建旧镜像会重新带入异常文件。

异常字节发生在构建、存储还是内存环节尚不确定，不能宣称已定位硬件原因。此前独立窗口消失与缩放卡顿未复现；真实 Electron 缩放/最大化/还原测试通过，不等同于排除偶发问题。02 曾出现额度接口五秒超时，随后新额度正常上报；03 新会话触发新采集，历史快照过期，无证据证明额度故障与依赖损坏同源。

## 新发行实现

- Linux Build 18，协议 24，runtime v3：构建时实际创建 PTY，生成终端依赖摘要清单；安装前离线校验并再次创建 PTY；每次服务启动校验 JS、原生 addon、可选 spawn-helper 的摘要。检测到异常时拒绝启动并指出文件，不等到打开终端后才崩溃。Build 17 曾因旧发布工具生成的 v2 元数据与迁移 v3 要求不一致而安全拒绝安装，已用 18 替代，原包不覆盖。
- 从已发布 Build 16 精确描述符准入，重新执行 npm ci 生成新镜像，保留原有默认空间准备、空闲校验、受控断开、冷备份、回退和历史备份轮转。用户节点安装需另行执行，发布本身不创建安装任务。
- 三次崩溃锁定保留，日志明确计数和 journal 路径；不自动无限重试，不自动清计数。仅对固定安全错误输出诊断，不打印可能携带凭据的任意异常。
- Windows Build 31，协议 24：记录终端窗口的应用销毁、原生关闭、主窗口关闭、无响应/恢复、终端及主页面渲染进程退出原因。保留原更新控制器与入口。

实际验证与发布身份见 [Build 18](RELEASE-SERVER-BUILD18.md) 和 [Build 31](CLIENT-BUILD31-PUBLICATION.md)。发布未替用户执行 Ubuntu 安装，该页不将源码或模拟测试当作已经安装到 Ubuntu 的修复。
