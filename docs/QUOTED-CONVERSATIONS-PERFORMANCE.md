# 引用与侧栏性能检查

后续阅读状态、大回答解析与历史前插改动的复核和对照数据见 [Harness 借鉴改动与验证记录](HARNESS-ADOPTION-REVIEW-2026-10-31.md)。以下保留引用功能合入时的测量范围与结论。

2026-10-31，对 `codex/quoted-conversations` 的引用、独立侧聊和本机预览进行代码检查、计数测量及假服务回归。所有测量均未调用真实模型。

## 已确认并修复

| 路径 | 原先的开销 | 修复后 |
| --- | --- | --- |
| 输入时的选区监听 | 主侧同时显示，输入 35 字符触发 70 次 selectionchange 监听安装和移除；原因是 effect 依赖每次渲染新建的动作对象 | effect 仅随启用状态和容器变化，原测试中重装、移除均为 0；点击仍使用当前动作回调 |
| 关闭侧聊后的缓存 | 不切换主会话，打开并关闭 40 个侧聊后保留 42 项历史缓存，另有工具进度残留 | 最后一个观察者退出时执行缓存淘汰，恢复为 4 项；保护当前主会话和所有活动观察者，清理历史、流式片段、工具进度，并拒绝迟到回复重新填充已淘汰项 |
| 网页预览布局检查 | 每个原生预览观察整个页面；20 次无关聊天文字/样式更新触发 20 次几何读取及浮层扫描，随后才去重 IPC | 忽略对话正文、输入正文中的无关变化，20 次更新的预览几何读取为 0；实际新增/移除菜单、角色变更、尺寸和滚动仍触发检查 |
| 服务端创建侧聊快照 | 同步把包括大量状态读数的所有历史行送入 JavaScript 解码，虽不纳入快照仍消耗时间 | SQLite 先筛选需要的记录；单一类型列表控制查询与实时片段接入，无额外索引或数据库迁移 |

服务端相同夹具、每组各 7 次的中位数（本机 Node 24 / SQLite）：

| 历史规模 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 1,000 条混合记录 | 4.033ms | 2.054ms |
| 10,000 条状态记录，每条约 3KB | 49.952ms | 34.279ms |
| 50,000 条状态记录，每条约 1KB | 125.974ms | 73.954ms |

快照内容、顺序与字符数保持一致。原始基准脚本与数据保存在本工作区忽略目录 `.local/side-context-perf*`；上述数字只代表该夹具及本机环境，不等于部署服务器或实际文档的耗时。

## 已有资源约束与保留成本

- 界面最多 4 个预览窗格，只挂载每个窗格的活动标签，未激活标签不会同时渲染所有文件或侧聊。连接订阅上限 32，客户端为主会话保留一个名额；活动观察者不会为满足最近 4 项缓存目标而被淘汰。
- 文件读取与目录监听 effect 依赖具体路径/修订，不会因主会话输出而重新读文件。文件监听最多 128 个，文件变化通知合并为 75ms；关闭组件释放监听。
- PDF 按当前页渲染，限制像素尺寸并在更新时取消旧任务、卸载时销毁文档。Office 采用本机引擎转换，输入/输出各限制 20MiB，最多排队 4 项并串行处理，提供取消与超时；打开大文档或多个原生网页仍有正常的 CPU/内存成本。
- 快照只在明确创建侧聊时扫描，状态扫描优化后仍是线性操作；极长会话可能短暂占用远端事件循环。普通流式输出不执行创建扫描。
- 首次明确发送侧聊时最多附带 256,000 字符的冻结背景，可能增加远端输入 token 和首答等待时间。这是继承上下文的成本；创建标签本身不请求模型，不自动重发背景，也不回传本机预览内容。

本轮指标定位了可避免的重复工作和缓存增长，未进行持续数小时、全部格式大文档或真实服务器/模型的帧率与内存基准，不能据此保证所有机器始终无卡顿。

## 验证

- 44 项界面回归通过，覆盖真实鼠标拖选、输入监听稳定性、无关流式 DOM 更新、嵌入对话的菜单遮挡及恢复、窄屏/浮窗、引用发送与草稿恢复。

- 最新构建的 2 项真实 Electron 测试通过，覆盖引用并行流、重启恢复、原生网页/本机文件/Office/PDF 预览、菜单遮挡、未授权页面隔离和资源释放。
- 类型检查与生产构建（含模型依赖边界检查）通过。无真实模型请求，UI 视觉样式和用户明确发送流程保持原样。

## 性能优化复审

独立复审再次核对了缓存引用计数、迟到消息、快照筛选与预览遮挡。补齐一个删除路径遗漏：删除会话时现在同时释放工具进度和活动时间记录，防止会话已从缓存列表移除后仍残留任务摘要。新测试先复现进度残留，再验证删除与缓冲片段清理；另验证淘汰后重新打开会话以零游标完整加载，并保护主会话和其他活动观察者。

预览测试增加了已存在元素变为/退出菜单角色，以及包含菜单的包装节点整体卸载。两类路径均正确隐藏、恢复原生预览；无关正文更新仍不触发几何读取。选区监听 effect 不捕获动作回调，稳定依赖不会使用旧会话的引用动作；原有会话 key 隔离保持有效。

复审后重新运行：80 项相关测试、44 项界面回归、最新构建的真实 Electron 引用/并行流/重启恢复/预览隔离测试均通过；类型、生产构建、模型依赖边界、索引仓库与空白检查通过。独立复审未发现剩余的确定性回归。本轮未提交或推送。

再次复审补强了两项边界：仅通过类名标识的浮层原地退出后也必须恢复原生预览；侧栏收起后选区监听必须释放。前者在模拟 DOM 场景下先复现失败，再通过记录上一轮浮层的弱引用集合修复；当前实际菜单仍保留语义角色，原交互不依赖该边界。弱引用不会阻止已卸载节点回收，无关正文更新的几何读取仍为 0。后者测试确认卸载恰好释放侧会话的监听，随后在主会话输入不发生监听重装。没有新增界面样式、模型请求或预览访问接口。

上述补强后，再次完整运行并通过 80 项相关测试、44 项界面回归和 2 项真实 Electron 测试（完整预览约 146 秒，引用/重启恢复约 30 秒）；类型、构建、模型依赖边界、索引仓库与空白检查通过。两名独立审查者未发现剩余的确定性回归。结论仍限于所覆盖路径，不代表真实模型或长时间全负载性能保证；本轮未提交、推送或合并。
