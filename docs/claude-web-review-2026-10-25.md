## 发现及修复

| 级别 | 已复现的问题 | 修复与回归证据 |
| --- | --- | --- |
| P2 | 单地址占满 4 个未认证名额；静默认证不计失败，拒绝后还可拖延关闭 | 全局名额为 8，每地址仍为 4；5 秒认证到期计失败；拒绝后的 WebSocket 关闭期限为 1 秒。测试覆盖其他地址准入、静默限流、忽略关闭帧的 peer |

| P2 | 窄窗口侧栏进入 Chat 后残留遮罩，挡住工具栏 | 进入 Chat 时收起窄窗口侧栏；500×800 回归验证可切回 Coding |

| P2 | VNC 认证请求提示管理员，随后被通用断线提示覆盖 | 进入持久暂停状态，取消该次连接，保留管理员原因；不要求用户输入 VNC 密码 |

## 尚未解除的上线阻塞

1. 受管 Docker 节点由 `enforceManagedDeployment` 强制配置 JEV。网页原始输入尚无同等审核路径，因此服务返回 `moderation-required`，拒绝建立显示通道。不能删审核配置来打通，也不能据此把真实已登录浏览器接入生产客户端。
2. 现有浏览器 trial 与 CC 服务缺共享私有网络。宿主 `127.0.0.1:6090` 不等于 CC 容器的回环地址；需检查私有监听、Docker 网络和服务别名。不向公网开放 VNC、noVNC 或 CDP。
3. 中文输入、本地附件传输、自动登录失效识别、官网账号菜单隐藏及只允许指定网页仍未交付。现有登录维护流程为用户手动暂停，管理员处理后手动重连。
4. 本轮不能验证真实 Ubuntu 的 IPv4/IPv6 出口、浏览器重启后的 profile、实际账号状态、资源压力或原生物理 Alt-Tab/托盘动作的全部路径。

下一步可进行 Ubuntu 只读网络和资源预检，并用独立合成画面服务验证受管门禁及网络。真实网页联调须先解决强制审核覆盖。离线代码通过不等于全功能交付，也不构成账号不会受限的保证。
