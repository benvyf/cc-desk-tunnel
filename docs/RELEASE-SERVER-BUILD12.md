# Linux 服务端 Build 12

本次服务端版本为 0.3.7 / Linux Build 12 / 协议 24，基于主分支 `64c4476`，包含 SSH 设备元数据和在线改名、Tunnel 正常关闭与资源回收修复，以及配套 Web 的浅色主题。客户端 SSH 自动恢复、连接池、粘贴和命令取消逻辑仍在桌面运行，模型、认证与 SDK 出口仍归 Ubuntu。

## 三台节点的更新入口

沿用 CC 管理中心已部署的宿主机更新通道，为 `ubuntu-cc`、`ubuntu-cc-02`、`ubuntu-cc-03` 提供签名 Build 12。已接入节点不需要重新安装更新 agent。管理中心在用户确认后才提交安装任务；本次发布不代替用户执行节点安装，不操作 04、05、06。

签名归档附带 `deploy/host-update/apply.py`，接受已发布 Build 10 和 Build 11 的精确描述符及协议 23，拒绝未知或已修改的基线。目标固定 Build 12 / 协议 24，保留 Node 24.22.2、官方 CLI 二进制、SDK 0.3.286、锁文件、签名公钥和只读策略检查。完整程序校验、空闲检查、断开客户端、冷备份和失败回退沿用原有路径；不重新登录 Claude。已安装相同目标时检查就绪后直接返回。

## 配套要求

当前已发布的 Windows Build 27 使用协议 23，不能连接升级后的协议 24 服务。此次只发布 Linux 服务端及其配套 Web，不重新发布或更改 Windows pilot/stable。桌面完整使用需要另行打包发布协议 24 客户端。

Ubuntu 节点运行的 Claude 调用链路不变。作为 SSH 开发目标的设备还需具备 Linux、Bash、SFTP、`setsid --wait`、`mkfifo` 和 `timeout`；这与 Ubuntu 服务端的宿主机更新 agent 是两个独立功能。

新增 Build 11 基线准入和 Build 12 / 协议 24 目标签名检查先失败再通过。VPS 的隔离测试目录内，10 项迁移测试和 11 项策略升级测试通过；Docker 操作被模拟，没有操作生产节点。完整核心测试、类型检查、签名包的完整文件清单、公开下载哈希及三节点管理接口会在发布前后核对。
