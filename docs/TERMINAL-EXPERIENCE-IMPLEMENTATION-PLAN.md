# CC 终端体验改进实施方案

日期：2026-10-29（香港时间）。状态：六个阶段已实施并逐项审查，详见 [实施与验收记录](TERMINAL-EXPERIENCE-IMPLEMENTATION-STATUS.md)。本文件保留原始范围和验收要求；未打包、部署或调用真实账号/provider。

CC 检查基线：`172ce028bbccc73229ce54d031c840c0ff51dfe4`，分支 `codex/terminal-status-coordination`。参考 Crew `2.5.2`，提交 `64bc7d49a6e3ce53cf82b9fe33b1fa6ac3a6aca3`。用户采纳前次分析的第 1、2、3、4、5、7 点；明确排除第 6 点分屏。

## 1. 交付目标与范围

在现有单独终端窗口、多标签、36px 顶栏的基础上，改善输入编辑、键盘、文件访问、终端定位、历史恢复与 Windows 窗口控制。

| 项目 | 本期结果 |
| --- | --- |
| 输入辅助 | 默认收起的多行编辑框，每标签独立草稿、附件与展开状态；用户主动粘贴后在终端确认 |
| 键盘与字号 | 选区复制和 Ctrl+C 中断区分、中文输入法正确处理、焦点可预测，终端使用现有代码字号 |
| 链接与文件 | 普通网址、官方 OSC 8 链接、文件路径及图片预览；区分本机、Ubuntu 节点与其他设备 |
| 标签定位 | 在现有“全部终端”菜单中按别名、项目和节点筛选，支持键盘选择 |
| 历史恢复 | 显式选择已验证的官方 CLI 历史，启动新进程继续；不承诺恢复旧进程或丢失输出 |
| 原生窗口控制 | Windows 使用系统绘制的最小化、最大化和关闭按钮，保留关闭确认 |

不增加分屏、布局树、关闭视图后后台托管、托盘常驻、内置浏览器、自动续接、自动提交、命令重发、账号切换或计费切换。保留当前已确认的标签外观与细线关闭图标。

## 2. 实施原则

遵循 karpathy-guidelines：复用现有组件和路径，只添加本需求需要的状态和接口；不引入状态库、通用终端管理框架、插件架构或后台任务系统；不借机整理无关旧模块。

前端基础体验与远程协议改动分阶段交付。只测试新增核心行为和会受影响的现有入口，不重复全面检查已经验收的旧模块。本文中的关键不确定性在对应阶段用最小实验解决；不预先建设两套长期并存的实现。

输入辅助和历史读取不使用 `query()`、`readNativeStatus()` 或模型请求。既有 SDK/订阅合规问题按 [合规复查](CLAUDE-COMPLIANCE-REVIEW-2026-10-29.md) 独立处理；本方案不以改善终端体验宣称全程序已取得授权。

## 3. 现有能力与直接复用

- `TerminalWindow.tsx` 已持有稳定标签集合，`NativeTerminal.tsx` 已实现独立 xterm、隐藏输出处理、输入分段、ack、尺寸更新及未知结果确认；保留这些路径。
- `fontSizes.ts` 已有 `code` 字号，范围 10–24；原生终端当前固定 13，应接入现有偏好，无需新增“终端字号”配置体系。
- 主渲染器已有 `Composer` 的图片保存、附件状态、预览能力，以及 `link:open`、`path:inspect`、`path:act` 的链接/文件操作；复用其中必要部分，不把整个聊天 Composer 搬进终端。
- 终端子窗没有 desktop bridge、Node 或通用 IPC；新增操作仍由拥有该子窗的主渲染器执行，经窄控制句柄传给显示组件。
- `remotePrompt()` 已支持经 SSH 读写本机项目；查看本机图片时已有临时 scp 到 Ubuntu、Read 后删除的说明。附件引用需按这条真实执行路径适配，不另起一套无条件上传系统。
- 当前 CC sessionId 与原生 PTY 中 CLI 自建会话 ID 尚未建立可靠关联；不能直接拿前者传给 `--resume`。

## 4. 阶段 A：键盘、焦点与字号

### 改动

1. 在 `NativeTerminal` 使用 xterm 的键盘拦截处理已约定的终端操作：有选区的 Ctrl+C 复制，没选区的 Ctrl+C 交给 CLI；提供 Ctrl+Shift+C/V。剪贴板失败要保留选区/文字并给出局部提示，不把失败的复制变成中断。
2. 普通粘贴通过 xterm 的 `paste()` 进入现有输入管道，保留 bracketed-paste 语义。不得把剪贴板字符串直接当作命令自动加回车。
3. 热键仅作用于当前终端区域。弹窗、筛选输入和辅助编辑框获得焦点时，各自处理按键，不再同时发送终端控制字节。
4. 输入辅助框的输入法 `isComposing` 状态优先，确认中文候选字不能触发粘贴或其他操作。
5. 读取现有 `fontSizes.code`，修改 xterm `options.fontSize` 后仅对当前可见终端 fit/resize；隐藏标签在激活时更新尺寸。保持 xterm 实例、输出和阅读位置。

### 验收

- 有选区 Ctrl+C 只复制；无选区只发送一次 `\x03`；Ctrl+Shift+C/V 不产生额外终端字符。
- 中文组词确认、菜单 Enter、弹窗 Escape 不误入终端。
- 代码字号在默认值和边界值切换后，已打开标签立即更新，切换标签不重新 open；观察历史输出时不强制跳到末尾。
- 保留现有窗口取消关闭后的终端焦点行为；浏览器剪贴板权限不足时有可理解的提示。

## 5. 阶段 B：全部终端筛选

### 改动

在现有菜单顶部加一个输入框，按别名、项目名/完整目录、节点名和设备名做大小写不敏感的包含匹配。无需模糊搜索库、搜索服务或跨节点扫描。

打开菜单后聚焦筛选框；方向键在匹配结果间移动，Enter 激活标签，Escape 关闭并把焦点交回原终端。结果显示项目/节点等必要身份，长标题保留完整 tooltip。零结果时显示空状态。

“选项目新建”“标签别名”等操作仍是菜单独立操作，不混进匹配结果。首版不抢占 CLI 的 Ctrl+K 等全局按键；通过已有入口打开即可。

### 验收

10 个以上标签、重名项目、长中文别名、零结果和关闭后的焦点恢复。筛选仅改变显示，不启动、结束或重建任何终端。

## 6. 阶段 C：链接、路径与预览

### 改动

1. 通过 xterm 的普通网址识别和 OSC 8 link handler 处理链接；仅在用户明确点击时操作。使用已有主渲染器链接通道，不给终端子窗增加 shell 权限。
2. 文件路径识别按“完整逻辑行”处理软换行与中文宽字符，支持明确的 Windows 绝对路径、file URI 和节点绝对路径；不把普通单词或模型输出当作可信命令。
3. 本机路径复用 `path:inspect` / `path:act`；文件可能执行程序时沿用现有行为，显示所在文件夹或明确确认，不能因为来自终端就直接运行。
4. Ubuntu 路径显示其节点来源，支持只读文本/图片预览和用户主动下载。优先复用现有认证传输；若缺少节点文件读取接口，只新增必要的只读请求，不开放任意 shell 命令接口。文本与图片分别设有界大小，读取前检查所属连接/会话权限，跟随符号链接后的实际路径也执行现有访问边界。
5. 非当前设备路径提示来源及可用操作，不自动当成本机同名文件打开。相对路径只有在实际 CLI cwd 有可靠依据时才解析，不能以底栏的“项目目录”冒充实际 cwd；不确定时提供复制路径。
6. 图片与文本预览复用现有展示能力；不执行 HTML、不自动读取终端里出现的所有文件、不预取可能携带登录参数的网址。新日志仅记录必要身份/错误，不记录完整链接、文本内容或授权参数。

### 验收

HTTP/HTTPS、OSC 8、软换行长路径、中文/空格路径、缺失文件、两台设备同名路径、节点离线、图片过大、符号链接和可执行文件。未点击时不产生打开、读取、下载或 provider 请求；预览失败不影响终端输入和输出。

## 7. 阶段 D：多行编辑框、独立草稿与附件

### 界面和状态

终端底部增加小型“编辑输入”入口，默认收起；展开后复用 CC 的输入样式，最高约占终端窗口三分之一，避免挤掉正文。保留现有底栏和 36px 顶栏。

每个 tabId 维护 `draft`、附件列表和展开状态，存在当前工作区内存中；不保存到服务器或额外数据库。断线、切换标签与粘贴失败保留内容；关闭一个标签只清理该标签草稿。发送中的异步操作必须捕获 tabId、sessionId、terminalId 和连接代次，完成时不能改写另一个标签。

### 输入动作

- 普通 Enter 在编辑框换行。粘贴通过明确按钮触发；首版不自动追加回车、不循环重试、不用画面识别猜 CLI 是否正在输入提示词。
- 粘贴目标在开始时固定为当前标签，先验证同一连接代次、终端仍运行且允许输入；经该 `NativeTerminal` 的窄方法调用 xterm `paste()`，沿用分段与传输限制。避免绕过原有输入管道另写 WebSocket 发送逻辑。
- 粘贴完成后聚焦终端，用户检查位置与内容后自行 Enter。界面说明“已粘贴”只代表本地输入动作完成，不表示模型收到或任务成功。
- 首版粘贴后保留草稿，并提供明确清空操作。只有在后续引入可靠确认机制时再讨论自动清空，不能把 WebSocket 已发送当作 CLI 已消费。
- 多行粘贴依赖目标 CLI 的 bracketed-paste 支持；在固定支持版本上验证。未启用相应模式的目标不做静默多行注入，提供复制文本后手动粘贴的降级方式。

### 附件动作

复用现有图片保存、去重和 preparing/ready/error 状态。附件必须属于正确标签与项目设备，未准备好时禁止执行附件粘贴。文件路径以引用文本进入终端；本机文件通过已有 SSH 工具链读取。

图片不机械照搬 Crew 的“粘贴 Windows 路径让本机 CLI 自动识别”。在 CC 远程环境里，使用现有单文件临时复制/Read 流程，验证 CLI 可以读取该路径；临时副本由既有执行流程清理，不新增后台清理服务。若现有路径对某种来源不可用，明确提示该附件暂不支持，不宣称已经传给 CLI。

### 验收

两个标签分别编辑中文多行草稿并附图，切换后完全独立；折叠展开、变更字号、失败粘贴、创建中/已结束/断线时的按钮状态正确。粘贴时切换标签或关闭标签不得串输入。测试长文本分段、输入法、bracketed paste、附件准备失败和 CLI 正处于菜单时没有自动回车。

## 8. 阶段 E：建立官方历史关联并显式继续

这是唯一需要增加持久会话关联的阶段，与普通输入体验分别提交。

### 身份和数据

明确区分 tabId（显示实例）、CC sessionId（业务会话）、terminalId（PTY 进程）与 nativeSessionId（官方 CLI 历史）。后者不能从当前画面、标签标题、同名目录或时间相近的文件推测。

新建终端启动前生成独立官方 UUID，通过已支持的 `--session-id` 传给 CLI，并在现有 SQLite 增加最小关联表，记录 CC sessionId、nativeSessionId、nativeRoot、项目设备/路径身份及时间。复用已有请求关联，未知启动结果先确认，不为一次重试生成多个官方 UUID。创建记录与“历史文件已可恢复”分开，尚未提交第一条消息的终端可能没有有效历史。

查询只返回当前授权范围内、与来源项目/设备一致且有可靠关联的历史。恢复前检查官方历史文件存在、配置目录/nativeRoot 一致、没有同历史的活跃进程，继续沿用所有权、容量和受管审核约束。CLI 环境或账号已经变化且兼容性不明时明确提示，不通过查询模型来试探。

活跃检查覆盖 CC 管理的进程；不能由此声称发现了所有外部手动 CLI。外部占用由官方 CLI 自身检查或启动错误处理，拒绝后不得强制接管。关联记录说明其来自 CC 启动时指定的官方 ID，不承诺追踪用户随后在 CLI 内手动切换到的任意历史。

### 读取与恢复

- 优先复用经确认仅访问本地文件的元数据函数；必须验证该函数不启动 `query()`、不查询 provider、不读取登录 token。必要时只封装所需的有界元数据读取，不建设通用历史索引服务。
- “新开同项目终端”和“继续历史会话”分开。用户选定历史后，通过新 PTY 启动 `--resume nativeSessionId`；不自动发送未完成消息，不重放输入，不自动恢复工具调用。
- 恢复使用新的 CC 终端标签/业务会话承载，并保留对原业务会话和官方历史的明确关联；结束标签原有输出留在原处，不伪造新旧进程连续。
- 旧版本终端没有可靠官方 ID 关联时，不按相近文件名自动补映射；首版提示在官方 CLI 内选择旧历史。本功能首先覆盖新增后建立准确关联的终端，旧数据批量导入另行评估。
- 不把现有 SDK 聊天历史默认当作原生终端历史，也不扫描其他用户的全部 `~/.claude` 内容。

### 协议兼容

新增历史列表/继续请求采用显式能力协商。由于当前 `terminal.open` 为 strict schema，不向旧服务端发送额外 `resume` 字段；新行为使用独立命令，旧客户端的普通 open 保持语义。无能力声明时隐藏历史继续入口。字段、分页/数量限制及错误码在该阶段按真实元数据实现确定，不在前端猜测。

### 验收

新会话 ID 与参数一致；有消息的官方历史可继续；空历史、已删除历史、服务端重启、跨设备同名目录、活跃历史占用、无关联旧终端均有准确结果；失败不静默新建。列表读取零 provider 调用；新旧客户端/服务端组合兼容；数据库新增表可被旧版本忽略。

## 9. 阶段 F：Windows 原生窗口按钮

在 `electron/terminal-window.cjs` 的实际终端子窗配置中，使用与 `titleBarStyle: 'hidden'` 配套的 `titleBarOverlay` 替代当前自绘系统按钮。先用真实 Electron 验证 `about:blank + Portal` 子窗中的 caption area、系统菜单、拖动及关闭事件，再确定最终配置；不同时保留两排系统按钮。

- Windows 顶栏保持 36px。通过系统提供的标题栏区域信息预留右侧空间，并处理缩放/最大化后的变化，不能固定猜一个像素宽度。
- 终端标签的细线“×”、新建和下拉入口继续由 CC 绘制；系统窗口关闭仍进入现有 `requestClose/closeAll` 确认，取消时窗口与进程保持，部分失败时保留窗口和错误。
- 主题变化由主渲染器通过窄 IPC 更新所属子窗的 overlay；不开放任意 BrowserWindow 控制或子窗通用 desktop bridge。
- 浏览器嵌入与其他平台沿用适用的现有控制行为，不伪装 Windows 原生按钮。

### 验收

最小化、最大化/还原、Alt+F4、系统关闭与按钮关闭进入一致流程；关闭取消与部分失败不丢终端；Windows 原生悬停/系统菜单行为正常。真实窗口在 480×300、100%/125%/150% 缩放、不同根字号、长标签与多标签下，系统按钮不遮挡标签操作，底栏和输入辅助仍可使用。确认子窗继续没有 Node、desktop bridge 或 opener 权限。

## 10. 提交顺序与验证安排

| 顺序 | 建议提交范围 | 必须通过的验证 |
| --- | --- | --- |
| A | 键盘/焦点、现有字号接入 | 输入归属、IME、剪贴板、实例稳定和字号 fit |
| B | 全部终端筛选 | 多标签筛选、键盘导航、焦点恢复，无额外 open |
| C1 | 普通网址、OSC 8、本机文件及图片预览 | 软换行/CJK、已有文件保护、用户点击才打开 |
| C2 | 节点路径与远程预览所需最小接口 | 会话/设备归属、大小限制、离线和错误定位 |
| D | 编辑框、独立草稿与附件引用 | 多标签隔离、粘贴不提交、不丢草稿、文件实际可达 |
| E1 | 官方 UUID 绑定、最小持久表和元数据读取 | 重启后关联正确，无 provider 请求，无盲目映射 |
| E2 | 历史列表、显式继续与能力协商 | 官方 resume、同历史互斥、失败不新建及版本兼容 |
| F | 原生系统按钮、主题同步与布局 | 真实 Electron 窗口、关闭确认、DPI 与最小尺寸 |

阶段 A/B/C/D/F 可先交付；阶段 E 的历史恢复不能阻塞其他独立体验改进。实现时可以先完成 E 的 ID 绑定，为后续新终端积累准确关联，但历史继续入口必须在完整验收后开放。

最终执行 TypeScript 和客户端生产构建；复用 `native-terminal`、`terminal-workspace`、`terminal-window` 等相关现有回归，按新增风险补核心用例。纯样式只做实际窗口检查，不建立镜像实现的快照测试；不因本轮需求重跑无关老功能全套。测试使用模拟 PTY、合成历史及本机测试窗口，真实 Claude/生产试点作为独立授权步骤。

## 11. 完成标准与发布边界

本方案完成指六项体验能力按上述边界实现并验证，明确不包含分屏。现有多标签生命周期、背压、断线结束、容量、审核和关闭协调均保持可用；新增界面不能绕过这些边界。
