# 同一邮箱仅一台电脑在线

## 2026-10-30 切换确认（主分支已实现，待打包部署）

管理中心在密码验证通过后，检查同一账号在其他电脑是否存在未过期且最近 90 秒联系过的会话。有则返回 HTTP 409，保留原电脑的会话和连接票据。新版客户端在主进程弹出“取消 / 切换到本机”系统对话框，默认取消；只有用户确认才重新提交密码和 `confirmSwitch: true`。管理中心重新校验密码，并在同一事务中检查其他会话及完成替换。

客户端沿用已有的每 15 秒登录检查，没有新增网络轮询或后台扫描。管理中心在成功会话鉴权后更新 `session_activity.last_seen`，每个会话最多每 30 秒写一次。开着客户端但不操作、最小化或挂托盘，仍会保持在线；最近一次记录超过 90 秒则允许新电脑直接登录，并撤销旧授权。在线时间有最多 30 秒的记录粒度，断网、休眠与退出无法严格区分，弹窗因此使用“近期在其他电脑登录”。

同电脑的多个窗口不会触发切换提示。错误密码不会触发弹窗，也不会撤销旧授权。旧客户端遇到 HTTP 409 会提示需要更新，不能静默挤掉近期在线的电脑。

已有数据库启动时自动创建独立的 `session_activity` 表，保留原会话表结构，兼容回退到旧版管理中心。尚无在线记录的旧会话获得 90 秒保护期，避免升级后首次检查前被直接替换；已有在线记录不会因服务重启而刷新。发布需要更新管理中心和客户端；Ubuntu 授权续验逻辑无需改变。以下 Build 14/17 记录是此前已发布行为，不代表本次功能已上线。

验证：客户端及鉴权模块 23 项测试、HTTP/WebSocket 集成 2 项；覆盖取消/确认、错误密码、同电脑多窗口、等待确认时退出、30 秒节流、90 秒边界、迁移保护、旧版会话写入兼容、服务重启及真实连接撤销。类型和 Electron 主进程语法检查通过；未调用 Claude。

再次复查补充：生产前端构建通过。隔离 Electron 实例使用真实页面、preload、IPC、主进程及本地 HTTP/SQLite 验证取消保留旧登录、确认撤销旧授权，并核对系统对话框的默认/关闭操作均为取消；对话框选择由测试替代，尚非两台电脑上的人工弹窗验收。另使用原主分支提交 `29f8398` 中实际旧版鉴权代码，完成旧版→新版→旧版→新版的数据库回退/再升级验证，原会话保护、旧版登录及再次确认切换均通过。本轮未发现新的阻断问题，未访问生产服务或调用 Claude。

## 登录规则

- 新电脑输入正确邮箱和密码后，管理中心立即撤销该邮箱在其他电脑上的会话和连接票据。密码错误不会影响原电脑，其他邮箱也不受影响。
- 同一台电脑的多个 CC 窗口使用现有本机设备标识，可以同时使用。设备标识由主进程读取，页面不提交自选标识。旧客户端没有设备标识时，每次密码登录作为独立电脑处理。
- 自动登录仅恢复已有有效会话，不重新提交密码，不会反过来踢掉新电脑。旧电脑退出后的迟到响应和退出请求不能删除新电脑的登录。
- 客户端主进程每 15 秒检查一次。收到 401 后清除内存和加密保存的会话、关闭本机连接通道，页面回到邮箱登录并清空密码、记住登录及自动登录选项。网络暂时故障不清除会话。
- 已连接的 Ubuntu 也会每 30 秒续验授权并拒绝旧票据。离线或休眠电脑在恢复通信后识别失效，不承诺离线电脑即时改变界面。

这是正常客户端的账号登录限制，设备标识不是硬件证明。不阻止同一个人主动重新输入密码切回原电脑，也不提供防修改客户端或防克隆系统的授权保护。

## 部署与使用

安装最新[邮箱专用客户端 Build 17](CC-SPACE-EMAIL-ONLY.md)：`D:\cc-desk-tunnel\artifacts\cc-space-email-only-build17\CC-Desk-Tunnel-Setup-0.3.7-x64.exe`。管理中心在“登录用户”页说明单电脑规则，用户无需额外开关。先确认 Ubuntu 已升级为 Linux Build 5，并已在管理中心设置自己的邮箱密码。

在电脑 A 通过邮箱登录，再在电脑 B 用同一邮箱登录。B 应正常进入工作空间，A 应自动返回登录页。然后重启 A：不能凭旧记住登录恢复连接；必须重新输入密码。无需发起 Claude/JEV 请求即可验证。

## 关闭传统凭据入口

单电脑规则只约束邮箱账号。`PROXY_LOGIN_MODE=both` 保留的传统服务 token 不属于邮箱会话；要强制客户端统一遵守此规则，Ubuntu 必须切换到 `email`。由于还没有收到邮箱实机验收确认，不能把节点已经切换写成已完成。

先确认至少一台电脑通过邮箱连接成功，结束正在运行的任务并退出客户端。在 Ubuntu 终端执行：

```sh
sudo cp -p /srv/cc-desk-tunnel/config/service.env /srv/cc-desk-tunnel/config/service.env.before-email-only
sudo nano /srv/cc-desk-tunnel/config/service.env
```

把已有 `PROXY_LOGIN_MODE` 行改为下面内容，没有则新增一行，保存退出。不要修改其他凭据或把文件内容发到聊天。

```ini
PROXY_LOGIN_MODE=email
```

然后重启原容器，使服务重新读取配置：

```sh
sudo docker restart cc-desk-tunnel-ba938975-proxy-1
```

重新使用邮箱连接成功，并确认传统 token 连接被拒绝。若邮箱连接失败，先检查是否确实为 Linux Build 5 及节点监控配置；需要恢复入口时，将该行改回 `PROXY_LOGIN_MODE=both` 后再次重启。不要重建镜像或恢复旧业务数据库。

## 兼容与回退

管理中心在数据库中新增独立的 `session_devices` 表，保留旧 `sessions` 表结构。已有会话在下一次成功登录前保留；新电脑登录时会撤销无法识别设备的旧会话。新增表不会阻止旧管理中心运行代码回退，回退不恢复已经撤销的登录。
