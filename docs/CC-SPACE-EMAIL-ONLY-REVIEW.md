# 邮箱登录页 Review（Windows Build 16）

本轮检查登录页、保存状态恢复、授权失效、旧入口迁移，以及管理中心连接配置到客户端的传递。发现三处 P2 问题，均先以界面测试复现，再修复通过：

- 显示密码后登录失效，下一次输入仍可能明文显示。现在清空密码时重置显示状态。
- 启动读取保存状态较慢时，会覆盖用户刚输入的邮箱/密码，甚至启动旧账号自动登录。用户编辑、开始登录、退出或收到失效通知后，忽略迟到的恢复结果。
- 保存状态读取失败缺少错误提示，形成未处理的 Promise 拒绝。现在显示可定位的错误原因，用户仍可重新输入邮箱与密码登录。

9 项邮箱界面回归及 17 项授权测试通过。验证包含单个工作空间自动连接、多工作空间选择、管理中心下发的地址与指纹、旧配置不恢复、登录失效、同电脑多窗口、跨电脑撤销、密码修改与邮箱修改并发边界。TypeScript、仓库检查、实际打包程序启动、旧配置迁移与包内身份检查通过；3 个主进程模块及 71 个前端文件与构建源码/产物一致。未重复运行不涉及的全量业务测试。

使用 `D:\cc-desk-tunnel\artifacts\cc-space-email-only-build16\CC-Desk-Tunnel-Setup-0.3.7-x64.exe`，退出旧版后安装。它替代 Build 15，协议仍为 22，Linux 继续配套 Build 5。精确大小、摘要和源码见[证据](evidence/email-only-review-2026-10-28.json)。

本轮只修改客户端，管理中心无需重部署。未安装用户本机程序、未改公开更新索引、未发起生产模型请求。Ubuntu 是否已切换 `PROXY_LOGIN_MODE=email` 及真实两电脑验收仍未收到确认；本地模拟 WebSocket 验证不代替生产实机结果。见[安装说明](CC-SPACE-EMAIL-ONLY.md)与[关闭旧 token 入口](CC-SPACE-SINGLE-COMPUTER-LOGIN.md)。
