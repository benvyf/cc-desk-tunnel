# CC SPACE 邮箱登录与节点接入设计草案

2026-10-28。状态：个人使用首版已实现并通过本地核心验证，配套候选为 Windows Build 11 / Linux Build 5 / 协议 22，部署和实机验收单独记录。原有服务地址连接继续可用；邮箱登录复用监控节点的 nodeId。

## 用户目标与边界

管理员在 VPS 的 CC 管理中心保存 Ubuntu 节点连接配置，创建邮箱/密码登录用户并分配可访问的节点。桌面用户只填写邮箱和密码；仅获授权的节点可以连接。一台节点直接进入，多台节点显示工作空间选择。

用户已确认：先只给自己使用。首期只创建本人的邮箱用户并绑定 ubuntu-cc，同一邮箱日后可访问多个节点。邮箱是 CC SPACE 用户名，独立于管理员账号及 Claude 官方账号；不自动使用监控到的 Claude 邮箱建号。不涉及 SMTP、自助注册、找回邮件、OAuth 或计费。

**授权节点不等于隔离租户。** 当前服务端在认证后返回该节点完整会话列表并提供该节点工作区。不同邮箱若分配同一节点，会共享其会话、文件和 Claude 环境。若需求为互不信任的多用户独立使用，首期应为每人分配独立节点/容器/数据目录，或另行实现完整会话、文件、工具和执行环境权限；不能只过滤界面或会话列表就称为隔离。

## 信息布局

保留顶部“账号监控 / 客户端更新 / 内容审核”。账号监控页中的节点摘要增加“管理设备”入口，打开 ubuntu-cc 详情。

详情页三个页签：

1. Claude 账号：复用现有监控数据、账号编号、额度、采集状态和备注。
2. 连接配置：显示名称、固定 nodeId、客户端可达的 wss 地址、证书指纹；高级区域保存传统服务凭据（掩码，留空保留，禁止回显）。配置有效性与监控上报状态分别显示，不把“监控最近有上报”写为“可连接”。
3. 登录用户：邮箱、备注、启用状态、最近登录、获授权工作空间；创建用户、重置密码、停用和撤销登录。一个用户可分配多个节点，表中用户是全局实体，修改密码应提示影响该用户所有节点。设备页只管理该设备授权。

用户增多后，可增加顶层“登录用户”全局入口并复用同一数据及编辑组件；首期无需单独堆叠管理系统。

桌面保持 CC SPACE 品牌、留白与主按钮配色。主表单改为“登录 CC SPACE”，邮箱、密码、记住登录、自动登录。管理中心 HTTPS 地址由定制版预置，日常不填写。底部“使用服务地址连接”保留现有方式，便于迁移和排障。登录错误统一提示，网络故障、节点离线、未授权与版本不匹配分别引导；没有节点显示“暂未分配工作空间”。多个节点进入工作空间选择，一台节点直连。

密码恢复首期显示“请联系管理员重置”。记住登录保存可撤销会话，不保存原始密码。登出清除缓存授权，切换邮箱时清除旧账号内存状态与连接。

## 数据与认证

复用 VPS 部署、管理员鉴权、请求审计以及节点 ID，新增独立用户/授权存储（适合现有 SQLite 习惯）：users、node_connections、user_node_grants、login_sessions。密码使用带独立 salt 的 scrypt 派生值；节点共享凭据若保存，用 VPS 独立主密钥加密且不返回普通客户端。日志不包含密码、共享凭据、完整令牌。

普通用户 `/cc-access/v1/` API 与 admin API 明确区分：登录、退出、工作空间列表、申请节点连接授权；管理 API 包含用户创建/重置/停用、节点配置、节点授权。保存用户修改会撤销该用户已有登录。复用现有密码派生方式，不复用管理员会话或给客户端管理权限。管理操作将管理员标识及节点/用户 ID 写入服务日志，不记录密码和票据。

流程：桌面主进程向固定可信 HTTPS 管理中心验证邮箱密码 → 在主进程保存可撤销的登录会话 → 查询用户可用节点 → 向管理中心申请指定节点的短期连接票据 → 使用节点 URL/证书指纹及票据直连 Ubuntu。客户端固定入口是已有可信域名 https://api.ghostapi.org。

不将永久共享服务 token 当作邮箱登录响应。首版采用随机不透明票据，数据库仅保存摘要，并绑定 nodeId、用户和登录会话；沿用既有监控节点凭据，通过 HTTPS 向管理中心验证，避免引入第二套签名密钥管理。新连接票据 2 分钟内使用，现有连接每 30 秒续验，授权租约最长 60 秒；停用、改密或撤权后断开受影响连接。管理中心不可达时新登录拒绝，续验失败关闭既有连接。记住登录时，30 天内有效的可撤销会话经系统凭据加密保存；未勾选时仅主进程内存保存、最长 8 小时。首版没有独立的刷新令牌或自动滚动延长有效期，期满重新输入密码。

票据对应的后续工具/隧道连接必须继承已认证会话身份，不能退回要求客户端持有永久 token。新登录模式启用、旧手动 token 模式关闭时，应同时覆盖 Web 入口及其它能绕过用户授权的接入点。迁移期可保留旧模式供原用户使用，但明确标记它独立于邮箱账号停用；试点验收后管理员可关闭，Ubuntu 控制台仍保留恢复途径。

管理中心入口必须用可信 HTTPS（优先域名与受信任证书）；节点可继续固定证书指纹。只有认证成功后的可信配置才可更新节点指纹，客户端不得在陌生登录源上“自动信任”证书。URL 只接受 wss，阻止账号信息进入 query；服务端检查配置的网络请求需明确目标和超时，避免任意 URL 探测内网。

## 迁移与验证

1. 管理中心新增用户和节点配置，保持当前手动连接可用，不更改已保存凭据。
2. Ubuntu 新版支持管理中心票据及撤销，新版客户端增加邮箱登录与原方式迁移入口。涉及握手/协议和镜像兼容性时提升配套版本，沿用当前严格兼容性检查，不绕过摘要。
3. 先绑定 ubuntu-cc 和管理员自己的一个测试用户；检查成功登录、直接进入单节点、记住登录、退出/重登、断网提示。测试不得自动触发 Claude 或审核供应商调用。
4. 核心安全回归：错误密码不泄露账号存在性、密码重置和停用撤销旧会话、无授权/过期/篡改/错节点票据拒绝、长连接撤销、Web/工具/隧道无旧 token 绕过、客户端本地不落盘原始密码或共享 token。
5. 用户正常使用确认后，再部署公开版本，并由管理员选择是否关闭传统 token 接入。已有历史会话与配置不迁移到另一节点，不宣称邮箱自动提供租户隔离。

## 部署说明

用户范围已明确为仅本人，不建设多租户隔离。日后对外共享前必须重新确认共享工作区还是独立环境。
用户已提供 VPS SSH 入口并授权部署，既有管理中心使用可信 HTTPS。部署新增 /cc-access/v1/ 的 Nginx 反代路由；节点的现有监控配置提供验证请求凭据。PROXY_LOGIN_MODE 默认为 both（具备监控配置时同时支持邮箱和旧 token），可显式设置 email 关闭普通旧 token 与 Web 登录入口；管理维护接口仍使用独立原服务凭据。首轮保留 both，邮箱登录实机确认前不关闭旧入口。
