## 1. 目标与范围

保留 CC Space 内嵌终端、独立窗口和现有预测回显，改善退出可靠性、高频输出流畅度，以及从终端返回聊天时的操作连续性。

本轮按 A 可靠性修复 → B 输出合并 → C 有条件采用 WebGL 的顺序实施。D 缓存提醒单独安排；空闲自动压缩另立功能方案。本方案不引入 ccdt、不移除网页版终端、不重写输入预测，不扩大支持的 CLI/平台范围，也不修改账号、审核或模型出口。Claude CLI、SDK、账号及模型网络始终在 Ubuntu。

当前没有真实用户机器上的卡顿测量。因此“更流畅”是待验证目标，不能仅凭减少消息数宣称性能改善；WebGL 可能改善绘制，也可能受 GPU/驱动、窗口数量和预测覆盖层影响而无收益。

## 3. 阶段 A：可靠性与聊天衔接

### A1. 正常 SSH 结束时送完尾部数据

- 先在既有真实 TCP/WebSocket 测试夹具复现：写入超过常见流缓冲的小段及大段数据后立即正常结束，接收端比对全部字节，不用测试替身只断言调用了 `end()`。
- 桌面端正常关闭允许 stream 送完已接收数据并完成关闭；错误、主动断开连接和应用退出继续沿用明确的取消/清理语义，不把所有 `destroy()` 换成等待。
- 对正常关闭但无响应的连接，参考上游设置 10 秒关闭上限；正常完成时清理计时器，关闭期间继续保留可供现有关闭入口清理的资源引用。避免在已关闭后设置失效计时器或重复关闭。
- 验证服务端与桌面两侧组合行为；服务端已实现的修复不重复替换。

验收：双向尾部字节完整、正常关闭完成、对端失联有界结束、连接重置与主动取消及时清理；不引入重复输出和取消后继续发送。复用 `apps/desktop/test-main/tunnel-channels.test.mjs`、`tunnel.test.mjs` 和 `apps/server/test/tunnel.test.ts`，只补直接缺少的场景。

### A2. 终端之后可正常压缩上下文

- 复现“新会话只在终端中聊一轮 → 退出 → 回到聊天”时，真实原生历史存在但压缩按钮仍禁用的问题。
- 仅在对应原生历史读取成功后记录持久化状态，复用已有 `native.context` 事件；核对原生 ID、配置目录和项目目录，不能把旧独立终端或 `/resume` 到另一历史的状态绑定到当前聊天。
- 状态记录放在最终历史导入后、退出状态完成前；事件处理保持幂等，不重复导入历史或生成模型请求。原生历史查询失败须可溯源，不能伪装成“已持久化”或“空历史”。
- 空会话、坏 JSONL 的现有保护保持；不得扩大历史扫描范围或改变删除条件来修复按钮。

验收：新终端产生有效原生历史后可压缩；已有聊天再进终端正常；空历史不虚假启用；读取失败保留历史并提供错误线索；切换其他原生历史不串绑。用现有服务端夹具和真实临时 JSONL 验证，加一个按钮状态界面用例。

## 4. 阶段 B：输出合并发送

### 最小实现

- 只在服务端 `NativeTerminal` 合并已附着终端的实时输出，客户端不再叠加另一层合并。键盘输入保持即时发送。
- 起始参数采用上游的 5ms 和 16,384 个 UTF-16 code units；后者是 JS 字符串长度阈值，不称为 16 KiB。最终传输帧与 ACK 仍按既有 UTF-8 字节计算。首版不添加用户设置或自适应调参。
- 收到第一段时启动一次计时，不因后续输出重置期限；达到长度阈值立即 flush。计时器只能提供调度目标，事件循环繁忙时不能保证严格 5ms。
- 保留既有 `send()` 的分帧、代理对保护、字节计数和背压。服务端屏幕模型仍立即接收原始输出，避免恢复画面落后；ANSI 序列可以跨帧，但不能被删除、重排或转码。
- 正常进程退出和明确关闭前，处理已收集的数据，输出顺序在 `terminal.closed` 之前；不为已断开的 owner 重发，也不改变现有关闭期间忽略新输出的语义。
- detach 时清理合并计时器及待发缓冲；数据已进入屏幕模型，由下一次 attach 的快照负责恢复，不能先发快照再补发旧缓冲。attach 快照和其后的 pending 输出继续沿用现有顺序。
- flush 清空本次缓冲与计时器后再发送；不会因暂停、关闭或重复调用创建悬挂任务。多终端各自独立，不能全局混合输出。

### 与预测回显的兼容门槛

保持字节顺序是必要条件，但不是充分条件：合并可能让预测器看不到某些中间输入区画面。不得用收到一帧、TTL 到期或 WebSocket ACK 充当按键确认。

复用现有预测用例，对同一输出序列增加两种关键交付方式：多次重绘合并成一帧、ANSI 序列跨帧切分。重点检查：

1. ASCII 与中文 IME、预测中退格；实际发送输入与关闭预测时逐字节一致。
2. `↑` 召回 `ab` 时提前输入 `b`，旧画面不能误确认新输入；重复字符和重复背景帧同理。
3. 超过 800ms 才到的真实回显、预测开关切换、resize、焦点丢失、断线重连；旧代次不能确认新数据。
4. 普通可确认输入最终清除覆盖层；存在真实歧义时允许继续暂停预测，不允许重复字符、错删、虚假确认或重发按键。与基线比较是否新增不必要的长期暂停。
5. 拷贝、真实 buffer 和历史不包含预测层文字。

若因合并出现退化，先定位丢失中间画面对确认机制的影响；只修对应兼容点，不能通过放松确认、缩短 TTL、清空不确定状态或关闭预测来交付。

### 测量与验收

- 在同机同版本环境记录修改前/后，使用相同录制 CLI 输出和相同网络延迟；低延迟与约 200ms 回声各测一次核心交互。不要将 round-trip 延迟与单向延迟混记。
- 记录输出总字节、帧数、交付到 xterm 处理完成的 P50/P95，以及输出回放时间；本地预测另测按键到覆盖层插入。区分 DOM 插入与真实像素呈现。
- 对“同一时间片内大量小写入”的固定负载，帧数应明确减少；输出文本和最终屏幕一致。低频单次输出不允许等到后续数据才发送。
- 新增合并等待以 5ms 为设计预算；计时精度与环境抖动单独记录，不把它当硬实时 SLA。若响应延迟明显超过这一预算或流畅度没有改善，先分析，不直接默认扩大发送间隔。
- 复用既有 128/32 KiB 背压场景验证真实字节 ACK、暂停/恢复、最后 flush、detach/attach、取消后无迟到发送。未改变的阈值不重新做全部组合。

## 5. 阶段 C：WebGL 仅在有收益时采用

先完成 B 并测量剩余瓶颈。仅当高频输出仍有可观察的绘制卡顿时进入本阶段；若瓶颈主要在网络、预测处理或 xterm 解析，WebGL 不作为默认答案。

### 实现边界

- 选择与锁定的 xterm 6.0.0 兼容的 WebGL addon，复用同一个 xterm 实例；首轮不顺带升级 xterm、预测插件或 Claude CLI。
- 在终端所属 document/window 内加载 addon，主窗和独立窗口都验证；注意预测插件会使用 proposed API 与字符尺寸信息，两插件不能互相覆盖其启用/恢复状态。
- 初始化失败或 context lost 时 dispose WebGL addon，恢复 xterm 默认渲染器；不重建终端、不重启 PTY、不重新发送输入。失败不应无限重试或反复弹窗。
- 渲染器变化后使用既有预测 refresh 清除覆盖层并重新读取字符尺寸，保留预测器的未确认输入/编辑恢复状态，不能重建预测器来抹掉不确定性。
- 字号、缩放、DPI、主题、隐藏标签再显示和独立窗口中的覆盖层坐标必须与真实字符一致。首次覆盖默认渲染器和 WebGL 两条路径；不新增用户必须理解的 GPU 参数面板。

验收：真实 Electron 中对比默认/WebGL，检查中文宽字符、光标、快速输入后的覆盖层撤下、滚动选区复制、resize、字号 10/13/24、缩放 100/125/150%、主窗/独立窗口和多个已打开终端。物理中文输入法、GPU context 丢失后的继续输入须实测；模拟 composition 通过不代替 Windows 输入法验收。重点组合测试，不穷举全部笛卡尔积。

准入条件：同负载可重复观察到绘制收益，预测无新增错位/重影，GPU 失败回退可用，多窗口无明显资源退化。若不满足，保留已完成的 A/B，暂不合入 WebGL；不为维护两个表现不明的渲染模式增加复杂配置。

## 6. 阶段 D：后续上下文体验，单独实施

先考虑缓存临近过期/已过期提醒，复用现有压缩和新建会话操作。缓存一小时只是上游采用的估计窗口，不保证真实命中或准确费用。只有服务端已有可信的最后活动时间与上下文读数才显示相应信息；若不足，先定义最小服务端状态，不能用客户端窗口停留时间猜测。

提醒不抢终端焦点、不自动向 CLI 注入命令；终端占用期间不得绕过会话锁发起聊天压缩。显示估算与可操作状态，避免后台输出持续重置提醒。

自动压缩另立方案，默认关闭。它会发起真实模型调用、消耗额度并改变上下文，需明确账号/配置目录、离线执行权限、审核流程、无执行通道时的运行条件，以及与任务/终端占用的互斥。不能把纯 CLI 无会话绑定的终端套入聊天压缩流程，也不能直接复用上游代码假定兼容 CC Space 的受管边界。

## 8. 本次方案 review 结论

已针对当前相关源码完成静态核对，并将以下修订纳入方案：

- 输出合并阈值明确为 UTF-16 code units，ACK 明确为 UTF-8 字节；不混淆 16K 字符和 16 KiB。
- 保留立即更新服务端屏幕模型，明确 detach 丢弃待发合并缓冲的恢复依据，以及 attach 不重放旧缓冲。
- 指出 xterm 解析回调可能跳过中间画面，预测兼容必须验证分组变化；有歧义时允许保守暂停，不能许诺任意输入都立即恢复。
- SSH 修复区分正常 EOF、错误与主动取消，并要求真实流数据完整性证据；不重复替换服务端既有修复。
- 上下文按钮问题标为待复现，禁止跨原生历史绑定，并保护损坏/未知历史。
- WebGL 从必选项改为有性能证据后采用，明确独立窗口、proposed API、DPI 与 context lost，禁止通过重建预测器或 PTY 回退。
- 缓存提醒与自动压缩移出首轮，说明费用、会话锁和执行边界；发布规则的既有客户端缺口列入交付条件。

静态 review 只能说明实施约束与验收要求已具体化。真实流关闭、输出分组合并后的预测表现、GPU 收益和物理输入法表现仍须实施后按上述步骤取得证据，当前不声称已通过。
