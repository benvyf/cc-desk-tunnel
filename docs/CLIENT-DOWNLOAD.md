# 定制客户端完整安装包

## 下载与安装

登录 [CC 管理中心的客户端更新页](https://api.ghostapi.org/cc-updates/admin/updates)，在“下载安装包”选择已发布的 Windows x64 完整安装包。页面显示版本、Build、配套协议、大小与更新说明，可复制下载链接，在“校验与构建信息”查看 SHA256 和源码提交。

正式通道和试点通道分开显示；未发布、撤回或索引过期时没有下载按钮。已打开页面在索引过期后自动停用入口，管理员续期后点击“刷新”恢复。下载链接本身是公开制品地址，不包含管理员凭据。历史制品可能仍保留，安装前以管理中心当前发布状态为准。

当前 pilot 完整包为 0.3.6／协议 20、Windows Build 5，配套 Linux Build 2。Build 5 修复升级断线后误读历史失败状态；下载与续期已上线，完整进度和验收见[当前交接文档](../DEVELOPMENT-HANDOFF.md)。历史 Build 2/3/4 制品保持原样。

先退出 CC，再运行完整安装包，保持原有安装范围和路径以覆盖升级、保留连接配置。通常不需要卸载。安装包包含随包的 OpenSSH 和 PowerShell 组件，不包含管理员凭据、Claude 登录信息或用户会话。

## 服务端与账号

Windows 完整包用于连接配套协议 20 的 CC 服务端，不会自动升级 Ubuntu。第一台 Ubuntu 的实际运行服务已核对为 0.3.6／协议 20，并由用户确认安装被动监控；其余节点需按各自真实版本单独核验。

账号监控在 Ubuntu 获取现有身份／额度事件时同步到 VPS，审核由配套服务端与 VPS 执行。客户端下载、管理中心刷新和本次打包验收不发起 Claude 额度查询或聊天测试。

## 源码与发布

Build 2 的原始发布源码身份为 `4a39bc35008707366949496f9219e9b68c8d0856`，通过 VPS root 保存的 Git bundle 恢复并合并。生产公开身份固定在 `deploy/managed-client.json`，生产私钥仅在 VPS；按 [VPS 统一发布](VPS-RELEASE-CREDENTIALS.md) 操作。

新构建使用独立 Build 和干净源码提交，保留旧 Build 2 制品。先发布 pilot，不自动修改 stable。管理中心上线不代表用户当前电脑已经升级；本机安装由用户选择执行。
