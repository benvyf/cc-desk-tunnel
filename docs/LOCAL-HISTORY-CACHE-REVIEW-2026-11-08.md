## 复现的问题与修正

| 优先级 | 触发条件与原行为 | 修正与回归 |
| --- | --- | --- |
| P1 | 最近一次订阅超时，可信末尾为 10，随后收到 30 但缺少 20；加载更早页的 prepend 把 30 提升为可信游标，下一次补拉永久跳过 20。 | prepend 只有在原尾部已 synced 时才更新可信游标；缓存启用时，未同步尾部不能被分页标成 loaded。回归断言下一次仍从 10 补拉。 |
| P1 | A 的主订阅迟到返回 invalid_cursor，而界面已经选中 B、侧边仍观察 A；按旧 retain=false 重试会把服务器主订阅切回 A，停止 B 的流式输出。 | 重试前重新检查会话是否仍被选中或观察，并按当前角色决定 retain。回归确认 B 仍是主会话，A 只发保留订阅。 |
| P1 | 磁盘副本已显示，但首次同步失败后 loading 变为 false，旧副本上的消息、审批、任务及原生控制可能被解锁；仅用 cacheReady 保护还会被关闭开关绕过。 | 为已注入但尚未验证的副本保留私有来源标记，直到真实 replace/append snapshot 到达或内存被清除。主聊、侧聊、停止快捷键、原生状态读取和终端/分叉入口使用同一保护。关闭开关后仍保留只读约束；重试继续使用可信游标。浏览器沿用原有 loading 分支。 |
| P2 | 关闭再开启缓存只执行 open，当前对话的 synced 已清空，却没有新订阅，因此界面显示已开启但持续不记录。 | 开启成功后重新同步当前选中与观察中的会话，snapshot 到达后恢复持久化。增加真实 Electron 开关回归。 |
| P2 | 在异步读盘期间关闭缓存，旧读取被取消，但本来等待读盘结束才发送的订阅也丢失，界面可能一直没有历史。 | 关闭及清除完成后，只为仍属当前连接、仍被选中或观察的原读取会话，恢复不使用缓存的网络订阅。 |
| P2 | 崩溃发生在完整 JSON 写入之后、末尾换行写入之前，读取尚可成功；下一次 append 却把两个 JSON 值粘在一行，之后误删整个文件。 | 检测末尾分隔符缺失，下一次追加先原子重写。真实文件回归验证追加后仍保留两条独立记录。 |

上述问题均以失败用例复现后修复。同步失败的真实 Electron 用例还验证：错误出现后输入保持禁用，关闭缓存并返回会话后也不能发送未确认的副本内容。
