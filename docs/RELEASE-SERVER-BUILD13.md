## 修改

迁移入口默认在构建前清理未使用 Docker 构建缓存，检查构建和备份空间；离线预检后再次清缓存并检查备份/恢复预算，不再依赖 agent 传 `--cleanup`。解包后和冻结切换前继续检查空间，客户端只在预检和空间检查通过、确认任务空闲后自动断开，失败沿用冷备份及回退。不会主动删除原镜像、容器、数据、账号、管理员策略或回退备份。

清理后空间不足仍在切换前停止，不承诺任意磁盘容量或断电情况下均能升级成功。该流程是后续签名宿主机迁移的默认行为，不应再由调用方选择是否准备空间。

Build 13 使用当前应用版本 0.3.10、协议 24，保持 Node 24.22.2、官方 CLI 和 SDK 不变。新锁文件与 Build 12 的差异只有桌面 workspace 版本 0.3.7→0.3.10；迁移对旧基线锁和新包锁分别精确校验。已知 Build 10、11、12 的原始描述符和协议均单独固定，未知基线拒绝，不覆盖原 Build 12 签名归档。
