# SSH 远程开发：最小实施方案

2026-11-04（香港时间）。本版替代上一版方案。实现已进入本地工作区，隔离测试与剩余验收见 [实施状态](SSH-REMOTE-DEVELOPMENT-STATUS.md)；尚未生成或发布安装包，未部署生产节点，真实环境联调未进行。后续按用户授权引入的增量见第 10 节，该节取代首版中相应的范围限制。

## 1. 交付目标

用户在 CC SPACE「设置 → 连接」手动添加一台 SSH 设备，填写目标项目的绝对路径，然后在现有聊天界面让 Ubuntu 上的 Claude 读取、修改、搜索该项目并执行编译或测试。

```text
模型服务 ↔ 既有 Ubuntu：Claude CLI / SDK、认证、模型请求、会话历史
                     ↕ 既有 WSS 控制与执行通道
              本机 CC SPACE：界面、SSH 连接与转发
                     ↕ 本机主动建立的 SSH
              目标设备：项目文件、命令、编译和测试
```

完成标准是这条链路可用，而不是拥有一个完整 SSH 客户端。新增连接不改变 Claude 的运行位置和网络出口。

首版范围明确为 Windows 桌面连接具备 `/bin/bash` 和 SFTP 子系统的 Linux 设备。这是本版缩小实施面的假设，不代表已确认用户的全部设备类型。遇到其他系统明确提示未支持，不猜测 Shell 或执行位置。

## 2. 必须保留与不进入首版的内容

| 内容 | 是否实施 | 原因 |
| --- | --- | --- |
| 设置「连接」、列表、手动添加、连接/断开/删除 | 是 | 用户管理执行目标所必需 |
| 身份文件和密码认证 | 是 | 常见的两种直接登录方式，ssh2 已提供；不额外集成 Agent |
| 主机指纹确认、错误提示、秘密不进日志 | 是 | SSH 正确建立连接所必需 |
| 手动填写远程项目路径并校验 | 是 | 建立会话与目标目录的确定绑定 |
| exec 与 SFTP 通道 | 是 | 衔接现有命令、文件和 scp 使用方式 |
| 接入现有 Ubuntu 执行通道与会话 | 是 | Claude 真正操作目标项目所必需 |
| SSH 配置发现/导入、扫描网段 | 否 | 手动添加即可完成目标，省去发现页和解析依赖 |
| 独立 SSH Shell 界面、目录浏览器 | 否 | 命令执行与路径输入已足够，不扩展终端产品 |
| 系统 Agent、跳板机、端口转发、自动重连 | 否 | 不属于当前开发闭环 |
| 文件树、预览编辑、附件上传、Git 分支显示的远程适配 | 否 | 首版隐藏或禁用这些未适配入口，防止操作本机同名路径 |
| 持久任务接管、远端常驻代理、文件同步 | 否 | 引入新部署或生命周期系统，非当前目标 |

身份文件支持通过 ssh2 解密的加密私钥，口令按需输入。密码与口令只在连接期间保存在主进程内存；断开后重连重新输入。已有 SSH 配置发现截图作为后续体验参考，首版点击「添加」直接进入手动表单。

## 3. 不可改变的网络边界

1. Claude CLI、Agent SDK、账号认证、模型请求及模型相关后台功能全部留在既有 Ubuntu，经 Ubuntu 现有网络出去。本机和目标设备不启动 Claude，不新增模型 SDK、endpoint 或 provider 凭据。
2. 不把 Ubuntu 的模型代理、登录目录、账号令牌或模型端口转发到本机或目标设备，不增加本机代发模型请求的路径。
3. SSH 登录由本机完成，目标私钥、密码和口令不交给 Ubuntu。Ubuntu 只持有当前本机适配端点的临时登录身份。
4. 目标不可用时只报错或沿用已有服务端离线等待，不切换到本机、Ubuntu 项目目录或另一台设备执行。不自动重放已发出的写入或命令。
5. 模型使用的项目内容、工具结果仍经 Ubuntu 返回；本方案不改变既有的数据流向。

沿用 `scripts/model-boundary.mjs` 的桌面依赖检查，并对新增调用链做实际出站验证。静态检查不是网络沙箱：普通开发命令使用目标机器的正常网络，本方案不为任意用户代码新增全系统联网限制。

## 4. 接入选择及依据

### 4.1 本机终止两段 SSH，复用既有设备通道

采用已依赖的 `ssh2`。每个开启的 SSH 配置对应一个稳定设备 ID、一条本机到目标的 SSH 连接，以及一个到当前 Ubuntu 服务的后台设备连接。本机项目继续使用原来的设备通道。

后台设备连接不是新窗口，也不是现有“新建服务连接”功能。它只让 Ubuntu 识别这个目标并为它建立既有 Tunnel。多个目标各自持有连接，路由通过既有 deviceId 完成，不建立新的通用路由系统。

执行链路：

1. 本机确认目标主机指纹，完成认证，探测 `/bin/bash` 和 SFTP。
2. 本机启动仅监听 `127.0.0.1` 的临时 ssh2 Server，身份独立于目标主机，返回现有启动接口需要的 `port / credentials / close`。
3. 后台设备连接沿用现有 WSS 认证、TLS 校验和 Tunnel 握手；`openChannels()` 连接到这个适配端口。
4. Ubuntu 仍使用已有 SSH 配置和 `device-script`。本机适配端点将 exec 请求转为目标 SSH exec channel，将 SFTP 子系统通道转发到目标的 SFTP subsystem。
5. 原样传递 stdin、stdout、stderr、退出状态和通道结束，结果经既有路径返回 Ubuntu Claude。

两段 SSH 分别认证，本机在中间转换通道语义；不能把两条已加密会话直接拼接。适配端点只接受本次临时身份，只提供 exec 和 SFTP；不实现 Shell/PTY、Agent 转发、X11 或通用端口转发。所有 exec 都发往指定目标，适配器本身不调用本机 Shell 执行项目命令。

选择这一接法的理由：

| 选择 | 对现有工程的影响 | 本版决定 |
| --- | --- | --- |
| 在现有执行通道后接 ssh2 适配端点 | 保留 Tunnel、会话 SSH 配置、原生 Bash 工具与设备路由 | 采用 |
| 新建 exec/read/write RPC 系统 | 新增执行协议，并改变 Claude 使用工具的方式 | 不采用 |
| Ubuntu 直接认证目标，或转发目标 Agent | 改变目标凭据边界；目标也未必能从 Ubuntu 直达 | 不采用 |
| 在目标部署代理/完整服务端 | 增加目标设备安装、升级和维护 | 不采用 |

这是基于现有代码的最小改动选择，尚未通过实际集成证明。实施第一步必须先验证 exec/SFTP 接回 Tunnel；验证前不将 UI 和协议改造铺开。

### 4.2 两处明确复用，减少服务端改动

**远程会话创建：使用现有 `session.create`。** 当前 `server.ts` 按发送连接的 `deviceOf(peer)` 创建会话。由目标后台连接发送现有命令，即可创建属于该目标的会话，无需增加“选择任意设备创建会话”的新服务端命令。

主界面通过受限桌面 IPC 请求「为指定 SSH 配置及项目路径创建会话」，主进程完成路径验证并在该目标连接发送命令。成功后主界面通过现有客户端订阅该 sessionId；后续消息、审批、停止、侧聊和历史沿用现有跨设备处理。后台连接只处理自己需要的握手、状态与创建响应，不将它收到的全部事件再广播到主界面造成重复。

**脚本执行：在本机满足现有 POSIX 合约。** 当前 `device-script` 使用 `exec "$CC_DESK_TUNNEL_SHELL" -s`。本机适配端点转发 exec 时在目标命令的作用域内固定设置 `CC_DESK_TUNNEL_SHELL=/bin/bash`，再执行收到的命令；该固定前缀不产生 stdout，也不复制本机或 Ubuntu 环境。脚本继续从 stdin 输入。

这样无需新增服务端执行后端枚举，也不必更改 `tunnel.ts` 的脚本命令或 SSH 配置格式。目标环境以远端非交互 SSH 环境为准，不承诺等同交互终端；缺少工具时明确报告，用户在目标设备配置。

### 4.3 身份、认证与边界数据

SSH 配置属于当前桌面服务连接的本机 profile，创建时生成稳定 UUID，不进入跨窗口项目 shared 列表，也不云同步。保存显示名、地址、端口、用户名、认证方式、私钥路径、已确认指纹及项目路径列表；密码、口令和私钥内容不写配置。

渲染器通过配置 ID 操作已保存目标，主进程验证字段与当前服务连接归属；远端不能通过新 IPC 指定任意地址或索取密钥。错误沿用现有日志渠道，记录目标 ID、阶段和错误码；涉及会话时附 sessionId，不记录密码、口令、私钥或完整认证帧，保证故障可以定位。

每次目标连接复用当前已授权的 Ubuntu 节点。服务凭据模式按既有方式认证；邮箱/工作空间模式通过现有主进程 ticket 接口取得该后台连接需要的票据，沿用已有失效处理。不假设主窗口票据能重复使用，不新增管理中心签发协议。退出账号、切换工作空间或关闭当前服务连接时，一并关闭所属 SSH 后台连接。

目标设备通过主进程写入 `platform: 'linux'`，不能使用运行 CC SPACE 的 Windows 平台值。为了区分 SSH 项目与本机项目，仅在既有设备身份/Device 元数据中增加一个可选的 `viaSsh: true` 标记，并随现有会话元数据保存；无需新建目标关系数据库或存储表。标记只区分行为，不赋予额外权限。

此标记用于两处实际需要：远端提示不再指向本机定时任务文件；界面禁用尚未支持的本机文件入口。`remotePrompt()` 和原生 Claude 终端共用同一目标描述，保留 Ubuntu 运行方式。描述目标 Shell 为 Bash 非交互模式，不向 Claude 承诺本机环境变量或目标上的桌面调度文件存在。

## 5. 项目与运行生命周期

远程项目键为 `(deviceId, absolutePath)`。用户手动输入绝对路径，本机用目标 SFTP `realpath/stat` 验证目录，并保存返回路径。不能调用本机 `fs`、本机目录选择器或本机文件存在性检查。现有 `pathKey()` 已按路径形式保留 POSIX 大小写，直接沿用，不另写归一化器。

同一连接可记录多个项目路径；不是一个主机只能开发一个目录。点击连接行的「打开项目」显示已保存目录及「添加路径」，通过目标后台连接创建或进入对应会话。主界面复用现有“设备 → 项目 → 会话”分组。源会话的分叉和侧聊保留原设备身份，首版不新增跨设备迁移功能。

对远程会话的附件、文件链接、本机预览、Git 状态和项目菜单做集中目标判断：支持的操作继续使用既有协议，依赖本机文件系统而未适配的操作不显示或禁用。新建会话/终端的本机项目目录分支不能接受远程路径。已有“从来源会话创建 Ubuntu Claude 终端”可按原机制保留并验证目标提示；不新增普通 SSH Shell。

首次指纹需用户确认；已保存指纹不匹配时停止。显示名和项目列表可修改；已关联会话后，主机/端口/用户名或信任身份变更作为新连接添加，避免旧会话静默换设备，不增加跨主机身份迁移流程。

首版仅手动连接和手动重连，切换设置页面不会断开。状态只有未连接、连接中、SSH 已连接但开发通道未就绪、已连接、连接失败。认证或能力探测失败在对应阶段停止；不后台循环认证。

目标连接丢失时，关闭适配端点及后台连接，UI 显示失败；Ubuntu 端沿用原有离线处理。用户主动断开时沿用 `leave` 语义清理。删除先断开，只删除本机配置，不删除目标文件和 Ubuntu 会话。使用现有运行状态判断是否需提示中断，不另建一套任务状态追踪。

停止沿用现有提示：已发出的 SSH 命令可能继续执行，副作用未撤销，不能自动重试。适配器必须正确关闭通道，但首版不新增远端进程组管理，也不把通道关闭宣称为所有子进程已结束。重新连接后由用户或 Claude 查看实际状态，再决定继续操作。

「设置」侧栏的「客户端」分组，在「常规」后增加「连接」，支持搜索 SSH、主机、设备、密钥、远程。桌面入口不出现在浏览器端。当前常规设置中的多服务窗口管理保持原位置，避免与 SSH 目标混淆。

```text

来自此电脑的 SSH 连接                               [添加]

[开关] [图标] 测试机                                  [⋯]
```

无配置时在相同区域显示「尚未添加 SSH 连接」和添加入口，不增加一个只有空列表的“发现连接”弹窗。更多菜单只保留重命名、重连和删除。

点击「添加」直接打开紧凑表单：

| 字段 | 交互 |
| --- | --- |
| 显示名称 | 可选，空时使用 `用户名@主机名` |
| 主机名 | 域名或 IP，独立输入，不解析任意 SSH 命令 |

| SSH 端口 | 默认 22，范围 1–65535 |

底部「取消」「保存并连接」。认证失败保留已保存的非秘密配置，用户重连时输入秘密；同一认证提示组件承载首次连接和重连。首次主机指纹通过现有 Modal 确认。选择「打开项目」后用小表单输入绝对路径，例如 `/home/dev/project`，验证成功才创建会话。

开关表达连接意图，文字表达实际状态。「SSH 已连接 · 开发通道未就绪」时禁用打开项目并显示当前失败原因；不另加无用途的“连接成功”页面。

- `SidebarShell`、`side-action`、`page-title`、`page-heading` 与 `.setting-row`。
- 当前设置页采用平面行和 `--line-soft` 分隔；沿用 `.page .card` 的现有行为，不照搬截图的大圆角列表框。

## 7. 修改面与实施顺序

| 修改面 | 最少需要做的事 |
| --- | --- |
| `SettingsPage.tsx`、新 `SshConnectionsSettings.tsx`、局部 CSS | 连接列表、添加表单、项目路径输入 |
| `main.cjs`、`preload.cjs`、`desktop.d.ts` | 受限的 SSH 配置管理、连接状态和创建远程项目会话 IPC |
| 新 `electron/ssh-targets.mjs`（实现过大时再按职责拆文件） | 本机配置与指纹、ssh2 Client、临时 Server、目标后台连接的生命周期 |
| `proxy-bridge.mjs` | 一个私有的执行端点启动回调和主进程目标身份注入，默认仍是现有本机实现 |
| `packages/protocol/src/index.ts`、`server.ts` | 身份与 Device 元数据透传 `viaSsh`，会话创建与路由继续复用现有命令 |
| `claude.ts`、`device-terms.ts`、`native-terminal.ts` 的相关调用点 | 根据会话设备标记生成准确的目标说明，不修改模型配置或 SDK 启动位置 |
| 主界面项目入口与本机文件操作入口 | 订阅目标连接创建的会话，禁用未适配的远程文件操作 |

现有 `tunnel-channels.mjs`、`tunnel.ts`、数据库和项目路径规则优先原样使用。不得为了“将来扩展”新增执行模式枚举、通用连接框架、任意主机 RPC 或改写全局 `ProxyClient`；如果实测出现必须改动的接入点，再根据具体失败补最小修改并记录原因。

按依赖顺序执行：

1. **先做通道验证。** 在隔离 SSH 测试服务中验证适配端点、既有 Tunnel、exec/SFTP、POSIX 脚本合约与退出状态；不调用真实模型。确认接法后才扩展 UI。此验证代码用于核心集成测试，不再建设独立调试产品。
2. **接入身份与会话。** 让一个目标以独立设备上线，经该连接发送现有 `session.create`，从主界面订阅后发消息；核对平台、标记及断开行为。
3. **实现设置与项目入口。** 按本节确定的字段和现有样式落地；检查所有会接触本机文件系统的远程会话入口，仅处理本功能涉及的分支。
4. **完成核心验收。** 验证目标修改结果和 Ubuntu 模型出口，执行相关回归、构建及视觉检查。只在出现新改动或失败时重复对应检查。

## 8. 验收标准

| 核心路径 | 需要的证据 |
| --- | --- |
| 完整开发链路 | Ubuntu 发起脚本，经现有通道和本机适配层，在目标目录完成读、改、搜索及一次编译/测试；stdout、stderr、退出码、EOF 与背压正确 |
| 文件传输 | 真实 SSH 服务验证原始 SFTP 子系统衔接和现有 scp 调用方式；文件内容一致，不自研传输协议 |
| 目标准确性 | 两个目标有同名目录，本机也放哨兵文件，交替创建/继续会话时仅指定目标改变；现有本机开发仍可用 |
| 身份与断线 | 指纹变化拒绝；认证错误可定位；目标或 Ubuntu 断开不串设备、不自动重放；手动重连恢复原会话身份 |
| 网络边界 | 原有模型依赖检查通过；隔离联调用假模型端点和出站记录确认请求仅由 Ubuntu 发出，本机/目标无 Claude 进程或 provider 凭据 |
| UI 与旧功能 | 浅深色及窄窗口检查新增页面；相关设置、设备、会话、原生终端测试运行一次，确认操作入口不会将远程路径传给本机文件系统 |

## 10. 已授权的使用体验增量

用户要求引进值得借鉴的远程开发体验，并保持网络边界和最小改动。此次选取三项：

1. **继续最近项目/会话。** 连接行提供「继续上次」，项目对话框优先恢复该设备、该规范化目录下的已有会话，并保留「新建会话」。本机的会话 ID 仅作提示，必须在本次已认证服务连接的会话列表中匹配；删除、迁移或跨设备的同名目录不能误恢复。主界面恢复使用普通会话选择，不重新初始化默认模型或审批设置。
2. **分阶段连接诊断。** 显示 SSH 登录、Linux/Bash 环境、SFTP、Ubuntu 认证、开发通道等阶段。错误提示指出失败阶段及处理方向；日志只记录目标 ID、阶段和错误码，不回显认证异常中的原始秘密。失败、删除、断开和重连共用同一清理生命周期，避免迟到的失败状态复活旧连接。
3. **简单远程目录选择。** 通过本机到目标的 SFTP 列出当前目录中的文件夹，支持进入文件夹、返回上一级和手动输入路径。不展示或下载文件内容，不使用 Shell 拼接路径，不增加文件树、同步或远端代理。取消、改写路径或切换对话框后忽略迟到的目录结果。

增量只增加本机 IPC 与界面能力，复用现有服务端会话消息，不新增模型接口、provider 依赖或对外端口；协议继续使用当前源码的 24。SSH 配置导入、普通 Shell、端口转发和自动重连不进入此次增量。实际 Linux/Claude 联调仍需按第 8 节完成，不能以夹具结果替代。
