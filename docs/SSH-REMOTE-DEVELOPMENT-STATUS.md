# SSH 远程开发实施状态

2026-11-04（香港时间）。对应 [最小实施方案](SSH-REMOTE-DEVELOPMENT-DESIGN.md)。

## 当前结果

本地源码已接入「设置 → 连接」：手动添加 Linux SSH 设备、身份文件/密码认证、指纹确认、连接/断开、重命名/删除、填写并验证远程项目路径，以及通过现有会话命令创建目标设备的会话。按最新用户授权，已增加「继续上次」、按阶段显示连接进度与故障、简单远程目录选择。

本机维护目标 SSH 连接，临时适配端点将 Ubuntu 经既有 WSS/Tunnel 发来的 exec/SFTP 转发至目标。目标平台与 `viaSsh` 标记由主进程写入，并随原有设备/会话数据保存。分叉和编辑重发通过目标后台连接发送原有 `session.fork`，避免变成本机项目。聊天与原生 Claude 终端共用远程目标说明。

Claude、模型 SDK、登录凭据和模型出口仍归 Ubuntu，桌面没有新增模型运行依赖；目标设备也不安装或启动 Claude。SSH 密码/口令仅在连接期间使用，保存的是主机、身份文件路径、指纹和项目路径，不是私钥内容或账号令牌。

未增加 SSH 配置发现、普通 SSH Shell、Agent 集成、自动重连、端口转发、文件同步或常驻目标代理。目录选择只读取目标 SFTP 的文件夹元数据，不是完整文件管理器。SSH 会话暂不提供本机附件、Git 分支和本机文件预览；相关入口已限制，服务端也拒绝将 SSH 终端文件预览当作 Ubuntu 本机文件读取。

## 再次专项 review（2026-11-04）

本轮检查仅针对新增 SSH 功能及直接接入路径，修复四处问题：

1. **退出工作空间期间仍发起旧目标登录。** 复现为重连等待旧连接清理时退出工作空间，旧流程又成功认证了一次。现在清理结束立即重新校验服务对象和授权代次，在新认证前终止失效流程；认证返回后的指纹保存也须通过同一检查。回归先失败后通过。
2. **目标断线时迟到的桥接端点未关闭。** 故障注入将本机监听端口的启动返回延后，目标先断线，旧清理完成后工厂才返回；原逻辑遗留监听端口。现在异常收尾同时回收已完成阶段与迟到资源，回归先失败后通过。
3. **SSH 会话编辑重发入口被隐藏。** 原有 `away` 判断把目标设备当作不可编辑的普通异机；代码核对后，只有具有桌面 SSH 能力的 SSH 会话可以使用既有目标分叉路径，普通异机会话和浏览器仍保留原有限制。
4. **退出状态早于输出完成。** 复核时曾出现原生 SSH 测试的标准输出为空；增加诊断及提前退出状态夹具后，稳定复现退出码到达时 3.6 MB 标准输出尚未到达。适配器现等待目标通道关闭、两路读取完毕且输出写队列排空，再发送退出状态及结束标记；大输出、SFTP 和原生 SSH 调用测试通过。
