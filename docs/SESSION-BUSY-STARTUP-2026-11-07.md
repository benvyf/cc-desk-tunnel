# 启动时的“会话正在更新”提示

2026-11-07，香港时间。用户升级客户端和服务端后，打开客户端出现“会话正在更新，请稍后重试”；随后能加载已有对话，但红色提示仍保留。

## 语义与复现

该文本来自服务端 `session_busy` 会话互斥检查，不是安装包更新进度。`mutations` 是进程内集合，原生状态读取、改名、删除、分叉等操作期间使用；状态读取通过 finally 释放锁。客户端会在空闲会话展示时自动发起 `session.status`，同时也会在启动/重连/选择会话时加载历史。

已用受控的原生状态读取等待点和真实 WebSocket 复现：状态读取持锁时，`session.subscribe` 被误拒绝，返回与截图相同的提示。错误条保存最后一次失败，没有自动过期；用户能够读取历史，并不自动清除旧提示。界面右侧“关闭错误提示”按钮只清除本地错误，不删除会话或中断运行。

本轮未取得用户当次失败请求的服务端跟踪，因此不声称截图已证明具体是哪条 RPC；确认的是同文案来源、一条可复现的启动历史读取冲突，以及用户反馈的提示残留行为。

## 源码修复

仅对读取代理数据库的 `session.subscribe`、`session.history` 放行，不让它们启动或修改原生 CLI。改名、删除、配置、发送等写操作及并发原生状态读取仍保持互斥，不通过隐藏全部错误或自动重发有副作用的操作处理。

回归先确认旧实现失败，再验证缓存历史订阅/分页可用、改名/删除仍拒绝、并发读取不启动第二个 CLI。相关终端控制、历史及审核测试 12 项通过；服务端、浏览器权限、侧边会话与移动兼容回归 68 项通过，合计 80 项无失败/跳过；类型检查通过。CLI/PTY 边界为受控替身，无生产模型或额度请求。
