# Thinking accordion implementation plan

**Goal:** Apply the supplied three-dot wave and Grid 0fr/1fr accordion references to real thinking rows, with readable light/dark/system colours.

**Architecture:** Keep native details/summary semantics and the existing reader-controlled fold/search behavior. A focused ThinkingAccordion component owns its local fold state; CSS animates the native details content grid, retaining content only until its closing transition finishes. Closed history stays lazy; no hidden Markdown cache. WorkItems supplies a thinking stage's observed end (the next item/step or turn end), so only the trailing thought of an active turn animates. Use existing semantic colours and motion timing tokens; no dependencies or backend changes.

**Scope decisions:** Keep the existing standard/expanded work grouping and two-line closed preview. The active/ended labels are Chinese, matching the client. Do not estimate thinking duration: persisted fragment timestamps represent settlement, so subtracting adjacent event times would report changing, inaccurate durations. Screenshots are visual references, including their annotation text. Reduced motion removes waves and grid transitions. No automatic opening/closing on stream completion within an existing row.
