2026-11-05。针对 Build 13 清理构建缓存后仍缺约 45.7 MiB 的情况，用户要求尽量回收无用资源。扩展宿主机更新的自动清理，保留备份空间检查，不降低阈值。

## 清理与保留

在已通过节点/签名/基线/空闲校验且持有升级锁后：

- 执行 `apt-get clean` 回收下载的安装包，不执行 autoremove，不卸载软件。
- 执行 `docker builder prune --all --force` 回收构建缓存。
- 枚举所有运行及停止容器和升级回退记录，保留它们引用的镜像及目录。
- 仅删除名称符合 CC 候选规则、未被任何容器或回退记录引用、没有其他用途标签的旧候选镜像；不使用强制镜像删除或全局 system/image/volume prune。当前版本目标镜像保留，支持失败后重试复用。
- 仅回收升级根目录下旧 `buildN-随机名/program/` 解包文件；当前程序、容器挂载或回退记录引用的整个构建目录不动。策略、日志、冷备份和未知目录保留；路径或回退记录不正常则停止清理。

构建及离线预检后仍再次清理构建缓存并核对备份预算；只有确认空间足够及任务空闲后才断开客户端、备份并切换。若磁盘剩余的都是有用数据，脚本仍应停止并保留原服务，不能保证任意容量下都成功升级。
