# 新建 Ubuntu 一条命令部署

目标系统：空白 Ubuntu 24.04 LTS x64。建议 2 核、4 GB 内存，构建前至少 6 GiB 可用磁盘。Ubuntu 默认提供 Python 3；需要 sudo 权限和访问 Ubuntu 软件源、Docker Hub、nodejs.org、npm registry 及控制中心的网络。

## 使用

1. 打开控制中心“客户端更新”页的“新建 Ubuntu 一键部署”。
2. 输入唯一节点名，例如 `ubuntu-cc-2`，生成并复制命令。
3. 十分钟内在这台新 Ubuntu 的控制台执行。每台机器独立生成命令，不可把同一命令发给多台机器。下载及构建时显示进度，保持终端打开。
4. 等待 `6/6 SUCCESS`。在 Windows 客户端填写脚本显示的服务地址、证书指纹和服务凭据。再次查看：`sudo cat /var/lib/cc-fresh-install/connection.txt`。
5. 需要登录自己的 Claude 账号时，先退出所有 CC 连接，再自行执行 `sudo /usr/local/bin/cc-claude-login`，按官方 Claude Code 提示授权。程序安装不会自动登录、启动 Claude、测试会话或查询额度。

默认监听 `8787/TCP`，服务地址为 `wss://Ubuntu-IP:8787/ws`，沿用当前客户端的指纹验证方式。脚本列出 Ubuntu 本机 IPv4 地址，请使用 Windows 能访问的地址。已有的端口转发需要指向新虚拟机的 IP 和端口；脚本不修改 Windows、路由器或云防火墙的转发规则。

新节点后续通过客户端检查并确认服务端更新。控制中心原来的“首次接入”和终端“已接入服务端升级”仍仅针对已审查的首台 ubuntu-cc，不能用于新节点。Windows Build 7 和 Linux Build 3 无需重新发行。

## 安装与凭据

新入口与旧节点接入完全独立。管理 API 需要现有管理员认证及同源请求；安装码用 32 字节随机数生成，服务端只保存摘要，十分钟有效，只允许一次 HTTPS 兑换。重新生成同名、尚未兑换的命令会撤销旧码；已兑换的节点禁止再次签发，避免撤销已安装节点凭据。

兑换为每个新节点生成独立监控和审核凭据，分别认证、不可互用。注册表在控制中心 `private/fresh-nodes.json`，只保存凭据摘要和公开签名索引。静态节点与新注册节点在启动时合并，避免重启丢失监控记录。管理服务不修改 root 配置文件，也不为增加节点而重启。

Ubuntu 在 root 私有目录 `/var/lib/cc-fresh-install` 保存已兑换配置、日志和连接信息。依赖安装或构建中断后，保留该目录，重跑原命令使用本机缓存，不能重新使用安装码部署另一台机器。已完成安装会直接显示连接信息；不会重建或重置账号和会话。若在首次配置写入中途被强制中断，脚本可能因已有数据而拒绝继续；保留日志和目录定位，不要删除数据目录来重试。

程序归档在生成命令时固定为当前签名 Linux Build。Ubuntu 使用固定公钥和 OpenSSL 3 验证 Ed25519 签名、索引有效期及归档摘要，沿用固定摘要的旧安装器中的严格 USTAR、文件清单及就绪验证函数。旧安装器主流程不执行。固定 Node 24.21.0 和官方 Claude Code 2.1.295 下载包、原生文件均做摘要校验；新镜像不调用旧 `install-linux.sh` 的 Claude 版本执行命令，签名程序文件保持原样。

构建后先使用无网络、无账号挂载及 CLI sentinel 做离线监督程序检查，随后配置 `/data` 持久化和 root 管理的 `/etc/claude-code` 只读审核挂载。正式启动只检查本机健康及受管就绪，不发送 Claude/JEV 请求。官方账号授权由用户另行发起。

## 验证范围

核心 HTTP 测试覆盖认证、安装码撤销/过期/重复领取、独立凭据及监控重启持久性。Linux 隔离测试使用真实 OpenSSL 签名验真与篡改拒绝，模拟 apt/Docker 的完整安装流程，检查数据拒绝覆盖、配置权限和重复执行。真实浏览器测试覆盖生成、复制、过期、切换节点/退出清空及 390px 布局。运行包测试实际打包、解压并导入新增模块。

这些验证不等于空白 Ubuntu VM 的完整联网安装。首次新机部署仍需在用户新建的 Ubuntu 上验收依赖下载、镜像构建、网络可达及客户端连接；不得为验收运行真实 Claude 或模型请求。
