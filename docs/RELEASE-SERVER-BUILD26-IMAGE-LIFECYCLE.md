# Build 26：独立镜像构建与回退资源轮转

2026-11-16，香港时间。针对 ubuntu-cc 的磁盘占用及 Build 25 切换失败修复。源码实现完成；发行和真实设备安装分别以本轮实际验证记录为准。

## 镜像增长原因与约束

历史升级把运行中的服务镜像作为下一次构建的父层。重复复制运行时，以及复制后对整个运行时再次 chown，会将旧二进制保留在旧层中。旧回退容器和别名还会持续引用这些层。标签显示的镜像总大小不等于可以回收的独占空间。

Build 25 已开始使用固定摘要的干净 Ubuntu 基础镜像；26 固定构建入口，不再接受任意旧服务镜像作为父层。现行升级和新安装 v6 使用同一配方，运行时从 COPY 起即为 root 所有，不对运行时重复递归 chown。候选必须保留固定基础层、通过完整清单/CLI/PTY 校验，并小于等于 3 GiB；超预算在停机之前明确报错。实际体积取决于依赖，3 GiB 是本次审核的上限，不是承诺任意未来功能均不会增大。

默认升级准备和成功后的保留流程首先校验当前健康服务、唯一对应的上一套回退容器、冷备份及其摘要；原备份轮转确认更早归档已退役后，新增镜像资源轮转：只删除退役记录精确对应、已停止、名称属于本服务回退序列、持久目录与当前服务共用 /data 且无独立可写挂载的旧容器。不删除挂载目录、卷、账号、历史、项目、管理员策略或故障日志。

镜像只清理已知 CC 仓库/标签，保护所有剩余容器（包括停止容器）、未退役备份中的图像/快照引用、当前候选和自定义别名。每次删除前复查容器引用，生成独立审计；不使用全局 prune、强制删除或按时间删除。校验失败保留资源并打印 RETENTION_PENDING，不把健康服务误报为安装失败。

新方案保留“当前 + 必要上一套”的受管回退，连续成功升级会退役再上一代，避免每次新增一套永久镜像。第一次迁移仍必须保留旧的 7.49 GB 镜像作为回退；其层不能在必要回退期内释放。其他独立容器、手工自定义镜像和业务数据仍可能消耗空间，不承诺整个磁盘永久固定大小。

## Build 25 切换失败

用户日志为 install-cc-space-037.py:359。离线预检已验证新 CLI 2.1.325，但通用切换脚本仍把候选与旧 CLI 2.1.295 摘要比较。26 将已审核的目标摘要传入切换脚本，保留旧入口默认摘要、目标描述符校验及失败即停止的行为；失败输出包含真实校验错误。该失败发生在备份目录创建和服务暂停之前。

宿主机目标就绪检查也按签名运行身份验证对应的 CLI；预激活修复只接受原已审核的两种 host-operations.py 摘要，未知修改和已激活的平台仍拒绝改写。

首次安装器的恢复辅助脚本固定摘要同步到实际版本，并采用新的 fresh-install-v6.py 路径；v5 及更早公开文件保持原字节。中心仅对现行运行版本增加 v6 路由、命令入口与新文件，保留既有宿主机通道功能。Linux 26 保持 0.3.10 / 协议 24，镜像运行身份更新为 node24-cli2.1.325-v5，令旧 v4 进入正式镜像迁移而非绕过迁移的普通程序更新。底层依赖能力文件仍为 4，Node/CLI/SDK 二进制版本未再升级；v5 表示独立基础镜像及资源轮转这项新的镜像约束。已发布 25 不覆盖。
