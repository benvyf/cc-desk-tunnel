# 本地内嵌网页：代理通道

2026-10-25。用户已选择本地浏览器显示与操作、Ubuntu网络出口，以及管理员在客户端首次登录。完整设计见[选定方案](superpowers/specs/2026-10-25-local-browser-remote-egress-design.md)。已实现服务端、本机代理与客户端本地网页接线，尚未部署或连接真实Claude。旧蓝色画面包不用于新代理验收。

## 已实现的基础

复用CC现有TLS服务监听，新增独立v2路径；不增加公网监听端口，不读取或复制Ubuntu浏览器登录数据，不改现有Coding协议。网站TLS由本地浏览器与官网协商，代理转发原始连接，不解密网站内容或替换证书。

- `GET /cc-browser/v2/status`：需要服务Bearer凭据，返回schema2和enabled/reason，查询不解析或连接网站。
- `WSS /cc-browser/v2/connect`：首帧为JSON `{ "type": "connect", "token": "服务凭据", "host": "管理员允许的域名", "port": 443 }`；认证成功、域名/地址通过检查且TCP目标连接建立后，返回 `{ "type": "ready" }`，之后仅转发二进制。首帧及网站数据必须在验证过服务证书的TLS连接内传输。
- 域名由管理员通过`PROXY_BROWSER_PROXY_HOSTS`配置为逗号分隔的精确DNS名，最多64个不同域名；默认未配置即关闭。每个目标仅允许443端口；不支持任意端口、URL、IP字面量或通配符。
- DNS在服务端解析，所有答案都必须是允许的公共IPv4/IPv6；混合内网答案、保留地址、IPv4映射和IPv6转换地址均拒绝。拨号使用已验证的数字地址，不重新解析域名。IPv6策略保守限制在2000::/3公共单播并排除特殊范围。
- 认证5秒期限、DNS与拨号15秒期限；取消、超时、停止或维护期间不创建延迟到达的目标连接。最多64个WebSocket、每地址最多4个未认证连接，共享既有Throttle；单帧最多256KiB，使用流反压和自有通道心跳。
- 强制审核、维护、关闭状态拒绝目标拨号；活跃代理参与受管维护busy检查。旧v1画面通道保持历史兼容，新v2路径优先路由，旧通道不会吞掉新状态请求。

当前生产节点有强制审核，配置域名白名单也不会使网页准入开放。此步骤不解决审核覆盖，也不授权删除或放宽审核配置。不提供真实Claude域名的默认白名单，避免未经验证即开启真实网站访问。

## 验证边界

新增测试使用自有TCP/TLS回环服务。为验证生产地址策略，测试通过进程内显式依赖把“公共解析结果”映射至自有服务，并检查传给拨号器的目标已是验证过的数字地址。生产createProxyServer、环境配置和协议首帧均不接受这些替代依赖。没有连接公网测试IP、Claude或审核接口。

验证包括：地址/域名限制、认证和限流、无Origin要求、默认/审核/维护门禁、混合DNS答案、DNS等待中取消和超时、预就绪与文本帧拒绝、1MiB双向数据、目标结束时2MiB完整响应，以及完整CC TLS服务接线。自有站点证书在加密代理内保持原样，由其测试CA验证；不关闭站点TLS验证。

本机代理只监听随机127.0.0.1端口，使用每次随机Basic凭据，限制64条连接、8192字节HTTP头和64KiB就绪前数据；拒绝普通HTTP、Origin、IP和非443目标。主进程先验证固定CC服务的TLS，再发送服务凭据，收到ready后才响应CONNECT200。取消、超时、心跳失联和关闭会释放资源；正常EOF保留写缓冲，不自动重连或回退直连网站。凭据仅供主进程，renderer与官网均不接收它们。

专用持久session按CC服务身份分区，先设置固定代理并关闭旧连接，再创建无preload的sandbox WebContentsView。只允许HTTPS/WSS443网络资源，拒绝设备/媒体等权限、外部协议和webview。关闭后保留请求拒绝门禁，关闭视图、session连接及本机代理；不恢复DIRECT。禁用QUIC、DNS预取及非代理WebRTC UDP，WebRTC限制也应用到具体contents。正常网站TLS验证保持Electron默认行为，生产没有网站证书例外。

Chat/Coding切换隐藏/恢复同一视图，保留页面状态与Coding草稿；区域由主进程按窗口边界裁剪。登录维护按钮关闭视图，管理员按钮使用相同持久profile人工重开，不自动登录或发送消息。断开CC、加载失败或取消加载会清理视图与网络；并发打开使用generation与串行队列防止旧连接复活。

下载由同一session触发系统保存对话框，用户选择本地路径；不自动打开附件，关闭时取消未完成下载。普通新窗口链接在当前受控视图打开。需要POST弹窗或window.opener的登录流程尚不兼容；媒体/设备权限目前关闭，不能宣称官网全部功能可用。

本地测试覆盖指定Chromium路径，并不能代替实际Ubuntu两侧出网记录、真实网络DNS/IPv6及官网登录验证。下一步仅先用自有站点完成Ubuntu联调；生产审核准入未解决前，不发布真实Chat功能。

账号区隐藏将在本地浏览器正常嵌入之后单独验证：只应用用户要求的本地显示规则，不改官网业务请求，不把隐藏当作账号权限控制。必须依据实际页面结构验证，官网改版后需复核；当前尚未实现。

## 第三步细节复核

本轮复核确认并修复两项问题，均先用回归测试观察旧实现失败：

- 状态查询缺少取消信号：打开Chat时若服务端迟迟不返回状态，断开或退出会等待HTTP超时。现将控制器的AbortSignal传到实际HTTPS请求；真实客户端测试保持状态响应未完成，要求断开在2秒内结束，并确认挂起请求归零、视图隐藏。
- 下载保存对话框重复：异步手动保存对话框期间，DownloadItem仍未设置保存路径，Electron可能同时打开原生对话框；pause不能阻止该路径。现只同步设置原生保存选项，由Electron处理一次路径选择和取消。真实Electron测试验证未调用额外手动对话框、选项及文件内容正确，并确认收到数据且处于progressing状态的下载会在关闭时变为cancelled。

下载自动测试通过测试监听器同步选择路径，没有实际操作系统保存或取消弹窗。WebRTC另增加指定STUN/TURN域名及netLog检查，在700毫秒观测窗口内未进入本地HOST_RESOLVER；这不代表已穷尽所有DNS或网络路径。生产没有加入测试证书信任、测试拨号映射或自动登录行为。

复核后验证：全量Node共600项，565通过、35按既有条件跳过、0失败；真实Electron测试及4项UI回归通过；类型检查、格式检查、生产构建和stageDesktop暂存检查通过。独立只读复核未发现本轮两项修复新增的P1/P2。实际Ubuntu出口、生产审核准入、真实官网登录及账号区隐藏仍未验收；本轮未部署、发布或访问真实Claude。
