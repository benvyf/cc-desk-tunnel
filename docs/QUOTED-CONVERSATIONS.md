# 引用与侧边追问

回答操作栏的“引用”把整条回答加入当前会话的输入框；选中回答中的一段文字，可选择“添加到对话”，右键菜单也提供同样操作。引用以独立胶囊显示，展开可查看原文、逐条移除。原有草稿保留，写下问题并发送后，回答继续保存在原会话。

“侧栏问”或选区菜单的“在侧边聊天中提问”会创建一个新的侧边会话标签。有原生历史时，服务端通过官方 Claude Agent SDK 在已保存的消息边界创建独立分支，继承 Claude Code 原生上下文（包括其已有的压缩状态），不再把主对话界面记录整体编码为提示词。之后来源会话的新内容不会同步过去；生成中尚未保存的片段不承诺进入原生分支，划选的文字仍通过引用胶囊随问题发送。侧会话使用独立的模型、审批、运行状态与草稿，停止侧会话不会停止主会话。关闭标签不删除会话，仍可从会话列表打开。

生成中会选择最近一个工具记录完整的安全截点：等待审批、运行中的工具，以及只返回部分结果的并行工具批次都不复制；所有调用均取得结果（包括明确的错误结果）后才可保留该批次。未闭合工具之后即使已有新文字，也不会被误认作安全位置；孤立的思考片段或没有摘要的压缩标记不作为截点。必要时背景会回退到较早位置，选区仍随问题单独发送。不停止或改写主会话，不补造工具结果；没有可用安全截点时明确拒绝创建，请等待工具结束后重试。

回答运行时，可在焦点所在会话内，500 毫秒内独立按两次 Esc 停止当前回答，或点击“停止运行”。单次 Esc、长按重复、输入法、菜单/引用浮层、审批和终端中的按键不会触发该快捷键。切换焦点、会话或运行后需要重新连按；停止会保留草稿并暂停该会话的待发送队列。在设置的“快捷键”页可查看说明，关闭快捷键总开关后仍可点击停止按钮。

引用和创建标签都不会发送消息或启动模型。侧会话的第一条明确发送的问题才会恢复其独立原生分支，经原有远端 Claude Code 通道处理，并加入简短说明，要求只回答新问题、不要继续原来的任务。背景中的旧任务和审批不会转移为待执行操作。本机侧栏预览的文件、网页、截图和浏览状态不会自动回传，也不会成为 Claude 可调用的接口；原有远端经 SSH 执行开发命令的能力保持原样。

每条消息最多包含 8 条引用，重复内容按来源去重。问题、引用编码和附件合计遵循原有 16,000 字符消息限制，超限需缩短问题或引用。新的原生侧聊不受旧的 256,000 字符 JSON 快照预算限制，实际可用上下文仍由 Claude Code 的上下文管理和模型 token 窗口决定。分支已创建但原生记录丢失时明确报错，不会偷偷新建空白会话。

兼容边界：既有侧聊保留原来的冻结快照和首次发送/重试行为，不自动迁移。没有原生记录的新会话及离线模拟仍使用原来的有界快照路径，保留 256,000 字符上限；已登记原生上下文的来源如果记录不可读，分叉失败，不降级成界面快照。主会话处于原生终端或会话管理操作中时，需要等待操作结束再创建侧聊。

主会话引用兼容已有节点。侧会话入口要求客户端与节点都已支持侧聊协议；不支持的旧节点会禁用入口并提示更新，不会转为本机模型请求。未发送草稿和引用按会话保存；侧栏标签布局属于当前客户端，切换会话、重连和重启后可恢复。

功能参考 [dsh-harness-chat-control](https://github.com/1985899182/dsh-harness-chat-control)，沿用 CC SPACE 自有界面和远端会话实现，不依赖其 DSH 或 Better Sidebar 运行时。

2026-11-04 的原生侧聊改动参考 [DeepSeek Harness 的事件边界分支](https://github.com/deepseek-ai/deepseek-harness/blob/8bd073392eef6f54e921a093b95076248eb08cbb/packages/core/session/src/fork.ts)，通过 CC SPACE 已有的官方 SDK `getSessionMessages` / `forkSession(upToMessageId)` 实现，不新增依赖、协议或数据库表。代理库只保存分支标记与原消息边界，原生记录使用新会话 ID 独立保存；源会话删除不删除分支。历史复制仅在明确创建时发生，没有新增轮询或常驻监听。

安全截点选择复用来源的 SDK 历史读取，按工具 ID 配对扫描，不复制大段工具正文。SDK 展示历史可能重组并行工具块，而分叉按文件顺序截取，因此分叉后还需读取并检查独立副本；来源在异步复制期间变化而留下的不完整工具链也由此拦截。副本没有完整工具链时取消创建并尝试清理该副本，日志记录 `side_fork_unsafe_copy` 及会话/截点 ID，界面提示等待主对话完成当前回答后重试，不补造工具结果或自动重放。若底层清理失败，保留原始失败响应并记录 `side_fork_cleanup_failed`、副本 ID 和异常原因，可能残留的原生文件不会进入侧聊目录；来源会话的操作锁仍会释放。没有新增轮询或常驻监听。`sideConversation.throughSequence` 记录创建时观察到的代理事件游标，原生实际选中的来源消息 UUID 保存在 `side_context.snapshot.boundary`，两者不保证对应同一位置。

此改动需要更新服务端；客户端只有来源说明文字调整，旧客户端也能使用服务端的新创建路径。源码回归使用真实 SDK 的内存会话分叉/消息读取算法及模拟 query，覆盖超限历史、边界冻结、独立重试、丢失原生记录和失败清理，不调用真实模型。部署按用户确认的不回退旧服务端约束执行，保留会话库和原生记录备份。当前源码修改不代表节点已部署或安装包已发布。
