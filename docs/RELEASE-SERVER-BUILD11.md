# Linux 服务端 Build 11

协议保持 23，兼容已发布的 Windows v0.3.9 / Build 27。服务端程序的 appVersion 沿用 0.3.7，升级身份使用独立的 Linux Build 11；不重新发布客户端，也不覆盖 Build 10 归档。

包含侧边聊天的原生上下文分支、生成中工具调用的安全截点、独立首次发送及失败重试，以及终端并存时的额度读取和会话同步修复。服务端归档附带配套 Web 页面。

## 每台 Ubuntu 的升级入口

控制中心现有宿主机更新通道读取新的签名发布后，在 `ubuntu-cc`、`ubuntu-cc-02`、`ubuntu-cc-03` 的服务端更新面板显示“更新到 Build 11”。发布不创建升级任务；由用户逐台确认。任务、待处理审批或原生终端未结束时拒绝切换。

本次修改存储、原生调用和协议数据结构的兼容摘要，旧 Build 10 的 supervisor 会拒绝直接热替换。签名归档中的 `deploy/host-update/apply.py` 供已接入的宿主机 agent 调用，不需要重新接入；它只接受已核对的 Build 10 descriptor、协议 23、Node 24.22.2、原锁文件及未经修改的官方 CLI。这里的镜像迁移用于安装新的程序和 supervisor，不更换 Node 或 CLI。

迁移复用现行控制中心已验证的签名/解包、策略保留、冷备份、空闲检查和离线回退实现；相关支持脚本随签名归档携带。基于当前镜像构建候选，离线预检后才进入停服、冷备份和切换；原容器、原镜像及账号/配置/聊天数据保留。已有未完成的备份或切换记录会阻止新迁移。失败时沿用原回退流程和备份目录中的回退命令，不自动重放升级。

## 验证

- Node 24 针对性回归：42 通过、1 项 Linux 专用测试在 Windows 跳过；涵盖侧聊、终端、归档、supervisor 和发布。
- TypeScript 检查通过。
- VPS Linux 隔离测试目录：20 项 Python 测试通过，包括三台节点的迁移入口模拟、仅准备不安装、签名/忙碌/镜像层/离线预检失败阻止切换，以及现有策略迁移测试。Docker 操作为模拟，不表示三台生产机器已升级。

发布时只替换 Linux 签名索引及其精确续期登记，保留 Windows 发布、控制中心运行程序、节点接入和历史任务。
