# 客户端本地聊天记录

本功能保存客户端能够通过现有连接读取的聊天展示记录，并在本机优先显示已保存副本。Claude CLI、SDK、模型凭据和模型请求仍在 Ubuntu；不会把 Ubuntu 上的账号目录搬到客户端。

## 使用

- 桌面客户端侧栏的“本地聊天记录”可查看、导出、导入或删除本机副本。登录页也有离线入口：需要这台电脑已记住的 CC Space 登录身份；退出并清除登录后，需要重新登录同一账号才能从界面读取它的归档。
- 连接支持此功能的服务端后，按分页后台同步全部可见会话；以后核对锚点并增量补齐。连接旧服务端时，本机仅保存已读取的页，会明确提示需要配套更新，不发送不受支持的新命令。
- “完整快照”指聊天展示事件已同步到最近确认的服务端游标，并非每个正在生成的字符都已落盘。请结合最近保存时间、后台同步状态和附件检查结果判断；未同步完成的内容不构成完整备份。
- Ubuntu 丢失会话、返回空列表或删除服务端会话，不自动删除本地归档。服务端恢复旧数据导致游标冲突时，保留旧版本，另建本地版本。删除本地副本不影响 Ubuntu；服务端仍有该会话时，后续在线同步可能重新保存它。
- 导出为 `.cc-history.jsonl`。小归档使用现有系统保存对话框；较大归档走本机下载，界面提示核对默认下载目录。文件包含聊天事件、附件副本或缺失说明、格式/计数结束标记。导入验证格式、会话、事件顺序和计数；截断或无效文件会拒绝并清理本次暂存，不覆盖已有记录。导入来源单独保存，只读，不进入在线同步或原生续聊。

## 附件与完整性

工具输出中已经内嵌的图片随聊天事件保存。引用附件只自动复制当前执行设备上明确引用的普通文件，单个不超过 20 MiB；从归档查看图片时只使用保存的副本，不再尝试读取当前磁盘同名路径。

来自其他设备/SSH 目标的附件、原文件已丢失、超过大小限制或敏感配置，显示未保存原因，不冒充完整备份。敏感目录、私钥和认证配置内容不自动归档。用户自己在消息或工具输出中写入的敏感内容仍属于聊天正文，会随记录保留，不能把此功能视为秘密脱敏工具。

## 数据和网络边界

数据保存在当前客户端用户数据目录的 IndexedDB（`cc-space-chat-history-v1`）。客户端只向受信任应用主窗口的主 frame 授予 persistent-storage 本地持久存储权限；其他来源及其他权限仍拒绝。若系统未授予防自动回收保护，界面提示导出重要归档。多连接沿用现有独立 profile；每份记录再按 CC 登录用户、服务端工作空间/地址/指纹和会话隔离。登录身份由主进程提供，切换或失效时关闭旧归档和同步器；延迟的旧连接结果不能把归档绑定到新登录。

这是应用级隔离，不是针对同一操作系统账户的加密保险箱。聊天和导出文件可能含代码及隐私；清除客户端用户数据或站点数据会删除本地数据库，客户端更新应继续保留既有用户数据目录。重要归档应另外保存到独立可靠介质；同盘副本无法防护该盘本身故障。

后台使用既有、经认证的 WebSocket，只增加协商后的 `session.archive` 只读分页请求。此接口读取服务端代理数据库，不启动 CLI、不创建运行、不提交审核/模型消息、不改变聊天订阅；浏览器端不开放本机归档同步。查看本地记录本身不需要 Ubuntu，模型新请求仍须经过 Ubuntu。

缓存恢复在在线历史核对前标记为本机副本，不能释放排队发送。归档视图关闭发送、审批及工具控制，导入/查看不会重放旧工具或消息。写入空间不足、连接中断或同步失败会显示未完成状态；客户端日志只记录失败操作、服务器摘要标识和错误类型，不打印聊天、凭据或附件内容。

## 与 Claude 原生恢复的区别

本次保存的是代理展示事件和可获得的附件，**不是原生 Claude 会话的 JSONL、自动记忆、配置或项目文件恢复包**。Ubuntu 重置后可以阅读已保存的聊天，但仅靠这些记录不能保证原样恢复 CLI 上下文。没有把普通聊天文字伪装成原生 resume，也没有提供自动上传归档/恢复工具执行的入口。

官方[数据使用说明](https://code.claude.com/docs/en/data-usage.md)明确描述 Claude Code 本地保存会话；本设计保留本地副本的目的与此一致。[法律与认证要求](https://code.claude.com/docs/en/legal-and-compliance.md)对第三方产品的认证方式另有要求，本功能不改变现有认证、不绕过限制，也不据此证明整个部署已获授权。

## 协议与发行

`ready.localHistory.version=1` 为可选能力，协议仍为 24。新客户端只有收到能力才请求 `session.archive`；新服务端对旧客户端正常工作。完整自动同步需要配套的新客户端/服务端；没有能力时仅保存已读取内容。正式发行必须使用新 Build 并遵守[更新与发布规则](UPDATE-RELEASE-RULES.md)，不能重发已公开的 Windows 32 / Linux 20。
