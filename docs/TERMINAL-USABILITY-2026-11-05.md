## 保留的改动

| 优先级 | 改动 | 实际效果与边界 |
| --- | --- | --- |
| 高 | 连接与 Claude 工作状态分开显示 | 区分连接中、重连中、已连接但执行通道未就绪，以及运行、等待确认/回答、等待输入。工作状态只读当前终端对应的既有 `activeRun.activity`；缺少数据时显示待同步，不推测为空闲。没有新增 `/status` 查询或后台模型调用。 |
| 高 | 终端内查找 | 使用 xterm 官方 addon-search 0.16.0，首次查找才加载实例；字面匹配、忽略大小写、前后定位，Enter/Shift+Enter 与 Escape 仅在查找区生效，不抢占 CLI 的 Ctrl+F 等快捷键。支持 ANSI 后的可见文字、中文、软换行、独立标签、已结束/离线缓冲。 |
| 中 | 普通滚动缓冲阅读保护与提示 | 复用原 xterm 阅读位置保护，上翻时新输出不拉回底部；显示“有新输出 · 回到底部”，由用户明确返回。切换标签保留位置和提示。进程结束先于最后绘制回调时，仍标记末尾新输出，ACK 继续按原生命周期约束处理。 |
| 中 | 断线恢复说明 | 明确接回原终端且未重发输入；原进程结束时明确提示，不静默创建替代进程。执行通道未就绪时等待既有设备状态，首次连接建立后采用新的连接身份再启动，不主动轮询 CLI。该项与高优先级状态反馈共用原生命周期，一起实现并单独验证。 |

### 查找与滚动的范围

查找只针对 **当前 xterm 活动缓冲**，不扫描会话数据库、服务端文件或 Claude 自身历史。普通缓冲沿用原有最多 2,000 行滚动保留设置；官方 CLI 进入 alternate screen 时，查找只能覆盖该屏幕当前内容，CLI 自己的历史滚动继续由 CLI 处理，不能宣称可以搜索全部对话或接管其内部滚动。

回到底部提示针对 xterm 实际可滚动的缓冲。交替屏幕没有普通滚动历史时不显示这个按钮；通过录制的 Claude 2.1.295 交替屏幕验证了这一点。没有为模拟这种能力而解析不稳定的 CLI 屏幕标记、自动发送按键或改变官方 CLI 设置。

查找栏使用独立一行：窄窗不会遮住首行匹配内容。仅选择当前匹配，不启用额外 proposed decoration API，不与预测插件争用开关。查找文字和导航按键不进入 PTY 输入；CLI 已启用的正常焦点协议帧仍保留，不把它们误当成用户提示词。

关闭查找会清理组合输入标志、恢复终端焦点；再次点击已打开的查找入口会重新聚焦查找框。标签各自保留查询，不保存至磁盘或服务器。

### 后续标题栏外观调整

按用户后续要求，服务端状态、Claude 状态和现有搜索入口合并到标题栏右侧（系统窗口按钮左侧），取消单独的文字状态行。状态以服务器、机器人/运行/等待等图标呈现，颜色辅助区分；悬停提示和可访问名称保留完整说明。只有当前标签的控件显示在标题栏，复用该终端的原状态与搜索处理，没有重复订阅或新增查询。

6 项相关状态、就绪、重连、查找、标签与真实 Electron 场景通过；另在真实 Electron 的 1,000px 和 480px 窗口检查标题栏范围、搜索聚焦以及整个调整仅启动一个终端。TypeScript、客户端构建和模型边界检查通过。预览与机器可读记录保存在 `.local/terminal-title-icons-*`、`.local/terminal-title-preview.json` 及证据 JSON 的 `titlebarRefinement`；没有调用真实 Claude，未打包发布。

用户再次要求 review 后，针对同一份标题栏源码完成增量检查：真实 Electron 中两个终端分别报告运行/等待，切换标签只有当前状态可见；当前标签结束并关闭后，图标恢复显示剩余终端状态，没有遗留控件或额外启动进程。检查搜索仍能聚焦、减少动态效果时运行图标停止动画、状态控件为 `no-drag`，并复核 1,000px/480px 边界均在 40px 标题栏内部。核对了聊天停止快捷键的 DOM 范围和终端活动禁用条件，以及标题栏双击仅作用于空白区的限制，未为假想故障改写旧快捷键逻辑。未发现新的需修复阻断问题，本轮仅追加记录；原 6 项回归及构建结果不冒充再次全量运行。原始结果为 `.local/terminal-title-review.json`，仍使用模拟服务，没有调用真实 Claude。

## 试测后未引入的候选

### WebGL：本机没有稳定收益

将官方 addon-webgl 0.19.0 下载到忽略的 `.local` 隔离实验目录，未加入产品依赖。使用真实 Electron 独立窗口、同一 xterm 实例、相同 100×35 重绘负载，预热后交替测试三轮，每轮 60 个样本。

| 轮次 | 默认渲染 P95 | WebGL P95 |
| --- | --- | --- |
| 1 | 7.8ms | 8.1ms |
| 2 | 7.6ms | 8.1ms |
| 3 | 7.7ms | 8.5ms |

这里测量“写入解析到下一次 animation-frame 机会”的时间，不是精确像素呈现或 GPU fence 耗时。Electron 报告 WebGL 启用；没有据此推断其他驱动/显卡的表现。隔离试验还验证预测覆盖层撤下、主动 dispose 后默认渲染与预测继续可用；未将此扩大为完整 context-loss 或物理 DPI 验收。

当前负载没有稳定改善，产品不引入 WebGL，也不新增 GPU 设置、回退框架或运行时重试。

### 2ms 输出合并：降低等待，但增加碎片消息

在隔离源码副本中将收集窗口从 5ms 改为 2ms，通过受控 spawner 比较三种负载。未修改实际服务端源码，也没有启动 Claude。

| 负载 | 2ms 候选 | 保留的 5ms |
| --- | --- | --- |
| 20 次间隔输出 | 20 帧；交付 P95 4.57ms | 20 帧；P95 6.96ms |
| 20 组密集输出，共 400 次写入 | 20 帧；P95 3.99ms | 20 帧；P95 7.49ms |
| 每组分散写入，共 400 次 | 200 帧；P95 3.08ms | 122 帧；P95 6.16ms |

候选能减少几毫秒交付等待，但分散重绘的消息数增加约 64%。这不是用户可感知跟手改善的证据；预测回显本来就不等待此窗口。故保留 5ms，不增加按输入猜测输出类型的规则或自适应参数。Windows 计时包含调度抖动，数值不是硬实时承诺。

## 验证结果

- 模型边界、预测核心、窗口与受管更新相关 Node 测试 **120/120 通过**；工作区模型运行依赖/导入检查通过。
- 终端、预测、工作区和 Electron 组合组首轮 **80 项中 79 通过、1 项失败**：新增状态栏与原标题重复显示退出信息。修正为固定身份标题、单一状态展示后，退出场景针对性通过；未把初轮记录改写成一次全绿。
- 后续 15 项组合场景通过；再补查找键盘/组合输入细节，14 项使用体验场景通过。查找栏改为独立一行后，中文、导航、窄窗、标签、组合输入和真实 Electron 等 6 项针对性复测通过。
- 新增发现均先复现失败再修正：按钮上的 Enter 不应被当成输入框“下一个”；组合输入中关闭查找不应锁住下次查找；再次点击已打开的查找入口应重新聚焦。最新增量结果及分次范围见 [机器可读证据](evidence/terminal-usability-2026-11-05.json)，不累加重叠用例冒充唯一测试总数。
- 录制 CLI 的交替屏幕可查找当前文字；不显示并不存在的普通滚动历史操作。普通缓冲的新输出、后台标签阅读位置，以及结束前最后一帧提示均有对应场景。
- 最新生命周期验证：迟到启动回复仍仅关闭对应原进程，退出状态可正常关闭，2/2 通过。新增展示状态遵守 disposed 与连接代次检查，不改变原 ACK 与输入分段。
- 本轮组合测试中的 100 次预测输入：模拟回声 200ms，DOM 显示 P95 约 0.5ms，最大约 1.4ms。不是物理像素延迟，也不代表网络 RTT 下降。原始 latency JSON 保留在 `.local/terminal-usability-final-ui/`。
- TypeScript、客户端生产构建、格式与 diff 检查通过；新的 MIT 许可文件在构建产物 `third-party/xterm-addon-search.txt` 中。原有分包/动态导入提示没有扩展为无关重构。

测试均使用模拟服务、临时数据、受控输出和已录制的 CLI 画面；**没有调用真实 Claude、执行账号登录、查询真实额度、读取生产凭据或改变生产代理**。真实 Electron 只用于本机渲染和键盘验证。浏览器组合事件不等于 Windows 物理中文输入法人工验收，也未声称测试过所有显卡或物理显示器。
