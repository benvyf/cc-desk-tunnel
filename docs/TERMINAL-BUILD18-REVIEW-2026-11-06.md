## 发现与处理

1. **P1：通用发布工具仍可能写错运行级别。** Build 18 的实际发布/续期已固定到正确干净源码，因此现有签名索引正常；但 `releaseFromArchive` 仍取工具自身 `RUNTIME_LEVEL`。用工具 v3 处理声明 v2 的真实格式归档，会把发布字段错误改为 v3。已先复现失败，改为从完整验签/清单校验后的归档内 `deploy/managed-server.json` 读取运行级别，同时检查其 Build 与描述符一致。旧基础镜像命令所需常量保留，不改变历史分支。
2. **P2：管理中心公开的首次安装脚本未支持当前 v3 运行级别。** 签名包内的宿主机升级入口已支持，但中心公开入口仍是旧脚本，不能据此声称首次安装链路完整。新增不可原位改写的 `fresh-install-v3.py`，新接入命令固定下载这个 URL 并验证该文件摘要；旧 `/fresh-install.py` 内容及摘要保持。已有旧命令不会被偷偷替换，需要新接入时重新生成命令。

这两项修复限定在管理中心和发布工具，不修改已发布 Build 18 归档或 Windows Build 31 安装包，不需要为相同制品伪造新 Build。
