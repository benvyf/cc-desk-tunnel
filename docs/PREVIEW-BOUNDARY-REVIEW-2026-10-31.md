# 预览与 Claude 接口边界再次复核

基线 `bb79d40`，范围为新增侧栏及其客户端 IPC、文档读取、页面导航和模型消息接线。两份独立只读审查加上实际 Electron 反向验证。

## 结论及范围

没有发现新增侧栏向 Claude 注册工具、转发预览 API、注入文件/目录正文或自动生成消息/附件的路径。预览数据留在客户端状态和专用 IPC；聊天发送仍从用户草稿和显式附件生成。独立网页没有 preload、Node 或 window.desktop。

用户最终明确的验收口径是：**CC SPACE 的 Claude 模型/API 请求仅由远端服务发起；侧栏不向 Claude 提供工具或访问 API，不自动回传预览内容。** 既有本机开发脚本的依赖下载、联网测试等功能保留。

实际主线为：客户端会话控制 → 既有 WSS 服务 → 远端 apps/server 中的 Claude SDK query() → 模型服务。正式客户端不打包或运行 Claude SDK，不新增本地模型 API 调用或连接失败后的本地模型兜底。

已有 SSH 设备脚本通道属于项目开发执行能力，本轮没有把它改成系统级断网环境。这里的“仅远端出口”限定于 CC SPACE 驱动的模型/API 调用，不作为所有本机脚本绝对断网的声明。

## 本轮修正

1. IPC 不再仅凭 file:// 放行：必须是当前主窗口的 webContents、主 frame、准确的应用入口文件；异常/销毁/其他 frame 一律拒绝。同步 boot 和 proxy:disconnect 采用同一规则。
2. 工作区目录打开的 Markdown 标签，后续文件链接保留原 root/restricted 限制，不自动扩大读取范围。普通聊天链接和用户文件选择的既有显式打开行为保留。
3. 异步文件导航加入每个标签的版本记录；隐藏、重新显示、切换、关闭和较新导航会使旧结果失效，防止隐藏后再次显示时补开旧标签。

## 证据

- 对消息发送、附件生成、服务器 Claude SDK 与协议接线进行只读追踪，没有新增模型侧预览接口。
- 单元测试拒绝其他 webContents、子 frame、其他本地文件、相似文件名、网站、失效/销毁 frame。
- 真实 Electron 测试专门创建无关本地页面并给它同一份 preload，确认 boot 为 null，文件读取、目录列举和 disconnect 调用均得到 Untrusted renderer；受信任主界面正常读取目录。
- 真实目录内 Markdown → 范围外文档点击被拒绝；原有用户手动选择项目外文件仍正常展示和刷新。
- 实际网页继续验证 typeof window.desktop/require 均为 undefined、跨源回环探针未收到静态预览请求；测试流程没有 message.send。
- 重启恢复、缺失文件恢复、PDF/Office、多窗格、终端和关闭清理继续通过完整 Electron 链路。
- 桌面回归 301 项：247 通过、54 按条件跳过、0 失败。UI 回归 25 项；类型、构建、格式和仓库检查通过。

验证环境 Windows x64 / Node 24 / Electron 44；没有向真实模型发送测试请求，没有修改或部署既有 SSH 通道的网络策略，没有发布安装包。


## 远端模型主线的构建约束

`scripts/model-boundary.mjs` 已接入 `npm run check`、客户端 prebuild 和安装包暂存入口：客户端清单禁止声明 Claude/模型 SDK、CLI 或服务端运行包（包括 npm 别名）；客户端 src/electron 禁止导入相应模型 SDK 和 apps/server 运行入口；现有升级功能使用的纯类型契约继续允许，不会引入服务端运行代码。导入分析复用 TypeScript 语法树，支持静态/动态 import、require 和重导出，避免把文案中的代码示例误判成真实导入。远端服务的 SDK 依赖正常保留，本机 PDF/Office 渲染依赖正常保留。

新增回归明确拒绝侧栏直接打开、资源请求或地址跳转到模型 API 目标。测试只使用目标字符串与本机夹具，不向真实模型发请求。该检查用于防止架构回退，不代替操作系统网络沙箱。

构建和打包还检查当前工作区文件，因此未暂存的模型 SDK 导入也会阻止构建；仓库检查继续校验 Git 索引中的提交内容。

静态门禁覆盖上述依赖与可识别导入，不声称可以分析任意动态脚本、字符串计算或所有原始 HTTP 调用；当前调用主线由代码追踪和已有运行验证确认。

本轮追加验证：15 项边界专项通过；客户端 prebuild、生产构建和类型检查通过。未修改模型服务地址、远端代理配置或既有 SSH 开发执行策略。
