## 保留规则

- 保留的是与**当前健康安装的 containerId/imageId 对应的上一套完整回退**，不是按时间戳选最新文件。必须验证原容器/镜像、冷备份 SHA256 和 rollback/helper 文件；缺失或不明确时不删除。
- 默认在升级锁内、旧服务基线/空闲检查通过后，尝试退役更早的历史冷备份大归档，保留当前必要回退；Build 14/15 精确已知基线适用。原有 APT/构建缓存和无引用资源清理、空间检查继续执行。
- 新版本切换、健康检查、原生服务状态检查并记录 installed 后，再以新安装身份选择新回退，退役原来保留但现已被替代的更早数据归档。安装失败不执行安装后的轮转；原有必要回退保留。
- 只退役固定历史目录中的 data.tar/data.tar.gz/old-image.tar/source-config.tar，保留日志、记录和退役标记。所有容器挂载覆盖的目录继续保护；不删容器、镜像、数据卷、项目、账号或会话，也不关闭审核或调用 Claude。
- 回退验证或退役未完成时记录 `RETENTION_PENDING`，保留必要回退，不能把已健康切换的服务误报成需要重放的失败安装。可能仍有多份未能安全退役的归档，需按日志核实；不以“必须只剩一份”为由强删。

该自动流程保留在源码中供后续发行沿用。单独手工维护命令仍限制 ubuntu-cc；签名升级入口仅对原有审核 01/02/03 传入各自容器，未扩大节点范围。Build 15 已发行代码不会自动得到这项行为。
