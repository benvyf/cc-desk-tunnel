## 1. 目标与交付边界

在一个独立终端窗口内支持多个标签。每个标签对应独立 CC 会话和官方 Claude Code 进程。顶部合并标签栏与窗口控制，不额外显示“CC SPACE · 原生终端”标题行；保留系统任务栏中的窗口名称以便识别。

采用已讨论的 CC 风格：中性色界面、陶土色选中标记、现有小尺寸按钮、深色原生终端输出区。项目目录和节点置于简洁底栏。终端输出按原样显示，不解析其内容以猜测“正在思考”“任务完成”或执行成功。

本期包含新建、切换、标签别名、全部终端列表、单独关闭、窗口关闭确认、自然退出、断线结束和必要错误归属。不包含分屏、标签拖出、多窗口进程托管、断线续接、输出云端存档、账号池、自动换号、增加订阅额度或自行复制项目。已有 worktree 可以作为不同项目目录选择，不自动创建或删除。

原型仅用于确定界面与交互，不是程序实现或合规证明。原型内文本均为示例；不得把原型的本地状态、按键或关闭逻辑直接复制为生产逻辑。

## 2. 合规结论的准确边界

**多开本身不是已发现的违规点，整个部署尚未取得“全面合规”的结论。** 官方文档介绍并行 Claude Code / worktree 会话；同时对第三方集成、订阅认证、托管、账号共享和使用范围另有要求。必须同时满足相关条件，不能只引用“支持并行”一句话。

用户此前说明本人自用、使用自己的账号，见既有 [合规审查](CLAUDE-COMPLIANCE-REVIEW-2026-10-24.md)。管理中心存在多个邮箱并不能证明实际有多个使用者，也不能证明各人已获得 Anthropic 授权。发布前应确认当前实际使用关系，不能仅凭历史描述推断全部节点的身份与权限。

本方案把“符合当前适用规则”列为发布前置条件，不承诺零风控、永久符合未来政策或替代 Anthropic 对具体许可的解释。没有书面证据的许可事项不得标记为已获准。

本方案中“必须”也包含为实现用户合规目标而制定的工程约束，不全是 Anthropic 条款原文。例如去除自动写引导标志、首版不恢复进程，是本项目选择的保守边界，不据此认定所有采用其他实现的程序已经违规。官方原文、代码事实和项目决策必须分开记录。

### 2.2 必须执行的合规约束

- 官方 CLI 必须来自可核验分发，保持原样，不打补丁、不改认证/限额判断、不伪装官方客户端身份，不伪造 User-Agent、OAuth client、账号或授权。

- 原生 PTY 通道会承载 CLI 的输入输出，其中可能包含登录链接或用户粘贴的授权码；不能把“没有专门的凭据 API”描述成“CC 完全不经手认证字节”。首版优先在 Ubuntu 的官方终端完成登录；不在 CC 自定义界面开发嵌入式订阅登录。若用户在原生 CLI 内自行登录，相关显示/输入只经必要的已认证加密通道传输，不额外解析、提取、记录或上报；也不拦截、禁用官方内置认证方法。托管场景仍须满足官方条件，透明转发不是整体获准的证明。
- 多个终端可以属于同一位合法使用者；不得让多个实际使用者共用同一人的个人订阅。多个独立授权用户的隔离部署需要另行设计，不能只靠新建 CC 邮箱或更换 sessionId。
- 不轮换账号/节点/出口来规避额度、并发限制、地区要求、封禁或付款。限额出现后保留官方提示，由用户选择官方支持的处理方式；不自动重发模型请求。

## 4. 标签、项目与状态模型

每个标签至少维护：本地稳定 tabId、CC sessionId、获得后的 terminalId、所属连接代次、设备/项目标识、可选标签别名、生命周期、局部错误和退出原因。不要把账号凭据放进此模型。

生命周期采用 `creating → opening → running → closing → ended`，另有可恢复的创建/启动失败。连接断开后单独标注 `disconnected`；启动/关闭超时为“结果尚未确认”，不能直接当作“服务端已失败/已关闭”。单个标签出错不改变其他标签生命周期。

- 主客户端“打开终端”针对当前 CC 会话：已有所属终端时唤回对应标签；其他连接占用则提示，不能夺取。
- 标签栏 `+` 明确创建新的独立会话，默认沿用当前标签的项目/设备和已明确的配置；没有当前标签时选择项目，不能悄悄改到服务器目录。
- 不调用会自动 `show()`、更换选中会话、刷新 SDK 状态的现有创建 helper 而忽略其副作用。新建流程先确定项目与设置，再只创建一次会话，成功后再打开终端。
- 新建会话/打开终端沿用 requestId 机制，但不得声称无限期幂等：当前 `peer.responses` 是每连接有数量上限的响应缓存，而创建会话另有持久化 requestId。短时同请求查询/重发仅在对应缓存或持久化记录可确认时使用；换连接、缓存淘汰后不得盲目重放 open。
- 创建成功而启动失败时保留该会话与失败标签，重试复用会话；不自动删除其数据。结果未知先查询第 7 节的终端状态，不改 requestId 直接再启动；已明确失败且终端不存在时，新的启动尝试用新的 open requestId，避免反复取回已缓存的失败响应。不能为解决一个标签的未知状态就断开连接杀掉其他标签。
- 新标签默认是新对话；不自动恢复旧 transcript、复用官方会话 ID 或 fork 上下文。显示目录分别注明项目目标与 CLI 实际工作区，不能声称运行在未验证的路径。
- “标签重命名”仅改 CC 客户端别名，不调用受运行锁约束的 `session.rename`，不改官方会话或工程目录。第一版别名在当前终端工作区有效；不承诺重启恢复运行中的进程。
- 独立进程不隔离项目文件；同目录并行可能冲突。项目选择处提供简短说明；不每次启动弹警告。需要文件隔离时让用户选择现有 worktree。

### 4.1 新标签的创建契约（实现时必须落实）

现有 `session.create` 使用 `deviceOf(peer)`，且成功后清空 `peer.subscriptions` 并切到新会话；`server.session.create` 会新建服务器目录。这两者都不能不加处理地用于“沿用当前标签的任意设备/项目”。客户端不调用 `show()` 也无法消除服务端订阅副作用。

采用一个职责明确的新请求，建议名称 `terminal.session.create`，与旧接口分开，避免改变旧聊天创建行为。字段为 requestId、title、来源二选一，以及明确的 permissionMode/model/effort：

- `sourceSessionId`：从当前可访问 CC 会话继承设备和项目，由服务端从记录解析，校验该节点的访问范围与执行目标；不接收可伪造的任意 deviceId、不复制对话上下文。服务器项目也用此方式沿用原目录。
- `projectPath`：仅用于当前已认证桌面设备已有授权范围内的新项目选择；不把别的设备路径冒充本机路径。本期没有来源会话时不提供“任意远端设备新目录”功能。
- 两种来源互斥；请求不改 `peer.subscriptions`，不改变主窗选中会话，不触发状态/模型读取。响应复用标准 requestId 结果并返回 sessionId；`terminal.open` 仍是下一步独立操作。
- 在创建持久化会话前校验完整来源与模型/权限字段，将所选设置和创建结果作为一个本地数据库事务保存，成功后才允许 open。现有 `Store.create()` 默认 `permissionMode: auto`，因此不能先按默认启动，再异步应用较严格模式；初始化失败禁止启动，返回可追溯错误。
- 创建请求幂等需覆盖来源、设备、项目及所选设置；同 requestId 不同内容返回冲突。来源项目在重试间发生移动/删除时按已保存结果或明确冲突处理，不重新解释来源后又创建第二个会话；不只依赖有界的连接响应缓存。
- `sourceSessionId` 只继承项目归属与已确认配置，不能作为跨用户授权；配置变化也不能借此绕过该会话/节点本来的限制。

此处新增协议和少量创建处理是为消除已确认副作用，不另造项目数据库、进程调度平台或新的模型调用层。具体命名可按仓库约定调整，但契约与验收不能省略。

## 5. 客户端终端实例与后台输出

- 标签切换保留 xterm 和输入/输出监听，使用稳定 key、稳定回调；不因为父组件渲染、菜单开关、重命名或主题切换卸载终端。检查 effect 的 `onClose` 依赖，禁止变化触发关闭进程。
- 非当前标签停止接收键盘焦点和输入，但继续处理其输出、流量确认与退出事件。现有服务端达到 128 KiB 未确认数据后暂停、30 秒未恢复则关闭，不能靠扩大超时掩盖问题。
- 明确后台渲染/写入回调能推进；保持 Electron `backgroundThrottling: false` 并验证最小化场景。不要在隐藏标签尺寸为 0 时 `fit()` 或向 PTY 发送最小尺寸；激活后再 fit、resize、focus。
- 保持每终端有界 scrollback（现有 2000 行可作为首版基线）、独立待确认字节数和定时器。自然结束后停止控制发送；保留已渲染输出直到用户关闭标签。
- 不为保留输出增加后台 transcript 抓取或服务器永久存档；诊断默认不收集原始终端文本。新建/切换标签不调用模型/额度查询。
- 所有窗口事件、监听、动画帧、定时器随其实际所有者释放；关闭一个标签不销毁整个 Portal 或其他标签。
- 本机输出保留只保证当前窗口仍在且对应数据已收到；断网期间未接收内容、客户端崩溃、重启后的内容不保证恢复。
- 同项目的 CC 会话可能共享 `nativeRoot`、`.claude` 项目设置和 CLI 自身的记忆/配置；不同标签不等于配置沙箱。不为多开复制凭据文件，也不让多个标签并发改写共享账号/设置来实现“每标签换号”。账号退出/换号与全局设置变更需等待相关活跃终端结束，不能只看当前标签。

## 6. 关闭、断线与窗口控制

| 动作 | 必须行为 |
| --- | --- |
| 关闭运行标签 | 明确确认会结束该终端进程；确认后禁用其输入、停止 resize/ack，发送一次 close，收到结果后移除 |
| 自然退出 | 标记已结束，保留输出/退出码；清理过期的关闭错误。非零退出说明原因，不标成正常退出 |
| 未知退出原因 | `exitCode: null` 显示“退出原因未知”；ack 超时、网络失联、被关闭等使用服务端已知原因，不把无退出码写成 0，也不从终端文本猜测 |
| 关闭已结束标签 | 直接移除，不再发送终端关闭命令，不删除历史文件 |
| 关闭失败 | 保留标签、显示局部错误；只有确认进程仍活跃时恢复输入和控制，允许重试 |
| 关闭中先收到 exited | 安静收尾，不展示迟到的 inactive 红字；不能据此吞掉其他终端错误 |
| 关闭窗口 / Alt+F4 / 主窗“关闭全部” | 经同一个协调流程；有运行/启动中/结果未知的终端先确认，逐个收尾，汇总失败；只有成功收尾或明确退出策略成立后才销毁窗口 |
| 主客户端主动退出、注销或切换工作空间 | 同样提示对所有终端的影响；不把原连接的标签带到新节点。不可取消的系统关机/崩溃靠服务端断线清理，不能承诺弹窗总能出现 |
| 最小化/隐藏/切换标签 | 不断开 WebSocket、不关闭任何进程；主窗“显示终端”恢复最近标签 |
| 网络断开/认证失效 | 禁止继续输入，标明连接中断。服务端检测到断开后清理该连接所属终端；检测存在延迟，不承诺断开瞬间所有远端任务立刻停止 |

本期不自动重放输入或恢复进程；不得对用户说“已回滚文件”。Linux 进程组清理沿用现有实现并验证；SSH 上远程衍生任务不一定随本地 PTY 消失，应明确边界，对本功能实际启动的可追踪任务核验清理，不能 kill 全用户进程、全部 ssh 或其他标签。

Electron 合并标题栏时核对无边框窗口的拖动区域、按钮/标签 no-drag 区、双击空白最大化、缩放、窗口边缘调整尺寸、最小尺寸（现有 480×300）、任务栏与多显示器。320px 原型预览通过不代表要把真实窗口最小尺寸降到 320px。

子窗口继续 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。若用自定义窗口按钮，增加仅对该子窗口生效的窄 IPC：最小化、最大化/还原、请求关闭、状态通知；验证发送者和所属窗口，不继承整个 desktop bridge、凭据接口、任意文件/命令执行权限。程序化关闭与用户关闭需可区分，防止确认递归或绕过。

## 7. 服务端与协议

- 保留 `sessionId + terminalId + owner connection` 校验，所有新标签都经已有认证和项目/设备定位；旧连接的 ID 不能操作重连后的进程，其他 CC 登录身份不能通过猜 ID 接管。
- 保留每会话互斥与节点容量；申请名额在异步启动前完成，启动失败、自然退出、断线、主动关闭最终都释放。不存在先创建成功却永久占名额的路径。
- control 错误携带 sessionId/terminalId（建议两个都带），或使用明确的终端错误消息。客户端将其写入对应标签，不再用一个全局 ended 布尔值处理所有终端。未归属错误不得任意吞掉；认证和协议错误继续在连接层处理。
- 新增只读 `terminal.state` 请求（requestId、sessionId、已知时带 terminalId），只查询调用连接拥有的终端；最小响应包含该 sessionId 的 `opening/running/closing/absent` 和获准返回的 terminalId，不读取 CLI transcript、不启动 CLI、不查询模型。其他连接拥有时只报告不可操作，不提供接管能力。`absent` 仅表示当前没有该进程，不伪造退出码或证明过去的任务没有执行。
- 每次需要新的状态观测时使用新的 state requestId；重复旧 ID 只表示重取那次查询的结果，不能拿缓存快照判断当前状态。只在操作结果未知时做少量有界查询，不加长期高频轮询；state 查询本身不申请容量、不改变订阅。
- 状态请求用于 open/close 超时的结果确认：running 且身份/输出流完整时继续同一实例，opening/closing 等待已有操作，absent 才按已知结果决定新尝试。丢失 `terminal.opened` 时可由状态拿回本连接 terminalId；重连不继承旧 owner，也不续接旧输出。该只读请求需允许在本连接终端 opening/closing 时查询，不能被普通会话 busy 判断挡住，但仍必须验证认证、来源和所有权。
- `terminal.state` 不是输出重放接口。客户端先注册终端生命周期监听再发送 open；若启动身份尚未确认但已收到 data，可按当前待启动 sessionId 暂存有界帧（不得超过背压允许范围），确认 terminalId 后才交给相应实例。若输出确已缺失，不能猜测字节数补 ack 或声称完整恢复；只对这个终端执行可确认的关闭，并让用户决定是否新开，不重放旧输入。若状态仍无法区分在途操作，先修正状态原子性，不增加模型/进程探测。
- 终端结束消息可增加有限的 `reason` 枚举，例如用户关闭、进程退出、输出确认超时；只传服务器已知事实。进程退出先于查询时查询可返回 absent，客户端保留已收到的真实 closed 信息，不反向覆盖为成功或未知码。
- 普通 `terminal.close` 保持 requestId 响应；不要新增会误伤其他连接的“关闭所有终端”后端快捷接口，客户端可按确切 IDs 收尾，服务端断线清理兜底。
- 容量以节点实际内存和 `PROXY_MAX_RUNS` 为准。对约 2GB 节点先采用保守管理员配置并以模拟高输出/资源观测验证，不能把每进程 300MB 估算当上限保证；核对 Docker 限额，不仅看宿主机总内存。已结束标签不占进程名额。
- 若 UI 展示总名额/剩余名额，必须由服务端能力/状态提供，不在客户端硬编码，且预检不等于预留；首版可仅显示准确的容量拒绝原因。
- 受管审核程序、配置、账号挂载和 SSH 目标沿用已核验的隔离边界。sessionId 只隔离路由，不构成不同用户之间的凭据或文件权限隔离。
- 不新增 Claude 请求代理、token 中转、账号调度或模型重试。官方 CLI 直接处理自己的模型认证和通信；CC 只传输终端控制/显示数据，现有审核链路另行明确其数据用途。

协议能力须由服务端初始握手显式公布专用的终端工作区能力版本（建议 `terminalWorkspace.version = 1`），代表新建契约、状态确认、错误归属及退出信息均已实现。不要复用“模型能力列表”来表示此功能。没有能力声明或版本不匹配时仅允许已支持的单终端模式，并给出升级说明。新请求在旧服务端会被 strict schema 拒绝，客户端不能靠尝试未知请求来探测是否支持。

## 8. 与现有 CC 功能协调

- `terminalSessionId` 的全部调用点按“运行中/启动中终端集合”替换，分别核对导航、模型配置、项目移动、删除、状态刷新、更新、断开、窗口展示，不能只替换变量名。
- 主窗打开/唤回终端应允许正常工作；本期可以保留打开终端时主聊天输入的既有禁用行为，不顺带扩大并发聊天范围。独立终端的新建不受该 UI 全局禁用误伤。
- 节点级原生状态读取目前与任意终端互斥；有任何活跃或启动中终端时继续跳过，不只检查当前标签。最后一个活跃终端结束才允许合法模式下的延后读取；该读取若涉及未获准 SDK/订阅组合，须按第 2 节停用/替换。
- 保留防重复的同步读取标识，处理读取期间新建、切换节点、失败恢复，不重新引入“会话正在更新”。已有 ended 标签不应永远阻止刷新与升级。
- 服务端升级忙碌可能来自进程、认证连接或后台任务；关闭终端后仍需满足原升级流程的断开与清理条件。UI 说明原因，不能承诺关闭标签后立即可升级。
- 本方案不把已有 quota、账号监控、计划任务、聊天功能都认定合规；核对它们是否触发 SDK/订阅路径、采集数据或主动请求，按第 2 节记录处理结果。

## 9. UI 细则

- `+` 默认同项目新终端；旁边下拉提供完整列表、选项目新建、当前标签别名与关闭；标签多时优先保留当前标签，其他从列表可达，不挤掉新建/窗口按钮。
- 标签显示运行/结束状态，但运行仅代表进程仍存在，不代表正在推理；不能靠终端文本推测并发任务完成。长名省略并可查看完整名称，状态不能只靠颜色区分。
- 自然结束采用中性状态与退出原因，提供“新开同项目终端”，它创建新会话而非假装恢复旧进程。连接断开与用户正常结束使用不同文案。
- 关闭确认明确单个或全部范围，默认焦点在取消；焦点留在弹窗内，Escape 取消，关闭后回到合理控件。批量关闭部分失败时列出未关闭标签，不能显示全部成功。
- 使用现有颜色、字号、圆角、Button/IconButton 和图标，不另造设计体系；外壳跟随 CC 主题，ANSI 输出画布继续深色。不把未执行的模型/CLI版本检测作为绘制 UI 的前提。
- Ctrl+Shift+T 新建、Ctrl+Tab 切换、Ctrl+Shift+W 关闭作为候选；先核验 Electron/系统/Claude Code 冲突后启用。输入焦点、中文输入、文本选择、复制粘贴与长文本粘贴均保持终端语义。Ctrl+C 传给当前 CLI，不被窗口截获。
- 快捷键入口可发现，键盘/触屏可操作；最小窗口、放大字号、DPI、浅深色下无重叠，菜单/确认框不被输出区遮挡。窗口拖动不能吃掉标签点击。

## 10. 数据、日志与历史

终端输出可能包含源码、个人信息和官方登录链接。默认仅留在终端显示缓冲，不发给管理中心或写入新增诊断日志。沿用 CLI 自己的历史机制并说明其存在，不能声称“绝不落盘”。

诊断只记录必要的时间、阶段、脱敏节点/设备标识、sessionId/terminalId/requestId、退出码与错误码；身份关联标识同样按访问控制保护。不记录按键、完整输出、提示词、OAuth URL/授权码、token、Cookie、密码、SSH 私钥或含密钥环境。日志采用现有有界保留机制，不另造遥测系统。

终端文本及远端返回的标题/错误均视为不可信输入：经 xterm 或纯文本控件显示，不拼接 HTML，不让控制序列或链接触发新增的任意 IPC、自动浏览器打开或剪贴板写入。新建的错误消息采用可控模板与错误码，不把可能含凭据的原始异常/CLI 输出抄进日志。保留用户明确的复制、粘贴与打开合法链接操作，不修改官方认证页面或其参数。

已有 JEV/关键词审核有独立输入数据流，必须如实说明并沿用现有授权、权限、留存和故障阻断；不能把原生终端转发说成“所有文本仅在本机”。未经允许不导出原始输出供排查。

## 11. 核心验收矩阵

优先模拟 PTY、模拟审核、合成协议帧，不带生产账号或数据，不连接真实 Anthropic/provider。测试聚焦本次多终端关键路径，不追求穷尽无关旧模块。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| C1 | 多标签 A/B 输入与输出 | 各自 IDs、缓冲、错误、输入、ack 不串线；输入只到当前标签 |
| C2 | 连续切换、重命名、菜单、主题变化 | 已有进程 PID/实例保持不变，没有重复 open/close |
| C3 | 后台持续输出超过 128KiB、最小化超过 30s | 正确确认/背压，无意外杀进程、无无限缓冲；显示后尺寸与内容正常 |
| C4 | 单个关闭、自然退出、结束后关闭 | 只影响目标；正常收尾无过期红字，非零退出可追溯 |
| C5 | 关闭失败、超时、先退出后返回、批量部分失败 | 真实错误归属正确；state 确认 opening/running/closing/absent；丢失 opened/response、缓存淘汰后仍无重复启动；null 退出码不变成 0 |
| C6 | 多次新建、启动中关闭、创建成功启动失败 | 同创建请求复用持久化会话，冲突内容拒绝；新尝试不被旧失败缓存锁住；无泄漏进程/名额 |
| C7 | 他人/旧连接发送控制、伪造 IPC 发送者 | 拒绝且不影响目标合法终端；无窗口/账号权限扩张 |
| C8 | 断线、注销、换节点、关主窗、Alt+F4 | 确认与清理范围正确；不静默重放输入、不假恢复；所有权重置 |
| C9 | 不同项目/设备、SSH离线、同会话重复打开 | sourceSessionId 正确解析当前/其他在线设备及服务器项目；拒绝越权来源；创建不改主窗订阅/选中，配置成功后才启动；默认 auto 不先于严格配置生效 |
| C10 | 达容量与释放后重试 | 不超配、不开额外 CLI；释放后可用，其他终端继续运行 |
| C11 | 状态读取竞争与升级 | 活跃终端保护有效、最后结束后不残留锁；不绕过升级 busy |
| C12 | 旧/新客户端×旧/新服务端 | 握手终端工作区版本明确，无声明不发新请求；不将缺少错误 ID 当已支持；明确退化/版本提示，无死连接或重复进程 |
| C13 | 窗口、焦点、文本与布局 | 480×300、常用尺寸、DPI/大字号、主题、长标签/菜单、输入法与快捷键通过 |
| C14 | 合规数据与授权路径 | 新建/切换无自动 prompt/SDK 查询；CC 启动辅助代码不读取 token/自行标记引导完成（官方 CLI 的正常读取保留）；模拟登录敏感字节不进额外日志/上报；不可信输出不触发 IPC/自动剪贴板；受管 hook 生效 |

模拟验证不能证明真实部署合规或节点清理全部正确。生产验收前先完成合规门槛；仅在用户明确授权后做最小真实 CLI 检查，说明可能涉及正常官方网络/费用，不自动发送测试提示词。不要为了验证限额主动耗尽额度或触发保护。
