# 本地聊天记录实施与验收

2026-11-07，香港时间。按用户指定的 karpathy-guidelines 完成客户端持久归档与配套只读同步能力，源提交 `f22b591`、`293f5db`。功能说明与限制见[本地聊天记录](LOCAL-CHAT-HISTORY.md)。本轮没有发布安装包或部署节点。

## 实施结果

- 客户端用户目录中的 IndexedDB 持久保存展示事件、保存范围及附件副本；历史先用本地已保存页显示，在线核对完成前标记为本机副本，不触发排队消息发送。
- 只读同步按分页补齐全部可见会话，后续先核对锚点再增量。后台同步不占用现有聊天订阅，不启动 SDK/CLI，不调用模型。Ubuntu 空列表、会话删除或恢复旧数据库不会清掉本地归档；冲突时保留旧版本。
- 本机用户身份只由主进程提供，不把票据或模型凭据写入归档上下文。账号切换/失效时停止旧同步和视图；延迟连接结果及旧 socket 关闭不会覆盖新身份的归档。
- 引用附件仅复制可获得的当前设备文件；20 MiB 上限、敏感路径/内容和网络共享排除。缺失保留原因；查看归档不读取当前磁盘同名图片。不把聊天正文中的敏感内容自动脱敏，也不声称归档一定不含用户自己贴出的秘密。
- 登录页和侧栏提供只读查看、分页、导出/导入、删除。导入独立命名，不成为在线缓存或原生会话；严格验证格式、顺序、会话及结束计数，拒绝截断文件并清除本次暂存。
- 只给受信应用主 frame 持久存储权限，保持其他权限拒绝；授权失败会提示导出。保存/同步失败在界面显示未完成，日志只记录操作、服务端摘要标识和错误类型。

没有添加依赖或把官方运行时搬到本机；Ubuntu 的原生会话文件、账号认证、审核和模型请求路径保持。新增协议 24 可选能力 `localHistory.version=1`，旧客户端可连接新服务端；新客户端连接旧服务端不发送不支持的归档命令，只保存已加载页。

浏览器用真实 IndexedDB 验证重载后保留、不同用户/服务器隔离、重复去重、服务端回退时旧版本不被新尾部污染、锚点后增量分页、配额错误不标完成、删除服务端记录保留副本、JSONL 往返与拒绝截断、只读视图不发指令或访问当前附件路径，以及 390px 无横向溢出。另覆盖登录前离线阅读和换账号关闭旧视图。已查看窄屏截图。

CLI/PTY、身份和传输故障用受控替身；没有生产模型/额度请求。首次兼容测试中旧登录夹具把缺失 SSH API 模拟成了普通函数，已明确为 undefined；新功能对真实接口函数做能力检测，最终兼容用例通过。

独立 QA 客户端位于 `.local/local-history-package-qa/`，使用提交后的源码和原有打包入口/更新控制器，单独临时 profile，未使用用户日常 profile，也未生成安装器、签名索引或修改公开制品。它只是 QA 产物，不是新的 Windows Build 发行。[结构化证据](evidence/local-chat-history-2026-11-07.json)记录测试范围和日志。
