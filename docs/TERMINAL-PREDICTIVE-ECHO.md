# 终端输入预测

在“设置 → 常规”打开“终端输入预测（实验性）”，可以减少远程原生终端打字时等待字符出现的感觉。默认关闭，设置只保存在本机，并沿用现有窗口间的偏好同步。

按键仍立即发送给远端。客户端先显示预测字符，真实回显到达后撤下预测层；显示错配或超时时清空，以远端画面为准。开关可以在终端运行中调整，关闭会立即撤下预测，不重新启动远端进程。

## 支持范围

当前针对 Linux 上的官方 Claude Code 2.1.295 验证，支持其手动审批模式下、已识别的普通单行输入区末尾追加字符。可预测 ASCII、常用汉字和部分中文标点，以及输入法提交的短文本；候选窗口和组字交给原有输入法与 xterm 处理。

下列情况保留普通远端回显：菜单、登录/审批等未识别界面，行中和多行编辑、粘贴、复杂 emoji 或组合字符、距右边缘不足、以及待确认字符过多。即时退格只删除尚未确认的预测文字，已经回显的文字由远端删除。

切换焦点、弹窗、滚动、改字号/主题、窗口尺寸变化及连接结束会清空预测。控制键后先等待真实输入区变化；无法确认编辑结果时，随后第一个字符可能仍需要等待远端回显。连续预测达到限制或出现渲染异常时也会回退。若出现不适合当前终端的闪烁，可以关闭开关继续使用。

它只改善符合条件的输入显示，菜单计算、命令执行和模型回答依然取决于远端和网络。

## 实现与维护

使用锁定的 xterm 6.0.0 和 xterm-zerolag-input 0.4.2。插件需要该终端实例的 proposed API 和私有字符尺寸回退；开启时临时开放，关闭时恢复。升级 xterm 或官方 CLI 时应重新验证。

识别依据是底部编辑框的双边界、提示符、实际反色光标、光标右侧空白及已验证的模式栏；允许符合这些条件的备用屏幕。不会以模型名、套餐名或项目目录识别输入区，也不扫描回答历史。未知形状不画预测。

输入来源通过 xterm 的公开 onKey 及实际 composition/paste 事件判断。预测模块不发送网络消息；唯一发送路径仍是 NativeTerminal 的原有分片循环。不会为回滚重发输入。预测层独立于真实终端 buffer、选区和历史。

中文组合事件和异步提交已有浏览器集成测试，包括通过 Chromium 输入接口触发的原生组合事件链路；这不能替代 Windows 物理输入法及其候选选择方式的人工验收。当前实验性范围不代表所有 CLI 版本、主题和终端界面都已覆盖。

## 验证

测试夹具保存了使用假 API key、容器内部模拟接口采集的 Linux 2.1.295 输入与输出片段；不包含真实账号、请求内容或模型系统提示词。两个目标采样分别验证了受管钩子阻断时的画面、隔离无钩子环境下的英文及中文提交与回答。

Node 测试覆盖输入来源、编辑屏障、迟到回显、宽度与容量、异常降级及释放。Playwright 使用真实 xterm 和产品组件，覆盖延迟回显、ANSI 分片、回答后继续输入、组合提交、粘贴、开关和发送一致性；另有真实 Electron 独立窗口验证。

100 次合格 ASCII 输入的性能测试测量键盘事件到预测 DOM 插入的时间，并保持模拟远端回声延迟 200ms。这是客户端 DOM 指标，不代表所有电脑上的实际像素绘制或真实网络延迟。

在源码根目录使用 Node 24 执行：

```powershell
node --test apps/desktop/test-main/terminal-prediction.test.ts
npm run test:ui -- apps/desktop/test/terminal-predictive-echo.spec.ts apps/desktop/test/terminal-window.spec.ts apps/desktop/test/settings-pages.spec.ts
npm run typecheck
```

测试不会调用真实模型。插件完整 MIT 许可随客户端分发在 `third-party/xterm-zerolag-input.txt`，仓库副本见 [许可文件](../apps/desktop/public/third-party/xterm-zerolag-input.txt)。

## 本次验证记录（2026-11-03）

本机使用 Node 24.22.1、Chrome 和 Electron 44.5.1；Linux 记录由用户在相同服务端镜像的一次性容器中采集，CLI 为 2.1.295。独立审核先复现了退格迟到回显、开关期间在途输入及原生事件微任务顺序问题，再加入回归并修复。

| 检查 | 结果 |
| --- | --- |
| 预测核心 Node 测试 | 36/36 通过 |
| 终端、设置和真实 Electron 界面回归 | 53 个用例均有通过结果；整组 52 通过，另 1 个遇到 Vite preamble 开发预加载异常，单独重跑通过 |
| 全量 Node 测试，串行运行 | 787 项：726 通过、60 条件跳过、1 个既有失败 |

| 客户端与服务端 Web 构建 | 均包含预测代码及与原包逐字节一致的完整 MIT 许可 |
| 100 次合格输入、模拟回声 200ms | 预测 DOM 插入耗时 P95 约 0.3ms，最大约 0.8ms；已保存预测出现、真实回声尚未返回时的截图 |

全量测试的既有失败位于 `packages/protocol/test/protocol.test.ts`：“upstream version history and managed build history describe their respective releases”。原因是发布历史的 windowsBuilds 不包含当前受管客户端 build；修改前已复现。此次没有为通过该断言改动发布版本或历史记录。

物理 Windows 输入法候选界面、其他 CLI 版本及 macOS/Linux 客户端未做本次实机验收。源码交付保持默认关闭；发布安装包和远端部署属于后续交付流程。
