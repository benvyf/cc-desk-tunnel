# 终端输入预测

在“设置 → 常规”打开“终端输入预测（实验性）”，可以减少远端终端打字时等待字符出现的感觉。默认关闭，偏好只保存在本机，并沿用现有窗口间同步。运行中开关立即生效，不重启远端进程。

按键仍立即通过原路径发送。客户端显示独立预测层，真实回显到达后撤下；超时、错配或无法确认时，以远端画面为准。预测不会写入真实终端 buffer、选区、剪贴板或会话历史，也不会为回滚重发输入。

## 支持范围

当前验证对象为 Linux 上官方 Claude Code 2.1.295 的手动审批模式，支持已识别的普通单行输入区末尾追加 ASCII、常用汉字、部分中文标点，以及输入法提交的短文本。候选窗口和组字继续交给原有输入法与 xterm。即时退格只删除尚未确认的预测，已经回显的文字由远端删除。

菜单、登录/审批等未知画面、行中和多行编辑、粘贴、复杂 emoji 或组合字符、距右边缘不足及待确认字符过多时，保留普通远端回显。切换焦点、弹窗、滚动、字号/主题、尺寸或连接状态会清空预测。

控制编辑和历史召回后，只有真实画面足以排除旧输入位置时才恢复预测。改变后的完整输入区先于继续打字到达时，可以立即恢复；用户提前连续输入、无变化的控制操作或重复/周期性文字可能需要更多回显，不能承诺固定等一个字符就恢复。背景重绘不会单独解除这种歧义。

超出单行跟踪范围、不受支持的批量命令/多行粘贴、恢复队列超限或出现无法解释的输入区变化时，本终端继续普通远端显示。若要恢复预测，需要新建终端；开关往返、Enter 或单纯重新打开原终端窗口不会擦除未确认状态。输入发送和真实回显继续可用。

该功能只改善符合条件的输入显示。菜单计算、命令执行和模型回答仍取决于远端与网络。

## 恢复规则与维护

使用锁定的 xterm 6.0.0 和 xterm-zerolag-input 0.4.2。插件需要该终端实例的 proposed API 和字符尺寸回退；开启时临时开放，关闭时恢复。升级 xterm 或官方 CLI 后应重新验证。

识别只依据底部输入区的双边界、提示符、实际反色光标、右侧空白和已验证的模式栏，不扫描回答历史，不依赖模型名、套餐名或项目目录。恢复签名不含屏幕行号，但每次仍检查当前底部行位置，支持窗口高度变化后的确认。

键盘、IME 和粘贴来源沿用 xterm 公开 onKey 与实际 composition/paste 事件。输入发送仍由 NativeTerminal 的原分片循环负责。插件正常拒画只暂停预测，初始化/绘制异常会隔离降级，不阻断原发送路径。

已确认来自粘贴入口的空括号粘贴按“未编辑文本”处理：原标记仍走原发送路径，不新增编辑记录，已有在途输入保护保留。没有粘贴来源的相同字节继续按未知数据处理，不能绕过保守暂停。

已知编辑按发送时记录的完整目标恢复，独立于插件 TTL 和当前画面，避免超时后重复拼接已经回显的文字。未知编辑使用一个有界候选对象：保存可能已处理到的输入位置、最近完整画面与后续编辑；新画面保留所有仍成立的位置，只有全部候选都到达最新输入后才解除暂停。追加、退格和 Enter 使用既有语义，Ctrl+U/W、历史等仍按未知编辑处理，不实现另一套编辑器。

例如 ↑ 召回 `ab` 的期间输入 `b`，收到 `ab` 时，“只完成召回”和“已经处理新 b”都可能成立，不能立即预测下一字符。后缀匹配只用于保留一种可能解释，不再直接充当确认依据；后续完整回显排除旧位置后才恢复。

候选队列最多保留 400 个编辑和 401 个位置，并删除所有候选之前的已消费前缀。已知旧画面的排除最多保留 65 个完整签名，超限保守折叠为最多 400 个列号。容量超限时保留不确定性，不清空历史假装确认，也不销毁健康插件。无法描述为普通文字或单个控制操作的批量数据保持普通回显。

这是对客户端画面的保守核验，没有 Mosh 协议的服务端按键序号确认，不能严格证明任意 CLI、控制序列或编辑历史的远端语义。

2026-11-03 的修复已将历史文本重合、重复中英文、重复背景帧、部分 IME 回显和非括号粘贴宏加入正式回归。曾失败的“召回 ab、提前输入 b、收到召回画面后输入 c”现在保持暂停，收到可确认完整目标后恢复。细节复核另修复空剪贴板被误当作批量命令的问题，验证原生粘贴、Ctrl+V、开关关闭时和已有在途输入的情形。独立复核未发现剩余阻断问题。
