基线：`main` 的 `667c2c767b34af1d62621728b4375009b085bf52`。实现分支 `codex/chat-content-width`。本文记录源码实现和验证，提交及主分支集成状态以 Git 记录为准；不代表已发布安装包或完成远端部署。

## 性能

Node 24.22.1、Playwright/本机 Edge、1800×950、假 WebSocket，100 轮问答（200 条消息）采样：

- 8 次鼠标移动产生 8 次宽度写入；拖动期间 0 次偏好保存，释放后 1 次。
- 被观察的 transcript 子树 0 次 DOM 变更；没有新协议请求，输入草稿保留。此项证明未重建/修改消息 DOM，不单独等同于所有 React 函数零执行。
- 手柄几何读取 2 次（进入和按下），移动期间不读几何；列宽观察使用 ResizeObserver 已有测量，纯高度变化不更新宽度。
- 100 个同一任务内的 pointermove 合并为 1 次宽度写入；取消后待执行帧不会恢复已放弃的宽度。
- 拖动及随后的输入未记录超过 50ms 的长任务；采样帧间隔最大约 28.6ms。第二轮复核输入事件到下次 RAF 的 22 个样本 p95 约 13.3ms。这些是本机采样，不能保证所有硬件或任意会话规模都零卡顿。
- 同一页面调宽前也记录了输入样本（第二轮 p95 约 44.3ms）；因顺序和首次输入预热影响，不据此宣称调宽提升打字速度。
- 与重新构建的基线对比，第二轮全部 JS/MJS/CSS 资产合计增加 23,272 字节，gzip 合计增加 6,589 字节（约 0.58%）；没有新增依赖。gzip 为逐文件独立压缩之和，并非打包程序大小。

控件无轮询和常驻 RAF；只在指针活动或可见指针提示需要随布局校正时安排帧。观察器及控件事件随卸载释放。一个不持有 DOM 的窗口级 storage 监听负责卸载期间失效缓存，HMR dispose 释放旧监听。

## 审阅修正

独立审阅提出的两处问题均已修复，并以回归覆盖：

1. 存储失败后切会话丢失偏好：先复现 960px 回退到 820px，再将降级缓存移到窗口级；移除偏好失败后的复位也覆盖。
2. 控件卸载期间遗漏同源窗口存储更新：窗口生命周期失效缓存，活动控件监听负责取消拖动和重绘；设置页返回测试验证 1100px 新偏好。

最终独立只读复核未发现新的可证实 P1/P2。没有依靠实际模型调用进行验证。

第二轮充分复核补测修正：按住手柄拖动时用 Ctrl+F 打开查找栏，正文框向下移动 49px，原提示线仍使用旧 top，导致指示偏离鼠标。新用例先稳定复现，再通过现有 ResizeObserver 在高度变化且指针位于手柄时校正位置；静止和继续移动两种情况均验证。列宽变化仍取消拖动，纯高度变化不修改已选宽度，不新增逐次 pointermove 几何读取，也不产生观察器反馈循环。独立审阅已核对该补偿、取消与卸载清理。

新增 `chat-width-review.spec.ts` 的 6 项补测：动态查找栏位置、真实右键/中键组合捕获结束、真实同源页面间的 storage 事件、8 次切会话后的全局监听收支平衡，以及 320–1097px、大字号下的居中和可操作性。没有仅靠合成 storage 事件或正常鼠标序列推断这些边界。

第三轮再次补测发现，上述定位修复还遗漏“松开拖动后鼠标仍悬停在手柄”的状态：finish 清空了 pointer，之后 Ctrl+F 移动正文 49px 时无悬停坐标可校正。`review3-red.log` 先复现该偏差；当前将手势和悬停位置分开清理：finish 仍清空 drag、取消旧 RAF 和释放捕获，pointerleave 清理悬停坐标。即使取消后因高度变化安排提示帧，flush 因 drag 已清空不会重新发布已取消的宽度；卸载仍取消帧、断开观察器、移除监听，不存在 effect 外部持有该局部指针的引用。独立审阅核对了取消、列宽变化及卸载路径。

第三轮另加 3 项用例，覆盖释放后的悬停提示、连续 16 次捕获手势各自保存最终值、窄列隐藏后键盘焦点释放；新增功能浏览器测试共 30/30 通过。第三轮 100 轮对话采样：保存 1 次、消息 DOM 变更 0、手柄几何读取 2 次、未记录超过 50ms 的长任务；输入事件到下一 RAF 的 p95 约 14.8ms，帧间隔最大约 28.6ms。预热/顺序限制同上，不据该采样推断跨机器保证。第三轮完整 JS/MJS/CSS 资产相对基线增加 23,265 字节、gzip 合计增加 6,594 字节（约 0.59%）。
