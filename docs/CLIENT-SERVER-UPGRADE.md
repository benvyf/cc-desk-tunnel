# 从客户端检查与升级服务端

Windows Build 7 提供固定入口，不再要求先出现协议不匹配。客户端和服务端协议相同时，也会根据已签名发布的 Build 判断更新；本次服务端仍为 Linux Build 3／协议20。

- 尚未连接：填写服务地址、证书指纹和服务凭据，点击“检查服务端更新”。
- 已经连接：在“设置 → 关于与更新”或“设置与账号”菜单选择“检查服务端更新”。结束任务后确认断开，客户端关闭当前隧道再自动检查。本窗口的连接信息临时保留，不额外写入磁盘；取消断开确认时继续保持原连接。
- 检查有更新后显示版本、Build、协议与 SHA256。再次点击“确认升级到 Build …”才安装；服务端保存备份、重启、验证就绪，失败回滚，客户端显示结果。完成后手动连接。
- 当前已是可用构建则提示无需升级。任务、原生终端运行时不允许从设置页进入升级；其他 CC 窗口仍连接时，服务端原有准入会拒绝安装，应先关闭其他连接。
- 尚未首次接入的旧服务端显示接入指引，打开控制中心后在 Ubuntu 执行一次首次接入命令。运行环境或持久化格式不兼容时仍转人工镜像升级，不绕过校验。

沿用现有主进程管理客户端、生产公钥、签名校验、精确目标确认、重放保护、固定管理路由、TLS 验证及服务端准入。未添加自动升级、GitHub源码重建、CLI/SDK更新或Claude账号登录操作。页面检查只调用受管管理接口，不调用Claude、JEV或额度接口。

验证：Node24 TypeScript检查；6项真实React/Edge合成界面场景（协议不匹配、首次接入提示、回滚与凭据变更、无协议错误时检查、已连接设置的取消/断开/临时凭据/确认安装、已是最新）；11项现有相关主进程回归全部通过。界面测试只使用合成管理API和WebSocket，不启动真实CLI或业务会话。正式安装包与生产发布结果另存发布证据。
