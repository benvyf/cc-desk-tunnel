# SSH 后台连接与主窗口授权互相撤销修复

2026-11-05。用户在连接 SSH 目标时收到 Ubuntu 返回的“登录授权已结束，请重新登录”。

## 根因与最小修复

主窗口和 SSH 目标各自向管理中心申请同一登录、同一 Ubuntu 节点的连接票据。旧 `DesktopAccess.connect()` 每次签发前删除该登录/节点的全部已有票据，因而新后台连接使主窗口的下次 30 秒续租失效，主窗口重连又可能反过来撤销后台票据。

仅移除签发时的这一次互斥删除，使一个有效桌面登录可持有多张随机、独立票据。不共享票据，不改变客户端或 Ubuntu 协议，也不建立新授权框架。新连接仍须在 120 秒内认证；现有连接续租仍受原登录会话、用户启用状态和节点授权约束。票据按原有会话生命周期维护，退出、过期清理及用户撤销会清除关联票据；不按短期签发过期时间删除仍在续租的票据。

同账号换设备仍要求确认并撤销原设备会话；退出登录、改密、停用账号、移除节点权限与会话到期仍使原有所有票据失效。维护请求继续使用独立短期票据，不因此得到长期续租权限。Claude、SDK、账号与模型出口保持在 Ubuntu，桌面只是多条既有执行连接。

## 验证

先修改回归预期，复现签发第二张票据后第一张失效，再修复通过。本机覆盖真实 HTTP/WebSocket：主窗口与 Linux SSH 身份后台同时连接并分别续租，确认换设备后两个旧 socket 都收到 4001，新的登录仍可工作。单元测试覆盖权限移除、会话到期、退出、维护票据过期、错节点/错 token、改密与单设备登录规则。

VPS 使用当前生产模块的精确基线，在私有临时数据库中运行最新 12 项授权单元测试，全部通过；不创建生产测试账号，不调用 Claude，不变更用户权限。生产源码仓库先记录与已核验运行清单一致的实际基线（其中一个历史更新脚本与记录提交不同），再只改票据模块，避免用当前主分支全量覆盖生产中心。
