# 关键词、JEV 审核与现有管理后台整合

2026-10-23，用户明确要求：JEV 内容审核及网页管理与已经存在的更新管理集成。本文记录集成范围；最新接口核对、已完成代码和未完成的节点执行检查见 [JEV-SUB2API-REFERENCE.md](JEV-SUB2API-REFERENCE.md)。管理配置和审核内核已完成本地实现，尚未部署或启用生产拦截。

## 管理入口

沿用 `https://api.ghostapi.org/cc-updates/admin/`，在现有管理网页及服务中增加审核模块，共用管理员登录、退出和导航。当前使用独立管理员令牌，首阶段复用此认证；GhostAPI 账号统一登录另行安排，不作为本阶段前置条件。

管理界面提供以下功能分区：

| 分区 | 功能 |
| --- | --- |
| 客户端更新 | 现有通道、候选、上传、发布、撤回和发布记录 |
| 审核策略 | 关键词、规则启停及处理方式 |
| JEV 配置 | 接口地址、模型、服务端凭据、超时等审核配置 |
| 审核记录 | 命中规则、审核结论、失败原因及关联节点/请求，供管理员查看 |

以上为功能范围；具体规则、JEV 字段和记录保留策略仍需结合实际接口确定。不会以新增页面或占位按钮宣称已有服务端审核。

## 执行边界

管理员在 VPS 同一后台设置策略并查看记录；强制检查仍由 CC 服务端在内容交给 Claude 前执行。VPS 现有加密 TCP 中转本身不能读取正文，单独增加管理页面不构成拦截。

管理员令牌和生产更新签名私钥不下发普通客户端或 CC 节点；JEV 凭据由服务端保存，读取设置不返回完整密钥。节点审核调用的认证与请求/记录协议在实施设计中单独定义。

已有更新签名契约、发布数据和自动续期继续使用原机制。普通客户端拒绝行为沿用既定需求：操作结束并返回通用失败，不展示审核结论详情；管理员后台可溯源。对必须经过 JEV 的请求，超时或不可用不能默默放行。原生终端、文件/配置修改等绕过路径仍需评估，不以仅审核聊天发送事件宣称完整覆盖。
