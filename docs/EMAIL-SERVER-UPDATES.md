# 邮箱账号发起远端升级

桌面客户端在“设置 → 检查更新”中显示客户端与服务端两部分。选择“检查服务端更新”后，先确认断开业务连接，保留邮箱会话，再检查目标工作空间。只在显示具体版本并再次确认后提交安装。成功或回滚后可点击“重新连接”，不必重新输入邮箱密码。

检查后无需升级或暂不安装时，同样可直接重新连接。安装请求的响应中断时继续查询结果，不自动重发安装请求；在结果未确认前不显示快捷重连按钮。管理中心版本过旧、尚未提供转发接口时，会明确提示先更新管理中心。

邮箱工作空间因协议版本不匹配而连接失败时，登录页提供“检查服务端更新”，使用已登录会话进入同一升级流程；不依赖进入工作空间后才能访问的设置菜单。

## 授权与执行

- 客户端只提交工作空间 ID、编译时协议，以及已确认的 Build 和 SHA256。邮箱会话只在 Electron 主进程使用。
- 管理中心的 `POST /cc-access/v1/server/check`、`install`、`status` 每次验证邮箱会话和工作空间分配权限。连接票据不能作为管理会话使用。
- 管理中心读取该工作空间已保存的服务凭据，通过 CA 或证书指纹验证 TLS 后调用固定的 `/cc-managed/server/v1/` 接口。客户端不接收永久服务凭据。
- 客户端仍独立验证服务端发布签名、协议、递增 Build 和精确安装确认。退出、换号或会话失效会清除未提交的升级确认。
- 远端复用现有的空闲检查、下载验证、冷备份、切换、健康检查和回滚。确认后提交的升级不会因关闭等待窗口而撤销；请等待可验证结果，不要重复提交。
- 运行环境或镜像不兼容时显示管理员处理提示，不开放在线安装。

## 后续发布依赖

此功能需要同时更新管理中心和桌面客户端。已有受控升级接口的 Ubuntu 无须为邮箱转发机制另行改造；没有受控接口的旧实例仍需首次接入。

部署管理中心时，包含新增的 `desktop-server-update.ts` 以及复用的 `secure-service.mjs`、`system-proxy.mjs`。源码发布清单已更新，并已用隔离目录验证可以独立导入运行时。

还需应用 [Nginx 示例](../deploy/update-service/nginx.conf.example) 中 `/cc-access/v1/server/` 的独立超时设置。原 `/cc-access/v1/` 的 15 秒超时可能早于远端下载验证完成，升级接口使用更长的超时；登录接口保持原设置。不得记录 Authorization 或请求正文。

桌面安装请求超时为 180 秒，检查及查询为 50 秒；Nginx 升级路由为 190 秒，覆盖内部连接、下载验证和响应读取的时间预算。

当前仅修改源码与部署模板，未打包、未部署，也未向真实 Ubuntu 提交升级。

## 验证

使用测试邮箱、临时数据库和本地 TLS 服务验证权限隔离、确认字段、证书指纹拒绝、账号停用和票据越权拒绝。桌面测试覆盖邮箱会话保留、仅传工作空间 ID、一次提交后等待重启以及重新连接。未调用 Claude，也未安装生产更新。

本轮复查通过 30 项主进程与授权/TLS 测试、26 项更新界面测试及 TypeScript 检查。回归覆盖响应丢失后只查询不重发、当前版本和暂不安装时重新连接、协议不匹配恢复、关闭窗口取消检查与忽略迟到结果、浅深色窄屏及键盘操作。
