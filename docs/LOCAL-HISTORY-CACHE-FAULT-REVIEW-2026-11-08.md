# 本机副本：故障、并发与容量复审

2026-11-08，香港时间。基线 `3567224`。本轮增加磁盘故障注入、异步操作交错、子进程突然退出、全局容量与长 run 连续追加用例，原工作区及服务端/协议保持不变。

## 已复现并修复

| 问题 | 复现与影响 | 修正 |
| --- | --- | --- |
| 磁盘故障吞掉网络加载 | A 的写入失败时，B 正等待读盘；或清除失败后原读取被丢弃。可见会话没有发出任何订阅。 | 根据当前选中/观察的会话恢复网络读取，不依赖已取消的磁盘 Promise；用 pending 的 sessionId 避免重复订阅。读盘开始时就标记未确认，避免失败回退采用全局流式帧推进的错误游标。 |
| 清除和关闭开关交错丢失订阅 | 手动清除先清空 diskReads，关闭开关再读取空集合；旧清除代次又不能恢复，最终不发订阅。 | 清除的 finally 和关闭完成后都检查当前连接及可见未确认会话，由同一恢复方法接续网络；旧连接的完成回调不会干扰新连接。 |
| 清除期间的权威 snapshot 没有建立 synced | snapshot 到达时 storage ready=false，因此虽恢复 ready，之后的流式事件一直不记录。 | 接受权威 snapshot 的连续性证明与磁盘是否暂时可用分开；只读存储状态继续控制写盘，临时清除不再丢掉证明。 |
| 正常 LRU 淘汰误关闭缓存 | 磁盘文件已淘汰，完整窗口仍在内存；下次差量补齐后 append 找不到旧文件，整个连接的缓存被关闭。 | 从已经确认的完整内存窗口原子重写；追加拒绝后再次检查连接代次/socket/synced，防止切换 owner 后写回旧窗口。重写也失败才关闭存储并恢复网络。 |
| 追加增长未触发全局容量淘汰 | 窗口低于单会话上限但多次 append 后总量超过全局上限，idle 后仍未淘汰。 | 追加后也调度维护；维护任务合并，最多再排一轮，避免多个侧聊制造无界扫描队列。 |
| 超长活动 run 以半截重新出现 | A 的 1/2/3 条超限后整组丢空，但随后 A:4 被当成新窗口保存；重开后依然可发生。 | 空窗口头部可选记录已丢弃 runId 的 SHA-256，跳过该 run 的延续，遇到新 run 才恢复保存；内部标记不进入 read IPC。 |
| 崩溃临时文件漏报且不回收 | 真实子进程在 write/sync/close 完成、rename 前退出，留下 tmp；原 usage 不报告、维护不删除。 | 维护清除当前模块命名的遗留临时文件，使用活动临时文件集合保护尚在写入的文件；分别验证突然退出和正常写入被暂停的情况。 |

上述用例都先在旧实现观察到失败，再验证修正。新存储头部可选 `discardedRun` 是本机完整 run 裁剪的内部恢复信息；format 仍为 1，protocol 仍为 24，没有线上协议或服务端变更。

## 独立复核

独立审查分别复核磁盘三项修复，以及客户端失败回退和迟到追加拒绝的 owner 隔离。另以只读夹具验证：清除失败时主聊/侧聊恰好恢复一次正确角色的订阅；旧连接清除结束不会对新连接发订阅。复核未留下本轮范围内未解决的已复现问题。
