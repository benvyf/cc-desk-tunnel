# Claude 账号数据被动同步

2026-10-23，Asia/Hong_Kong。初版实现位于 `codex/account-monitor-sync`；与线上审核/密码登录合并后的 `codex/account-monitor-production` 已部署 VPS。首台 Ubuntu 被动监控已由用户安装成功，其余五台暂停；VPS 尚无自然上报，完整状态及备份见 [生产部署记录](ACCOUNT-MONITOR-DEPLOYMENT.md)。本文件描述配置方法，不能据此认为节点已经上报。

## 工作方式

Claude Code → CC Ubuntu 服务端原有数据事件 → 后台 HTTPS 上报 → VPS private SQLite → 管理页。

新增同步从不调用 Claude、不启动 CLI、不执行额度刷新；保留既有客户端操作和原生采集频率。没有既有活动时，不会为了监控唤醒 Claude。管理页每 30 秒和手动刷新均只读取 VPS，超过 15 分钟没有新额度采集显示“数据已过期”，不能据此认定节点离线或账号被封。

上报默认最多每 30 秒一次，同一账号瞬时多条事件合并为最新快照；五秒超时，失败指数退避，最长五分钟。后台只有一个在途请求，待发队列按账号合并并按观察时间发送，最多 64 项，溢出丢最早待发项。服务停止取消上报。队列仅在内存中，重启后等待下一次现有数据事件；不会主动补采 Claude 数据。VPS 持久保存已收到的账号档案与各节点最后快照。

当前原生额度依赖 SDK 实验接口；本功能不改变其调用方式/频率。多账号复核只给现有采集事件附带原请求时间 `quotaAttemptAt`，在上下文刷新时沿用，防止旧错误覆盖新成功；没有新增读取。这不增加对 Anthropic 的授权或合规保证。

## 身份与数据

- 每个节点配置独立随机密钥，至少 32 字符；VPS 仅存 SHA256。不能复用管理员令牌、CC 连接令牌或 Claude 凭据。
- 用户已明确选择“完整邮箱＋自定义备注”。schema 2 上报完整邮箱、组织、套餐、登录方式、API 提供方及身份状态；账号 ID 仍为规范化邮箱的 SHA256，接收端核对二者一致。邮箱、组织和备注作为私人数据，仅管理员可以读取。不会上传聊天内容、路径、登录网址、OAuth Token、Cookie、凭据、tokenSource 或原始错误正文。
- 备注最多 2000 字符，仅管理员写入 VPS，节点不能修改；支持按邮箱、备注、节点、套餐和组织搜索。刷新保留未保存草稿，退出清除页面上的数据和草稿。
- 上报额度窗口的已用百分比、估算剩余和重置时间，以及最近会话累计用量及其会话/运行 ID。会话可能跨账号，不能当作账号总量；金额是 API 单价估算，不是 Pro/Max 账单，不能把这些快照相加作为总消耗。仅有 `max` 时不推断 5×/20×。
- 切换/退出账号清除本地当前额度；VPS 保留之前账号档案、备注及每账号每节点的最后快照，标为历史绑定。身份未知不等于未登录。多个节点的同账号额度独立展示，不累加百分比；组织/提供方明确变化时不沿用旧上下文额度。
- 接收端兼容 schema 1，旧 SQLite 节点记录会幂等迁移为账号档案；旧记录无邮箱时等待下次正常使用上报，不主动补采。schema 1 的会话累计没有运行来源，升级时保留额度但不伪造该用量的 runId。
- 同账号重启后的“未采集”不覆盖最后有效额度，缺失的套餐/组织等字段保留最后已知值。最近读取失败/不提供额度与旧快照并列显示；额度时间仍是原采集时间，不随身份或错误更新而变新。
- 数据源按一次原生进程的运行 ID 绑定身份。账号变化后旧进程事件失效；新进程身份未知时清除旧数据。交错的上下文更新不能覆盖更新的会话用量，原生重置时间统一转换为 UTC。
- 网页沿用现有管理令牌，内存保存认证；节点密钥只有该节点上报权限。浏览器 Origin 上报被拒绝，所有读接口要求管理员认证。

## VPS 配置

在现有 `/etc/cc-update-service/config.json` 顶层增加可选字段；原有字段完整保留：

```json
{
  "monitorNodes": {
    "ubuntu-1": "填入该节点上报密钥的64位小写SHA256",
    "ubuntu-2": "填入另一个独立密钥的64位小写SHA256"
  }
}
```

此片段是合并示例，不能作为完整配置文件。最多 64 个节点，ID 为字母、数字、下划线、短横线，1–64 字符。每个 Ubuntu 实例必须有唯一节点 ID 和密钥，不要把一份环境文件原样复制到不同节点；同 ID 的两个生产者尚无冲突检测。哈希不得相互重复或与管理令牌哈希相同。删掉字段表示禁用监控；移除某节点后重启会清理它的当前绑定，保留已收到的账号档案和历史快照。没有成功上报的配置节点也会显示“等待首次上报”。

新接口位于现有 Nginx `/cc-updates/admin/` 代理范围，通常无需新增路由；仍应在正式部署前检查实际 Nginx 配置及请求限额。节点 POST 上限 16 KiB，不应在日志记录 Authorization 或请求正文。

- 节点：`POST /cc-updates/admin/api/monitor/report`
- 管理员：`GET /cc-updates/admin/api/monitor`
- 管理员备注：`PUT /cc-updates/admin/api/monitor/accounts/<账号SHA256>/note`，JSON `{"note":"账号备注"}`；必须携带管理认证和正确 Origin。
- 页面：`https://api.ghostapi.org/cc-updates/admin/` 的“账号监控”区域。

数据位于 `/srv/cc-update-service/private/monitor.sqlite`，遵循已有 private 0700 隔离。备份需停止服务后复制整个 private 数据目录，不能只在线复制一个 SQLite 主文件。

账号档案记录首次/最后接收时间及每个账号在每个节点的最近观察，不是完整换号流水或账单台账。账号累计数量不受节点数限制，目前没有自动过期删除、分页或档案删除界面；数据保留及清理需由运维明确管理，数据库/备份也含完整邮箱及备注。初次采集的身份变更时间与每个元数据字段的最后采样时间尚不单独建账。

本轮未实现自动登录/换号、凭据托管、封禁/账号健康探测、续费/余额/账单查询，也未根据快照做账号消耗汇总。后续管理应继续使用现有读取结果，不为填满字段增加账号请求。

## Ubuntu 配置

更新 CC 服务端源码/镜像后，在每台自己的 `/data/config/service.env` 或现有同等环境文件中增加：

```dotenv
PROXY_MONITOR_URL=https://api.ghostapi.org/cc-updates/admin/api/monitor/report
PROXY_MONITOR_NODE_ID=ubuntu-1
PROXY_MONITOR_TOKEN=替换成该节点独立随机上报密钥
```

配置支持 HTTPS、精确上报路径，不支持 URL 凭据、查询参数、片段及重定向。必须三个字段一起配置，全部省略则默认关闭。通过安全运维终端传入环境文件并限制文件权限，不把密钥写到 Git、聊天或命令输出。`PROXY_` 配置在启动 Claude 前从继承环境清除。

上线顺序：先备份并更新 VPS 运行归档/配置 → 启动检查 → 单台 Ubuntu 新镜像试点 → 在正常使用后观察数据 → 再逐台部署。不要为验收自动向 Claude 发送测试消息。首台已安装被动监控，但受管服务端首次升级接入仍待执行；不能直接假定其他节点已具备此功能。

## 验收与回滚

本地测试全用合成数据和回环 HTTP/TLS，不读取或访问真实 Claude 账号。正式验收检查管理员能看到节点最近上报，重复/乱序不会覆盖新数据、节点令牌不能读取管理数据；停止 VPS 后 CC 聊天可继续。后者应在自然使用窗口观察，不额外创建 Claude 请求。

初版 Node 24 回归共 361 项，330 项通过、31 项跳过。多账号复核增加了换号历史、元数据保留、错误重放、并发身份、版本迁移、备注权限及草稿竞态测试；验证结果记录在本轮复核计划中。真实浏览器验收使用本地合成账号，覆盖完整邮箱、备注保存重登、搜索、历史绑定、未上报节点和移动布局。

Ubuntu 部署仍需核实实际版本：首台实际容器已经是协议 20，旧宿主源码仍是协议 19，其他节点应逐台核实；其他后续任务也可能已升级节点或部署审核，必须从控制台核对后合并，不能按旧记录覆盖。用户当前通过 UU 访问远端 Windows，再由虚拟机控制台管理 Ubuntu；当前工具没有该桌面或 Ubuntu SSH 管理入口。此实现不自动升级或重启生产节点，不应为监控打断正在运行的 Claude。

关闭某台同步：从其环境文件同时移除三个 `PROXY_MONITOR_` 字段后按原方式重启该台 CC。VPS 回滚前停止服务，恢复旧运行目录和原配置；原版本不认识 `monitorNodes`，回滚配置必须移除该字段。SQLite 快照可以随备份保留，不改动更新发布数据库或签名身份。
