# 多设备开发：追加独立复查

2026-11-06（香港时间）。复查对象为 `codex/multi-device-development` 的 `2fa600d`，按用户提供的 `32-multi-device-fix-plan.md` 核对 A1–A5、B1–B3、C1–C2，以及既有网络边界。两位独立审查者分别检查创建与重试、终端交互；主代理通过界面测试复现并修复问题，再由审查者复核。

## 发现与落实

| 级别 | 问题与实际触发 | 修复与验证 |
| --- | --- | --- |
| P2 | 静默创建已生成会话，但创建响应丢失，或配置失败后再次失败并取消对话框。再次从项目菜单重试时，最新的未配置会话可能成为来源，其 `auto / null / null` 覆盖原审批模式、模型和思考强度。 | 在首次创建请求前，按稳定创建 ID 保存完整配置快照；重复请求使用原快照。远程对话框仅在配置成功后清理创建身份；改选设备或目录时按新目标计算配置。覆盖本机 / 远程丢响应、两次配置失败后取消重试、无来源保存项目及默认配置变更，共 6 个用例。 |
| P2 | 给 A 标签改别名时按 Ctrl+Tab 切到 B，或按 Ctrl+Shift+T 新建 C，保存时会修改当前活动标签。 | 别名对话框保存打开时的目标标签 ID，始终修改该标签。两种快捷键分别有回归用例。 |
| P2 | 搜索框组合输入尚未结束时关闭菜单，组合状态可能残留，导致再次打开菜单后 Escape 等按键失效。 | 菜单关闭时清理其组合状态，保留正在组合输入时不执行菜单动作的保护。补充中断组合输入后关闭、重开与 Escape 的回归用例。 |

9 个新增用例均先在原实现上复现失败，再在修复后通过。重试用例的夹具采用真实的新会话默认审批模式 `auto`、空模型 / 思考强度及较新的更新时间，并模拟配置成功后的会话更新，确保能够检出未配置会话被错误选作来源的问题。

复核未发现剩余的已确认问题。生产代码只涉及 [App.tsx](../apps/desktop/src/App.tsx) 和 [TerminalWindow.tsx](../apps/desktop/src/TerminalWindow.tsx)，对应测试位于 `multi-device-development.spec.ts` 与 `terminal-projects.spec.ts`。
