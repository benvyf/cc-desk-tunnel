# 客户端跨协议更新提示修复

2026-11-05。用户反馈已安装的 Build 27 不提示新版。

## 根因

Build 27 使用协议 23，新发布的 Build 28 使用协议 24。受管更新的签名选择器按设计拒绝跨协议安装，返回 `protocol-mismatch` 和空 `release`。控制器将空版本信息直接传给界面，`managedUpdateNotice()` 因缺少目标版本返回空值，导致“禁止跨协议自动安装”同时变成“不提示有新版本”。此路径独立于是否成功连接 Ubuntu，不需要放宽工作空间协议或模型网络边界。

## 修改

只在桌面受管控制器中保留经验证且版本高于当前安装/确认版本、不低于防回放账本记录的新发布元数据，供界面显示配套升级提醒。原选择器的安装授权规则、签名、固定通道、摘要和回放检查保持不变；自动下载及安装仍必须满足 `available`，`protocol-mismatch` 不具有执行安装器的权限。

手动查看配套版本会推进已验证版本账本，后续检查仍应显示同一新版本；旧版或当前已安装 Build 不应出现更新提醒。没有增加模型 SDK、账号请求、代理或模型出站路径。

## 验证

先用现有控制器复现跨协议检查返回的 `release.build` 为空，再修复通过。回归覆盖签名元数据到 `managedUpdateNotice()` 的实际提示生成、手动链接查看后提示仍存在、旧版不提示，以及跨协议下载/安装仍拒绝。受管客户端/签名契约整组 41 项测试及跨协议界面测试通过；安装器篡改、撤回、回放和活动进程限制也保持通过。

## 已安装客户端的限制

此修复属于客户端本地代码，当前只在源码工作区，尚未生成或发布新客户端包。不能仅修改管理中心就给已安装的 Build 27 注入新逻辑，也不能把协议 24 安装包伪装成协议 23 来强迫旧客户端自动更新。

Build 27 用户当前可以从管理员提供的已签名完整包手动覆盖升级，保留原安装范围及目录，结束任务并关闭全部窗口后安装。若要获得本次修复，需将此变更纳入新的签名客户端 Build 后手动安装一次；以后跨协议新版可显示配套提醒。该修复不表示旧 Build 27 已自动得到更新能力。
