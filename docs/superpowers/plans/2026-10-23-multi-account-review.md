# 多账号监控复核与修补

**目标：** 复用既有 Claude 事件，让每个账号可识别、可备注、可追溯节点和数据时间。用户已选择完整邮箱＋自定义备注。

**设计：** 上报 schema 2 增加邮箱、组织、登录方式、API 提供方及身份/额度读取状态；接收端兼容 schema 1。账号 ID 仍为规范化邮箱 SHA256，额度保持每账号每节点独立。SQLite 保存每个账号在每节点的最后快照，节点当前身份独立保存，换号不删除档案。管理员备注仅写 VPS，不随节点上报覆盖。展示配置未上报节点、历史绑定、搜索及清晰的时间/状态。

**采集边界：** 不改 Claude SDK 调用及现有刷新频率；`native-controls` 仅给既有事件加上原请求时间并在上下文刷新时沿用，不新增读取。不查询账单、余额、续费日期或封禁状态。身份/失败状态仅表示最近既有读取结果。邮箱/组织未知时如实显示，已有值不被新的“未知”覆盖。上报失败时仅向 VPS 重试；不制造 Claude 活动。

- [x] 先补失败测试：现有事件身份元数据、失败保留旧额度但标记错误、退出与未知区分、短时间换号都被上报；历史与备注持久化、节点未上报清单、跨节点不合并额度、权限/输入校验。
- [x] 修改 `packages/protocol/src/account-monitor.ts` 和 `apps/server/src/account-monitor.ts`。后台按账号合并有界待发队列（最多 64 项，溢出仅丢最早待发项），单请求/节流/退避保持原约束，旧进程不能改变当前身份。并发初始化只允许匹配同账号及所有已知上下文的未绑定来源。
- [x] 修改 `apps/update-service/src/monitor.ts` / `http.ts`：幂等历史迁移，账号档案及节点快照在同一事务更新；管理员专用备注接口。未知/退出不抹掉历史。乱序不能更新当前身份或让旧数据变新。迁移合并同账号多个节点的最早/最晚接收日期。
- [x] 修改管理页：完整邮箱、备注编辑、搜索、组织/套餐/登录方式/提供方、当前或历史节点、额度与错误/新鲜度分开、输入/输出/缓存 tokens 和估算费用。刷新保留未保存备注，保存期间的新编辑不会丢失；退出清空页面及草稿。
- [x] 真实浏览器覆盖完整邮箱、备注保存重登、搜索、历史账号、无上报节点、移动布局及备注保存期间继续编辑。Node 24 focused 37 项通过；完整回归 373 项：342 通过、31 平台/显式开关跳过、零失败。迁移多节点日期汇总的最终修补另行通过专测。类型、格式与 diff 检查通过，独立复核没有剩余重要问题。
- [x] 更新运维文档。保持未上线状态，既有协议迁移及运维入口依赖仍适用。最终归档在干净提交后按来源提交生成并验证，未生成前不声明交付包完成。

不提供自动换号、登录、凭据托管、账号健康探测、自动可用性测试。不能从过期快照推断节点离线或账号封禁。当前档案只代表服务已经成功接收的观察，进程重启的内存待发队列不会恢复。
