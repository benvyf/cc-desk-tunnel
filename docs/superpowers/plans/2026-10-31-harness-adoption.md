# CC SPACE 借鉴 DeepSeek Harness 的分阶段改动计划

> 执行本计划时使用 `executing-plans` 逐项推进。本文是引进决策与改动计划，不代表功能已实现或已通过测试。

**目标：** 在模型请求仅从远端发出、预览侧栏不向 Claude 暴露接口且不自动回传内容的前提下，改善预览连续阅读、长对话流畅度和回答结束时的画面稳定性。

**架构：** 沿用 CC SPACE 的 React 界面、客户端预览与本机布局存储、远端 Claude SDK 和既有执行通道。首批只改客户端阅读状态及其验证；性能优化和滚动修复以可复现证据为准，不引入 Harness 的插件、调度或模型运行时。

**技术：** React、TypeScript、Electron、现有 PDF.js / 本机 Office 转换、Node 24 测试与 Playwright 假服务。

**状态：** 已在隔离分支 `codex/harness-adoption` 完成实施与复核。性能两类工作负载均完成原版/改动后各五组保留测量，结果见[执行记录](../../HARNESS-ADOPTION-REVIEW-2026-10-31.md)。不调整发布版本或部署。

**核对基线：** CC SPACE `main`：`27925f45c10ba088396b6ad4e6844741c0610c2d`。Harness `master`：`ce7073d51254c26cd63b22a60835b8f948deb447`；截至 2026-10-31 的前轮查询仍为该提交，本文引用固定 SHA，实施前重新核对主线。

## 1. 引进结论与范围

选择“小范围体验补齐 + 测量后优化”，首批交付由三个工作包组成：

1. **建立基准和回归证据。** 复用已有长会话、预览性能及引用测试，补主侧会话并行输出场景。
2. **保留文档阅读状态。** 文本、代码、Markdown 保留阅读位置；PDF 和 Office 转换结果保留页码、缩放与当前页阅读位置。
3. **改善已证实的性能或滚动问题。** 只有能复现、能对比、能验证的缺陷进入修复；未发现问题时交付测量与回归覆盖，不为对齐 Harness 强行改写。

三种方案的取舍：

| 方案 | 收益与代价 | 决策 |
| --- | --- | --- |
| 引入 Harness Sidebar / 插件运行时 | 能快速获得其功能体系，但与现有 React 状态、预览安全策略和协议重叠，维护面大 | 不采用 |
| 补齐现有路径中的体验，并用测量决定优化范围 | 阅读收益明确；边界清楚；可以分批验证、单独回退 | 采用 |
| 只增加性能测试 | 风险低，但无法补齐已确认缺少的按标签阅读状态 | 作为第一步，不作为全部交付 |

### 1.1 候选功能筛选

| 候选 | CC SPACE 现状 / 新增成本 | 本轮决策 |
| --- | --- | --- |

| 定时任务迁到远端、更多时间规则 | 已有客户端定时任务；迁移涉及设备离线、投递幂等、时区与无人值守审批 | 独立后续项目 |
| 事件触发自动化 | 上游目前是提案，存在触发范围、重复执行及费用决策 | 不引进本轮 |
| LiveShare、本机电脑控制、浏览器内模型运行时 | 超出单用户产品方向，或引入额外控制与运行入口 | 不纳入本计划 |
| 上游 apply_patch、模型请求插件 | 属于 Harness 工具体系；CC SPACE 继续由原有 Claude Code 管理工具和模型请求 | 不移植 |

## 2. 不可突破的边界

- 主、侧会话的模型/API 请求继续经原有远端 Claude SDK 发出，客户端不加入模型 SDK、API 密钥或本机模型回退。
- 不新增 Claude 可调用的预览、目录、网页、DOM、截图或阅读状态接口。不得把这些内容附入提示词、工具结果、侧聊快照或自动附件。
- 本计划新增的阅读元数据只保存在本机客户端配置中；不进入 `packages/protocol`、服务端会话库或诊断上传。
- 用户主动提交的对话引用继续走原有流程；阅读状态恢复不能触发发消息、创建侧聊或启动模型。
- 不增加网页 preload、Node 集成、原生网页 DOM 访问、端口转发或开发服务启动能力。不绕过重启后网站与 HTML 的“加载此预览”确认，包括 HTML 后缀别名。
- 原有 SSH 开发脚本能力不变；这里没有新增全设备断网要求，也不把架构检查描述成操作系统防火墙。
- 测试使用模拟服务、临时文件和测试配置，禁止调用真实模型 API。

边界依据：[预览说明](../../PREVIEW-SIDEBAR.md)、[边界审查](../../PREVIEW-BOUNDARY-REVIEW-2026-10-31.md)、[引用说明](../../QUOTED-CONVERSATIONS.md)。

## 4. 工作包 A：基准与问题复现

### A1. 固定工作负载

| 场景 | 数据与操作 | 指标 |
| --- | --- | --- |
| 长历史 | 复用 400 步夹具，分别使用标准和全部展开视图 | 打开耗时、逐键输入耗时、长任务数量 |
| 长回答 | 单条 256 KiB 文本，分别拆成 4,096 / 16,384 片段；包含前半为空白的思考文本 | 合并与对话组装 CPU、最终文本完整性；分别测纯处理与浏览器绘制 |
| 并行会话 | 主会话和 1 个侧会话各持续输出 30 秒，同时在聚焦输入框输入 120 字符；先关闭预览，再开启一个静态文档作对照 | 输入延迟 p50/p95、超过 50ms 的主线程长任务、监听重装次数 |
| 预览互不干扰 | 20 次无关聊天 DOM 更新；连续滚动文档 10 秒 | 原生几何读取、文件重读、IPC 调用、本机存储写入与 React 渲染次数 |
| 生命周期 | 打开/关闭 40 个侧聊；文档切换、移动、浮动/停靠各 20 次 | 观察者、监听、状态条目和文件 token 是否回落 |

纯处理吞吐用例允许批量投递全部片段；浏览器交互用例必须按时间投递，不能用一口气灌入事件代替输入流畅度。聚焦输入和另一个未聚焦输入框分别检查，避免主、侧焦点串扰。

### A2. 测量与决策规则

- 同一机器、相同 Node / Edge 版本、相同视口和夹具；预热一次后运行 5 次，保留每次数据并报告中位数，明确冷/热缓存。
- 沿用现有打开小于 5 秒、平均逐键操作小于 150ms 的回归上限；它们是测试宽限值，不能宣传为真实输入延迟。
- 新增“输入事件到下一帧回调”的浏览器内输入响应估计，目标为 p95 不高于 100ms；使用同一浏览器时钟下的 `input` 事件与动画帧时间戳。它不等于 keydown 到像素实际显示的延迟，也不能用 Playwright 调用往返耗时代替。达不到目标时记录环境和剖析结果，不调大阈值掩盖问题。
- 新增阅读状态后的打开和输入耗时，中位数不得比同机基线劣化超过 10%；基线差异小于 5ms 时按噪声记录，不宣称优化。偶发超限完整复跑该工作负载一次，并保留两组数据。
- 只有组装、重复解析或可见性判断被剖析确认为热点，才改对应代码；先减少重复工作，再考虑增量组装。不得预先把整个 `transcript` 改成缓存框架或增加常驻 Worker。
- 正确性、内容完整性、停止与审批隔离属于硬门槛，即使耗时下降也不能放宽。上游基准数字不作为 CC SPACE 的性能提升证据。

## 5. 工作包 B：按标签保留阅读状态

### B1. 首批支持范围

| 内容 | 保存内容 | 恢复时机 |
| --- | --- | --- |
| UTF-8 文本、代码 | 正文纵向位置及实际存在的横向滚动位置 | 同标签重新挂载、刷新成功、浮动/停靠和正常重启后 |
| Markdown | 排版/源码模式，以及各模式独立的纵横位置 | 模式切换与同标签恢复后；异步排版完成后校正 |
| PDF / Office 转换 PDF | 页码、缩放、当前页滚动容器的纵横位置 | 文档成功加载并确认页数后；当前页绘制完成后恢复偏移 |
| 图片、网页、HTML、侧边聊天 | 不新增阅读状态 | 保持现有行为；尤其不读取网页或 HTML 的 DOM |

文本状态首批使用像素偏移，不引入段落语义锚点、内容指纹或正文缓存。文件插入、删除或排版改变后只保证恢复到可用偏移，不承诺仍是同一句话；这项限制须写入用户说明。

### B2. 身份、存储与兼容

- 身份使用现有连接、区域、工作区、会话与 tab id。不能仅用文件路径作键；同一文件在不同会话各有阅读位置，主区与终端区互不污染。
- 沿用 `cc-preview-v1` 存储范围，在布局序列化对象增加可选的 `reading` 字段，包含独立的 `version: 1` 与按会话、tab id 索引的数值状态；正文和文件内容不入库。
- 拟议状态只有 `text`、`markdown`、`pdf` 三种判别类型。文本为纵横坐标；Markdown 额外包含当前模式及两套坐标；PDF 为页码、缩放和当前页坐标。类型、清洗与序列化集中在新文件 `apps/desktop/src/previewViewState.ts`。
- 旧布局没有 `reading` 时使用默认状态；未知版本只丢弃阅读状态。坏 JSON 沿用现有布局兜底；阅读字段损坏不丢掉有效标签布局。
- 仅为经过现有布局过滤的有效会话、标签恢复状态；过滤无关字段、非法类型、非有限数值、危险对象键及不支持的内容类型。
- 阅读元数据新增上限为每个存储范围 256 KiB，按 UTF-8 编码计；超限只丢弃阅读元数据并保留布局。继续遵守总输入 2,000,000 字符、100 会话、每会话 64 标签及 4 窗格限制。序列化后若新增阅读字段使完整布局超过总输入限额，先移除阅读字段再保存，不能写出下次恢复会整份拒绝的结果。此工作不扩大现有布局配额。
- 偏移只接受有限非负值并限制在 0–10,000,000 CSS 像素；PDF 页码为正整数且在加载成功后裁到真实页数；缩放限定为现有 0.5–3 范围及 0.25 步长；无效字段使用默认值。
- 关闭标签删除其阅读状态，删除会话删除整组，正常工作区切换将旧状态写回旧范围并解除旧回调。断线期间会话列表暂空不能误删；沿用当前会话列表已就绪后才清理的规则。
- 同一 tab id 的拖动、分栏、浮动和停靠保留状态；关闭后重新打开取得新 tab id，按新标签默认位置开始。

### B3. 高频事件与落盘

- 阅读位置存在工作区 owner 的可变引用中，滚动时不更新整个 board 的 React state，不引起主对话、输入框或其他窗格重绘。
- 与现有布局写入统一调度，每个 owner 最多一个待执行存储任务。变更后静默 500ms 合并写入；持续变化时在本轮首次未保存变更后的 2 秒写入，然后重新开始计时。布局更新和阅读更新序列化同一份最新数据，不允许两个写入器互相覆盖；退出补写不受这两个延迟限制。
- 替换现有 150ms 布局写入调度时，调整依赖该时序的测试为条件等待，不能再硬编码等待 200ms。此处是为避免每次滚动复制与序列化布局作的局部修改。
- 标签切换与卸载保留旧 owner 的最后有效位置。清理时只有容器尺寸仍匹配有效视口才采样，避免 React 先移除父级工具栏、再清理 PDF 时把临时夹紧坐标覆盖进去。`pagehide`、`beforeunload` 和工作区释放时补写；由 owner 在序列化前调用已注册的采样函数，不依赖 window 目标事件的监听顺序。旧组件的迟到回调必须按 owner、会话和 tab 身份校验。
- 本机存储不可写或达到限额时，当前运行期间仍用内存状态，不阻塞打开文件、不弹重复错误，不承诺该次重启恢复成功。
- 不为状态保存增加文件读取、Office 转换、IPC、常驻轮询或文件监听；定时器只是合并写入，退出时清理。

### B4. 刷新、恢复与异常规则

1. 刷新前保存已就绪正文的位置；读取中、失败占位、清空内容和布局自动夹紧产生的滚动事件不得把旧位置覆盖为 0。
2. 只在对应 tab、读取修订及模式仍有效时应用结果；旧文件读取、旧 PDF 加载或旧绘制任务的迟到结果不能更新新标签。
3. 恢复目标为已保存像素偏移与当前可滚动范围的较小值。第一次刷新中短暂空白不算文件变短；成功内容及异步排版稳定后才提交夹紧结果。
4. 文件确实变短时，停在新的末尾并接受这个位置；不永久保留不可达位置，也不为了追赶旧位置重复读文件。删除后保留旧状态供文件重建成功时恢复；明确关闭标签才移除状态。
5. 用户在等待恢复时主动滚轮、触摸、拖动滚动条或按滚动键，立即取消本轮自动定位，优先保存用户新位置。程序恢复引发的 scroll 不能被当作用户新选择。
6. 文本/Markdown 切模式时保存各自位置。用户改变字号、窗口或分栏大小时按当前布局夹紧；不要持续强制回旧坐标。
7. PDF 加载完成前不把页码写回 1；页数减少时裁到末页，并在页面绘制完成后再恢复偏移。翻页时从该页起点开始，首批不保存每一页独立的历史位置。
8. Office 文档只能复用一次正常转换后的 PDF 恢复状态；不能为恢复页码增加转换。保留现有取消、超时、队列、画布上限和资源清理机制。
9. 内容格式发生变化时丢弃不匹配的阅读状态，不能把文本状态套到 PDF 或 HTML 上。HTML、网站的加载确认优先于任何恢复行为。
