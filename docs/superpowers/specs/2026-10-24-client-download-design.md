## 推荐方案

### 完整安装包

找回并核对已发布 Build 2 源码，保留它的固定 VPS 源、受信公钥、更新校验和用户确认安装流程，再合并当前分支中与客户端有关的最新改动。以新的不可变构建号发布，不覆盖已有 Build 2。应用版本和协议从最终合并代码读取，构建号根据发布记录分配，预计为 Build 3。

使用现有 NSIS 完整安装流程，包含应用、OpenSSH 和 PowerShell 等现有随包运行组件。保留连接配置的覆盖安装方式。包中不放管理员凭据、Claude 登录信息、历史会话或 Ubuntu 节点令牌。

账号监控和内容审核的执行模块仍在配套 Ubuntu／VPS；Windows 完整安装包不代表自动部署或升级六台 Ubuntu。下载区明确显示协议兼容要求。

### 管理中心下载

在 `/cc-updates/admin/updates` 的发布管理区域前增加下载区。使用已有登录与 `/status` 数据，只为已发布、未过期且有安装包的通道显示下载操作；不为候选、空通道或过期索引显示可用下载按钮。

显示 Windows x64、应用版本、Build、文件大小、更新说明和兼容协议，支持下载及复制链接，SHA256 放入可展开详情。下载路径只能由现有可信发布字段和固定同源 `/cc-updates/v1/artifacts/` 路径生成，不接受自由外部 URL，不把登录凭据拼接进下载地址。

先在 pilot 发布新构建，页面明确标为试点版；未完成实际安装验收前，不把它描述为稳定正式版，也不自动改 stable 指向。页面首次进入和“刷新”读取 VPS 发布数据，不触发 Claude 或 JEV。

### 验证与上线

验证下载区的正确通道、空／过期状态、下载路径与移动布局；验证客户端更新契约、打包身份、配置保留策略与完整包内文件。真实打包启动测试使用隔离配置和离线模式，不连接用户账号，不覆盖本机安装。

VPS 上线前备份独立管理服务，保留当前配置、数据库、账号监控、管理员密码、审核策略和节点身份。发布通过现有签名、候选上传和校验流程完成；正式 HTTPS 下载验证字节数和 SHA256，验证管理中心入口可用。安装包可下载与本机已完成升级分别报告。
