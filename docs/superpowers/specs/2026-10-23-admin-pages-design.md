# CC 管理中心独立功能页

用户已确认按此方案实现并上线：统一顶部导航，账号监控、客户端更新、内容审核各占独立页面；刷新和浏览器前进/后退保留目标功能，只读取当前功能的 VPS 数据，登录和修改密码共用。

页面地址为 `/cc-updates/admin/accounts`、`/cc-updates/admin/updates`、`/cc-updates/admin/moderation`。根入口默认账号监控。服务仅为这三个明确路径复用管理壳，不对任意 admin 路径开放 HTML fallback。导航用真实链接，普通点击更新 history 和当前视图，新标签和直接访问正常工作。登录凭据继续只在内存中，整页刷新后需重新登录，随后返回该地址对应功能。

共享页头包含产品名、导航、修改密码和退出。导航位于所有功能内容之前，当前页有明确选中态，移动端可横向滚动且无整页溢出。每次只显示一个功能区，搜索与未保存备注在同一登录会话切换时保留；退出清除私人数据和草稿。

导航控制单独放在 navigation.js；审核模块只负责审核内容，不再拥有导航。初次登录和切页只刷新当前功能；账号监控每30秒只在该页可见且无草稿/编辑时读取VPS，离开页面停止轮询。正在执行的操作结束后只补载最新目标页，避免历史导航与视图不一致。密码设置链接仍正常消费并从地址清除。

验收覆盖三个明确 HTTP 页面和错误路径、页面互斥、导航位置及选中态、直接访问/刷新/历史、请求隔离、备注草稿保留、密码流程和移动宽度。所有测试使用本地合成数据，无 Claude/JEV 调用。上线先核对生产版本和 hash，备份完整数据/配置，部署后验证原数据库和凭据保留，不改节点或中转服务。
