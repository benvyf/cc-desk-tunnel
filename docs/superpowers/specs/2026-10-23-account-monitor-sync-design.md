# Claude 账号数据被动同步

用户已确认：Ubuntu CC 服务端取得现有数据后，向 VPS 同步一份；尽可能不打扰 Claude。

## 数据与边界

- 只观察既有 `native.capabilities`、`native.metrics` 和 `account.state`，不调用 Claude、不启动 CLI、不增加定时刷新。
- 每个节点独立配置 HTTPS 上报地址、节点 ID、随机上报密钥；PROXY_ 配置会在启动 CLI 前从继承环境移除。
- 只上报散列账号标识、订阅类型、额度窗口、采集时间和最近会话用量。禁止传登录凭据、邮箱原文、聊天、项目路径和任意错误正文。
- 无账号标识时不关联额度；退出或切换账号清除本地旧快照。上下文事件重复携带的额度不重复上报。
- 原有 SDK 实验额度接口不作修改，也不作为新增稳定性承诺。

## 同步

异步队列只保留最新快照，默认最多每 30 秒上报一次；失败向 VPS 退避重试，间隔最长五分钟。请求五秒超时，禁止重定向，不影响聊天。同步关闭时不创建网络请求或定时器。

## VPS

复用更新管理服务与管理员认证，增加节点专用写接口和管理员只读接口。配置兼容既有文件，默认禁用上报。每个节点密钥只能写该节点，不能读管理数据或发布安装包。

在服务 private 目录 SQLite 持久化每节点最新快照。严格校验字段、大小、时间、数值与节点白名单；旧数据和重复数据不覆盖最新记录。同一账号在多节点出现时展示各节点快照，不累加额度百分比。

管理页增加账号监控区域，刷新只读 VPS；标明采集时间、接收时间、数据过期与最近会话估算用量。没有新数据不判定账号被封，也不将旧额度伪装成实时数据。

## 验收与部署

本地真实 HTTP 测试覆盖身份隔离、拒绝额外字段、乱序、重复、持久化、重试与故障隔离；完整类型检查、现有回归和真实浏览器测试。所有采集调用保持现状。准备配置说明与打包文件；生产部署状态单独记录，未验证前不声明上线。
