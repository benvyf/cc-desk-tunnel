# 连按两次 Esc 停止回答

用户已确认加入刚才说明的 Harness 快捷键：同一会话、同一运行、同一焦点区域内，500ms 内两次独立 Esc 请求停止。单次 Esc 不停止；长按重复、修饰键、输入法、终端、iframe、审批、菜单、查找、引用浮层和排队消息编辑不参与序列。

复用主会话和侧会话现有停止函数及错误提示；分别暂停该会话的排队消息并通过现有远端 `run.cancel` 路径停止。无需增加协议、客户端模型依赖或本机访问接口。

焦点移动、鼠标操作、失焦、页面隐藏、输入法开始、其他按键、会话/运行/连接及可停止状态改变均重置序列。捕获阶段记录当前浮层状态，冒泡结束后才接受按键，避免局部 Esc 已关闭浮层后被误认作停止，也尊重 preventDefault/stopPropagation。键盘监听仅在可停止时挂载，不为每次渲染重新注册；输入法生命周期跟踪随组件保持稳定，在禁用期间仍接收开始和结束事件。序列只保留时间戳，不创建常驻轮询。

沿用现有快捷键总开关，在设置中用现有 setting-row/kbd 显示固定操作说明。现有按钮和 UI 样式保持。使用假服务测试主侧目标、超时、长按/输入法、浮层、审批、焦点及运行切换；不调用真实模型。

局部查找栏、斜杠菜单、右键菜单和终端选择器仅拥有其实际输入区域中的 Esc，不拦截另一会话。原生模态框以及提供全局 Esc 关闭处理的弹窗仍优先处理。停止请求失败时沿用现有错误提示，保留草稿；重试必须重新完成一对 Esc，不自动重发停止请求。
