# 配套服务端发布与升级（已批准）

用户批准：最新完整服务端包放 VPS；客户端协议不匹配时提供“升级配套服务端”，展示目标并确认；空闲检查、备份、升级、本地健康检查、失败回滚。旧节点首次在 Ubuntu 控制台接入一次升级能力。运行环境或依赖不兼容时要求人工升级。

整合基线：本机 cca00af 与 GitHub codex/vps-update-channel 的 9f783b25d8ed0c2395af9e16bb484a46a19bb402。两分支分叉，必须保留账号被动同步、管理中心独立导航、完整客户端下载，以及远端的原生终端审核和部署校验。不能把远端 Build 2 标记覆盖现有 Build 3。

程序升级使用现有容器内的非特权监督程序，固定 VPS 来源、签名索引、SHA256 和依赖锁摘要。升级 API 独立于业务协议，认证使用现有服务令牌；客户端主进程固定请求路径，TLS 指纹确认后才发送令牌。旧 GitHub 自升级入口保持关闭。

候选程序在独立目录验证，维护期间阻止新任务；停服后备份、切换、验证本机健康；失败仅回退程序，不用旧数据覆盖新增历史。监督程序及审核策略保持管理员所有、不可由服务用户修改。运行环境不匹配拒绝程序替换。

架构审查补充：升级兼容性还必须覆盖持久化格式和固定审核钩子的完整依赖闭包（hook、moderation、errors），不能只比较单个 hook 文件。初始实现对持久化实现摘要采用保守的精确匹配，格式迁移交由人工镜像升级。候选启动后继续维护隔离，认证的本地 readiness 确认目标发布摘要、协议、数据库打开和有效审核配置后才接纳业务。监督程序以原容器环境和现有 env-file 的原优先级启动；持久化事务日志记录停服、备份、切换、探测、提交或回退，等待旧进程组退出，容器关闭时不得再次启动子进程。每次启动重新验证已安装发布文件和指针；索引过期只阻止新的安装，不阻止已安装程序离线启动或回退。候选由既有非特权服务用户运行，不宣称对同一用户已被攻陷后的进程具有权限隔离。

首次接入脚本保留实际容器配置、环境变量、挂载和审核设置，不使用宿主机过时 Compose 源码。公开包不得含监控令牌、服务令牌、账号数据、私钥。首次接入没有节点访问授权入口时交付可验证命令，不声称已在 Ubuntu 执行。

验证禁止调用 Claude 账号/额度 API、发送 Claude/JEV 消息或打开真实终端；使用离线测试、模拟服务及无账号挂载的 Linux 环境。
