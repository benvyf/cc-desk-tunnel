# 登录时的客户端升级提示

日期：2026-11-04（香港时间）。状态：方案待确认，尚未修改产品代码或生产服务。

## 目标

使用旧客户端连接已升级的工作空间时，明确说明需要更新客户端并给出可信获取入口。保留协议隔离，不通过允许旧协议登录来掩盖兼容问题。仅客户端过旧且目标工作空间不兼容时触发；同协议的较旧 Build 仍可正常使用。

## 已核实的约束

- 当前公开 Windows pilot 是 Build 24／协议 22，sourceCommit 为 4d55cd20b9f13d3d21d9799766f5a4c28884ab11；尚未发布协议 23 客户端。
- 该客户端的邮箱登录和连接取票请求没有上报客户端协议或 Build，版本号 0.3.7 也不能区分协议 22/23。
- 旧客户端会显示管理中心 HTTP 返回的 error 文本；426 不会被当成密码错误、过期登录或切换电脑确认。
- 旧客户端已有协议错误文字显示，尚没有可由服务端远程开启的“升级客户端”专用弹窗。仅改变服务端不能给已安装旧程序新增按钮或替换其界面。
- 原自动更新界面禁止跨协议自动安装；本次不放宽这项默认规则。

## 方案比较

1. 仅改 WebSocket 拒绝文案：最小，但发生在连接工作空间之后，旧界面的错误框及“检查服务端更新”按钮仍可能误导。
2. 连接前兼容检查 + 新版客户端升级弹窗 + 旧版文字兜底（推荐）：旧版也能在取连接票据前收到明确提示，新版提供专用弹窗和正确获取入口。
3. 登录时全局强制最低版本：会误伤仍使用协议 22 工作空间的用户，不采用。

## 推荐交互

单工作空间：点击“登录”后自动检查目标工作空间；多工作空间：在选择工作空间时检查。自动登录、记住登录和重连也走同一取票检查，不只覆盖手动点击。

客户端过旧时显示：

> **需要升级客户端**
>
> 此工作空间已更新，请升级 CC SPACE 客户端后重新登录。你的账号和聊天记录会保留。

配套客户端已发布时提供“下载新版客户端”“稍后升级”。下载需要用户操作，不自动安装、不自动重启或升级服务端。可在详情中显示当前及所需客户端版本。

没有匹配的已签名客户端时显示“配套客户端尚未发布，请联系管理员”，保留关闭操作，不提供会再次下载协议 22 旧包的按钮。

已安装 Build 24：管理中心返回兼容的明确升级文字，显示在原登录/工作空间页面；不能承诺旧程序会凭空出现新弹窗。安装具备提示能力的新客户端后，后续升级可完整显示专用弹窗。

## 判断及接口

新版客户端由主进程提交自身 Build、协议等信息，渲染页面不自行声明已兼容。管理中心在认证、工作空间授权通过后，按目标节点当前可信状态判断，不能拿“最新可升级服务端版本”代替该节点实际运行版本。

客户端协议较低：在签发新连接票据之前返回 426 和结构化 client_upgrade_required 信息，同时保留旧客户端能直接显示的 error 文本。缺少版本信息的现有 Build 24 视为旧版；只有可信的当前目标状态证明其需要新协议时才阻止取票。

版本未知、节点离线或状态过期：不凭猜测把网络故障或未知状态标成“客户端过旧”，保留握手校验作为兜底。WebSocket 的稳定拒绝消息也明确区分“升级客户端”和“联系管理员升级服务端”，保持旧版能解析的连接错误帧。

客户端比服务端新：提示配套服务端需要管理员更新，不让用户反复下载客户端或自动降级。同协议旧 Build 不强制更新。

升级拦截不额外执行注销、清除保存的登录、撤销其他会话或触发 Claude 请求，沿用现有认证与单设备登录规则。401 继续表示认证失效，409 继续表示切换确认或已有事务冲突，不能复用这些状态冒充客户端升级。

客户端获取入口只来自可信源、已验签且协议匹配的发布信息，不接受服务端任意 URL、上游原版或不匹配的公开安装包。手动配置连接没有中心取票路径时，仍显示明确的握手升级说明。

## 验证与采用

覆盖真实 Build 24 请求形状、同协议旧 Build、协议 22→23、新客户端连接旧节点、单/多工作空间、记住/自动登录、无匹配客户端发布、未知或过期节点状态、错误密码和升级取消。验证升级提示不会循环重连，也不会变成“检查服务端更新”的错误方向。

新客户端弹窗需真实浏览器交互测试；管理中心与原生取票链路需联合测试。正式启用前先备好并验证匹配的签名客户端，再安排服务端升级，避免升级提示指向尚不存在的客户端。

实施完成先交付可审阅代码、测试与候选包；中心及客户端的生产发布按最终候选安排，不在本次方案确认前变更线上。
